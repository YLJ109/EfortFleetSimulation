# 方案：AI 对话智能体（可正常聊天 + 可执行）

> 2026-10-09 · 状态：**待确认，未实现**
> 需求原话：做一个可以正常聊天的大模型，也能执行代码的智能体；对话右边是我，左边是机器人，重新对话框合理一点。

---

## 1. 现状与问题（先说清楚为什么现在"不能聊"）

| 现状 | 问题 |
|---|---|
| `llm.py` 是**一次性 JSON 翻译器**（单轮、无历史、无工具调用） | 只会"翻译指令"，不会聊天。说「你好」→ 规则解析不出 → 报"没听懂" |
| 规则解析（nl_intent）**永远先跑**，LLM 只是兜底 | 聊天类输入两条路都失败，必然报错 |
| 前端气泡：**用户在左、机器人在右** | 与通用聊天习惯相反，用户要求对调 |
| 本轮实测的报错「放到 B 区要指定颜色列」 | **与 LLM 无关**——规则解析把「取A1→判色→放B区」翻成了 `move_one(to=整区B)`，而计划校验器要求 B 区必须给颜色列。根因是**计划表缺"判色后按颜色自动选列"这个目标类型** |

大模型连接状态：`.env` 已配智谱 `glm-4-flash`（免费、官方文档确认支持 **Function Calling**），
key 已用后端真实代码路径实测打通。**后端重启后才生效**；AI 页顶部会显示"大模型 已启用"。

## 2. 做什么

### 2.1 后端：新对话端点 `POST /api/ai/chat`

```
请求：{ text, history: [ {role:"user"|"assistant", content:"..."} ] }   ← 前端带最近 10 轮，后端不存
返回：{ ok, reply: "给用户看的话", plan: {...}|null, source: "rules"|"llm" }
```

**分流逻辑（离线优先，与现口径一致）：**

1. **规则解析先跑**（nl_intent）：认得出 → 直接返回计划卡（不耗 LLM、断网可用，行为与现在一致）；
2. 规则认不出 → **LLM 智能体**（function calling，多轮工具循环，最多 2 轮）：
   - 模型可以调**工具**，也可以纯聊天作答；
   - 聊天类（「你好/你能干嘛/钢铁为什么会生锈」）→ 直接回话，不出计划；
   - 状态查询类 → 调只读工具拿真数再答（"机器人现在什么状态"→ 读真实链路状态）；
   - 动作类 → **只出计划卡，绝不直接执行**（见 §3 安全线）。

### 2.2 工具集（白名单，全部复用现有校验/执行通道）

| 工具 | 危险等级 | 行为 |
|---|---|---|
| `get_robot_status` | 只读 | 连接/就绪/档位/伺服/报警/当前关节角/分拣状态，**可直接答** |
| `list_programs` | 只读 | 列出可执行程序（示教器 XPL + 本地 JSON），**可直接答** |
| `look_color(from)` | 运动 | 出计划卡，需确认 |
| `move_one(from, to)` | 运动 | 出计划卡，需确认 |
| `move_all(from, to)` | 运动 | 出计划卡，需确认 |
| `sorting_control(op)` | 运动 | 出计划卡，需确认 |
| `run_program(name)` | 运动 | 出计划卡，需确认（"执行代码"= 跑程序执行页那套，不引入别的代码解释器） |

> 动作工具的参数校验完全复用 `llm.py` 的 `_loc/sanitize` 白名单——模型编造的格子/动作在这里被丢弃。

### 2.3 修本轮实测暴露的真缺口：`color_auto`

计划表目标增加一种写法：`to = {"kind":"color_auto"}`（"按判出的颜色放对应列"）。
- 规则解析：识别「判色→放B区」「放到B区对应颜色列」类说法 → `color_auto`；
- 执行器：`look/move` 流程中判完色 → 选该颜色列第一个空槽（复用 `_free_b_slots`）；
- 校验器：`color_auto` 合法，不再报"要指定颜色列"。
- 兼容：显式说「放B区红列」仍是 `color_col`，行为不变。

### 2.4 前端：对话框重构（AiControlView.vue + aiChat.js）

| 项 | 改法 |
|---|---|
| 气泡方向 | **用户 → 右侧**（青色渐变气泡），**机器人 → 左侧**（深色气泡），头像跟各自一侧 |
| 消息类型 | 新增 `CHAT`（纯聊天文本，机器人左侧普通气泡）；PLAN/RUN/RESULT/WARN 样式沿用 |
| 输入栏 | 保持 75px textarea + 麦克风 + 发送/停止竖排（本轮刚调好的不动）；placeholder 改为"随便聊，或直接下指令" |
| 空状态 | 预设胶囊改为两类：**试试聊**（你好/你能做什么/机器人什么状态）+ **下指令**（现有 5 条） |
| 发送链路 | `submitInput` → 优先 `/ai/chat`；返回 plan → 出计划卡（确认词「执行」逻辑不变）；返回纯文本 → CHAT 气泡 |
| HUD | 「大模型 已启用/未配置」徽标保留 |

## 3. 安全线（不可妥协，全部沿用现有机制）

1. **动作绝不自动执行**：智能体对动作类工具只产出计划卡，与手打指令同一套 `plan_id + confirm` 通道；
2. **模型不碰寄存器/不写程序**：工具白名单之外一事无成；参数过 `_loc/sanitize` 白名单；
3. **空跑开关照旧**：HUD 空跑勾选对智能体产出的计划同样生效；
4. **断网降级**：无 key/超时 → 回"规则解析 + 提示大模型未配置"，页面不崩；
5. **不落库**：对话历史前端内存保存（最近 30 条），刷新即清（现场口径不变）。

## 4. 不做什么

- ❌ 不做连续自主执行（智能体一轮最多提一个计划，不自动连环调动作工具）
- ❌ 不做流式输出（glm-4-flash 非流式足够；流式留作后续可选项）
- ❌ 不做对话历史持久化 / 多用户会话隔离（单页内存即可）
- ❌ 不做"模型写代码解释执行"（"执行代码"= 触发既有程序执行通道）
- ❌ 不引入任何 LLM SDK（继续 urllib + OpenAI 兼容协议，零新依赖）

## 6. 验收口径

1. 「你好」→ 机器人自然回话（不出计划卡）；
2. 「机器人现在什么状态」→ 回真实状态（读 get_robot_status）；
3. 「取A区第1行第1列判色然后放到B区」→ 出计划卡"取 A1 → 判色 → 放 B 区对应颜色列"，说「执行」才动；
4. 「把A区第1行第1列放到B区红列」→ 与现在完全一致；
5. 断网/无 key：指令照旧能用，聊天回"大模型未配置"；
6. 气泡：用户右、机器人左；构建 + 22 个前端回归 + 380 条后端测试全绿。
