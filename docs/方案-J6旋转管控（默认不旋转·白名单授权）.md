## 1. 根因（已定位到代码行，不是猜）

**一句话**：`keep`（不旋转）目前**只对 18 个原料位生效**；**其余 20 个点一律按"该点自己录的 J6"下发 → 一到就转**。

关键代码 —— [sorting.py](file:///d:/EFORT_Projects/EFORT_Web_Monitoring/backend/app/services/sorting.py#L403-L410)：

```python
if norm_face(face) != FACE_BACK:
    # 正面 = 该点自身 6 值（**与旧行为逐字一致**）
    return _with_norm_j6(vals), False, ""       # ← vals[5] 就是"该点录的 J6"
```

而 [face_for_target](file:///d:/EFORT_Projects/EFORT_Web_Monitoring/backend/app/services/sorting.py#L271-L299) 只在**原料位**上把它翻成 `keep`：

```python
if is_raw_material_slot(name):     # 只有 A1…A9 / B1…B9 这 18 个
    return FACE_KEEP
return face                        # ← 其余 20 个点：原样透传 "front"
```

于是**每个现象都能对上号**：

| 现场现象（用户原话） | 代码原因 |
|---|---|
| 「**到原位回到正上位**突然旋转卡住了」 | `A2` → `A2上`：`A2上` 非原料位 → `face="front"` → 下发 `A2上` **自己录的 J6** → 腕部猛转 |
| 「**回家**」也转 | 同上，`开始/结束点` 自己录的 J6 |
| 「**去摄像头点位**也 J6 旋转一下」 | 同上，`C检测` 自己录的 J6 |
| **单件分拣**跑一路也在零星转 | 单件路径的 `_move` 大多**没传 face** → 全默认 `front` → **每到一个点都把 J6 拉到该点录值** |

> ★ 为什么"卡住"：J6 被拉到该点录值时可能是一次很大的角度变化（甚至贴到 ±327 限位/腕部奇异），
> 现场表现就是"突然转 + 停住/卡住"。

**⇒ 结论**：现在这个"默认 front"的语义，与用户"其他时间一律不允许旋转"**直接冲突**，
所以必须把**默认**从"按目标点自身 J6"改成"**保持当前 J6**"。

## 2. 目标口径（把用户原话拆成可判定的规则）

| # | 规则 | 判据 |
|---|---|---|
| **R1** | **默认一律不旋转** | J1~J5 用**目标点自身**的值（不然到不了那个点）；**J6 保持当前实时值** |
| **R2** | **只有白名单允许旋转** | ① 用户主动旋转 ② 双面分拣 ③ AI 快速分拣 ④ 游戏（井字棋） |
| **R3** | **面判定不写死** | 基准 = **示教的 `J6正面` / `J6反面` 两个点的 J6 值**（不是"每点自身 ∓180"）；<br>当前 J6 **离哪个基准近 → 就是哪个面**（环形距离，因为 J6 是转动轴） |
| **R4** | **fail-safe 方向** | "漏改 / 不知道 / 没授权" 一律落到**不旋转**（宁可不动，绝不乱转） |
| **R5** | **禁转黑名单不放松** | 18 个原料位**仍然**严禁旋转（`is_raw_material_slot` / `_rotation_guard` **一个字节不改**） |

### ★ 一个重要的物理事实（支撑 R1 是安全的）

**"面"是"料 ↔ 吸盘"的相对关系，由"有没有翻过"决定，与 J6 的绝对值无关。**
所以单件分拣 / 视觉规则 / 普通到点**全程 keep 不会影响判色结果**（料相对吸盘的朝向完全由 A 区摆放决定）；
只有"要另一面"时才需要在**允许旋转的位置**翻一次，之后一路 keep 就保持着那个面。
——这也是用户规则自洽的地方。

## 3. 设计（四层，唯一咽喉）

### 3.1 新增默认面语义 `auto`（= 不旋转），与既有 `keep/front/back` 并列

| 面语义 | 含义 | 谁用 |
|---|---|---|
| **`auto`（新默认）** | **保持当前 J6**（不旋转）；语义等同 `keep`，但**名字表明"由系统决定、不主动转"** | 所有**没显式授权**的调用点（默认） |
| `keep` | 同上（保留，兼容旧调用与已写的回归钉） | 同上 |
| `front` / `back` | **要某个面**（会改 J6）——**只在白名单授权后才可能生效** | 双面分拣 / AI 快速分拣 / 游戏 / 用户显式翻面 |

> 关键：`auto` / `keep` **都不看调用方想要的 front/back** —— "想翻转"必须**另外拿到授权**。

### 3.2 旋转授权：`rotate` 开关（**默认 False**）

新增**唯一的授权入口**（放在 [api/sorting.py](file:///d:/EFORT_Projects/EFORT_Web_Monitoring/backend/app/api/sorting.py#L423-L472) 的 `_move` 那一层）：

```python
def _resolve_face(name, want, rotate: bool) -> str:
    """★ 旋转闸门（唯一）：**未授权 → 一律 keep（不旋转）**；授权后仍受原料位禁转约束。"""
    if not rotate:
        return S.FACE_KEEP                       # fail-safe：漏改/没授权 = 不旋转
    return S.face_for_target(name, want)          # 授权：原料位仍强制 keep（黑名单不放松）
```

- **`rotate=False`（默认）** → 不管调用方传什么 face，**一律 keep**。
- **`rotate=True`** → 尊重传入的 face，但 **18 原料位仍被强制 keep**（R5）。

`_move(ctx, pmap, name, speed, dry, stage, st=None, face=S.FACE_AUTO, *, rotate=False)`；
`resolve_target_joints` 本身**签名与语义不变**（它收到的 `face` 已是"最终生效值"）。

### 3.3 面基准来自"示教的两个面"，**不写死**

> ★★ **2026-10-12 下午终版：本节"面基准"方案已整体作废**（用户原话「**去掉J6正面和反面录的
> 0和180的值，只显示正面和反面进行旋转的按钮，不用录制正反面**」）——
> `services/j6_face.py` 与 `bases` 实参**已整体删除**，面值改为**逐点派生**（见 §3.4 终版）。
> `J6正面`/`J6反面` 变成**虚拟切面命令**：按点名驱动、基姿态 = 当前实时关节、只覆盖第 6 轴；
> 不再读点位库（库里残留两行无消费方，可删可留）、示教接口直接 400"无需示教"。
> 下面的小节原文**仅留档**，不再对应现行实现。

```python
def face_bases(front_hint: float) -> (float, float, bool):
    """返回 (正面基准 J6, 反面基准 J6, 是否来自示教点)。
    · `J6正面` / `J6反面` **两个点都在点位库** → 直接取它们的 joints[5]（**用户现场示教值**）；
    · 缺任一 → 回退规则：(front_hint, front_hint∓180 归一)，**并在 state/日志如实标注"基准来自规则回退"**。
    """

def ring_dist(a, b) -> float:
    """J6 环形距离（转动轴：相差 360° 是同一姿态）→ `min(|Δ|, 360-|Δ|)`。"""

def face_of_j6(cur, front_base, back_base) -> str:
    """**面判定（不写死）**：当前 J6 离哪个基准近 → 就判哪个面。
    （用户原话：「J6 靠近正面一点那种正面，如果靠近反面那就反面」）"""
    return FACE_FRONT if ring_dist(cur, front_base) <= ring_dist(cur, back_base) else FACE_BACK
```

用途：
- ✅ **如实显示"当前面"**（state.face / 手柄执行页 / 分拣页"当前面"）；
- ✅ `keep` 时判出"实际保持的是哪一面"（供日志/state 记录）；
- ✅ 双面流程里"这件当初用哪面拿的"（已有 `moves[].face`）核对。

> ★ 现状 `back_j6` 用的是"**该点自身 J6 ∓180**"—— 这正是用户说的"**写死**"。本方案把它换成
> "**离两个示教面谁近**"，并且 `keep` 的下发值**逐字等于当前 J6**（不做任何 ∓180 折算）。

### 3.4 keep 的下发值

> ★★ **2026-10-12 下午真终版（第三轮现场迭代）**（用户原话「**正面就是之前录的J6，
> 反面就是当前-180就行了**」「**不是-180度，而是当前点J6的值减掉180度**」）：
> · 第一版「逐字锁实时值」→ 采集滞后/漂移被吸进目标（件被带歪）；
> · 第二版「一律对齐示教面基准」→ 现场**A1上/A3上 偏差**（用户原话
>   「A1和A3的正上位异常有偏差，但是A2没有这个偏差」「J6的坐标没有问题，问题好像别的轴，
>   摄像头和起点正常」）—— **根因**：每个点自己录的 J6 才是该点的对位姿态（随 J1 变化：
>   A1上 −14.1 / A2上 −4.3 / A3上 +3.0，单一基准盖不住全场），强行用基准 = 工具绕竖轴歪
>   3°~14°，而 J6 读数"正常"（= 基准 0/−180）→ 看起来像"别的轴没同步"；
> · **真终版**：**面值逐点派生，不再有任何"面基准"** ——
>   **正面 = 该点自身录制 J6（own）；反面 = own − 180**（在 {own−180, own+180} 两个等价表示里
>   取**离当前实时 J6 数值更近**的一侧 = 少绕线；拿不到当前 → 取 |值| 更近 180 的一侧）；
>   **keep/auto 判当前面后取对应变体**（同面用自身值 → 对位准、无漂移；
>   跨面取该点自身的另一面变体 → 仍不翻面、不转大圈）。

```python
# auto / keep（2026-10-12 真终版）：
cur = _current_j6_from(base_provider)          # 拿不到 → 拒绝（判不了面 = 保证不了"不跨面"）
own = normalize_j6(vals[5])                    # 该点自身录制的 J6 = 正面变体
back = back_j6(own, cur)                       # 反面变体 = own ∓180 中离 cur 更近的等价角
tgt6 = keep_j6(own, cur)                       # ring_dist(cur,own) <= ring_dist(cur,back) → own 否则 back
tgt = [vals[0], vals[1], vals[2], vals[3], vals[4], tgt6]
```
- `back_j6(own, cur)`：**反面 = 该点自身 J6 − 180**，但落点在两个等价表示（own−180 / own+180）
  里取离当前更近的一侧 → **少绕线**；`keep_j6` 平局归正面，`cur=None` 保守取正面；
- `normalize_j6` 只做"折进 ±327 可表示范围"的**等价角**变换（J6 是转动轴，物理姿态不变）；
- **J1~J5 仍用目标点自身**（必须，否则到不了该点）；
- **拿不到当前 J6 → 拒绝**（判不了面 = 保证不了"不跨面"，绝不猜；空跑/离线由 `_move`
  走"不下发指令"的回退把流程走通，不会卡住）。
