# 方案：按「同色成行 / 成列」摆放（约束求解）＋ 无效色（黑）放回原位继续

> 2026-10-10 · 状态：**已实现**（见文末 §7 实施清单；两个未做项已写明）
>
> 起因（用户原话）：
> 「B5,B9已有摆放物体，从A区拿三个蓝，两个绿，一个红放到B区，按同颜色一行或者一列摆放，
>   如果出现无效颜色放回原位继续！」
> 现象：B5/B9 明明有东西，它还是往上放（料上放料）；摆放是"第1列红/第2列绿/第3列蓝"那种写死规则，
> 不是"同色成行或成列"。

---

## 0. 先回答三个问题（现场现象的真实原因）

| 你的问题 | 答案 | 证据（代码） |
|---|---|---|
| 这条是 AI 解析的吗？ | **是规则解析（nl_intent），大模型没参与**。大模型（已配智谱 glm-4-flash）**只在规则解析失败时**才兜底；你这条规则认得，所以根本没问模型。 | `backend/app/api/ai.py` → `_parse_to_plan()`：先 `NL.parse(text)`，成功即用；`if not res.get("ok") and llm.enabled():` 才调大模型 |
| 为什么「料子上又放了料」？ | AI 页的**占位表 `_occ` 从空开始**（重启即清、不共享分拣页那轮的表）——它**不知道 B5/B9 里已经有东西**，在它眼里 B 区是空的。 | `ai.py` `_occ = {"A": {}, "B": {}}`；`_occupied()` 把"没记录过的 A 格"一律当"有料"，但 B 区没有对应机制 |
| 「同颜色一行或者一列」为什么没生效？ | **规则层里根本没有这个概念**：落位是**写死的三列映射** —— 红→B1/B4/B7、绿→B2/B5/B8、蓝→B3/B6/B9；你说了"一行或一列"，它照样按写死的列放。 | `backend/app/services/sorting.py` → `DEFAULT_COLUMN_SLOTS`；`nl_intent.color_column_slots()` 同一份 |

> ★ 核心结论：**不是模型笨，是规则层把"颜色→列"写死了，而且写死得太早** ——
> 在解析阶段就定死，后面没有任何"按约束摆"的余地。
> 你要的"同色成行/成列"是**一个约束**，不是一张固定的颜色对照表。

## 1. 目标（做什么）

1. **「同色成行 / 成列」变成真正的约束**：摆放位由**约束求解**算出，不再写死"哪色占哪列"。
2. **占用感知**：B 区**已被占的格绝不落料**；用户说"B5/B9 已有物体"要自动识别为**已占用**（= 禁放），并回显"我按已有料处理"。
3. **无效色（黑 / 判不出）→ 放回原格 → 继续**（不再整轮停）；且**试件次数不固定** —— 1 个黑多试 1 次、3 个黑多试 3 次，直到配额凑齐或 A 区试完。
4. **黑色能被视觉检出**（"暗色兜底"本轮已写，见 §3.4；**待现场真图验证**）。
5. **解析链路明确**：规则解析**结构化约束** → 规则解不出 → **大模型只翻约束（不给格号）** → 约束求解器出摆法 → **摆法回显给人确认**。

## 2. 不做什么（边界，先说清）

- ❌ 不让大模型**直接给格号**（它会瞎编、不可复现、无法回归）—— 它只能翻成"约束"。
- ❌ 不用 3D/相机去"判 B 区空满"（相机只对 C 检测位，照不到 B 区）—— 只认"我方确知的占用"（本轮放过 + 用户明说）。
- ❌ 不引入真空/料位传感硬件。
- ❌ **不改分拣页现有默认行为**（分拣页仍是"第1列红 / 第2列绿 / 第3列蓝"，那是它既定口径）；
  新规则只在**指令里明确说了摆放方式**时生效。
- ❌ 不动运动原语（`_move/_air/_capture`）、不动速度口径、不动围栏互锁。

## 3. 设计

### 3.1 摆放 = 约束求解（核心）

**输入**（全部可由规则解析 + 现场状态得到）：

| 项 | 例 | 来源 |
|---|---|---|
| `counts` 颜色→件数 | 蓝3 绿2 红1 | 规则 `_parse_quotas`（已支持中文/阿拉伯数字） |
| `zone` | B | 规则 |
| `pattern` 摆放方式 | `row_or_col`（一行**或**一列）/ `row` / `col` / `any` | 规则新增（见 §3.5） |
| `occupied` 已知占用格 | B5、B9 | 用户明说（"已有物体"）/ 本轮已放过 |
| `banned` 禁放格 | 同 occupied + 显式"不能放" | 规则 `_scan_bans`（已有） |

**求解**（规则、确定性、可回归）：
- B 区是 3×3，线只有 **3 行 + 3 列 = 6 条**。
- `row_or_col` = 同色**全部**落在**同一条线**上（件数=3 时必须占满一条整线；件数=2 占同线相邻 2 格；件数=1 任意可用格）。
- 穷举 6 条线的分配，过滤掉：含占用/禁放格、两色抢同一格、互相冲突的解。
- **多解** → 按确定性优先级选一个（列优先 → 列序 → 件数降序），并**回显**所选摆法。
- **无解** → **明确拒绝**并说明卡在哪（"3 件同色必须占满一整行或整列，但三条含 3 格的线都被占用/禁用占掉了"），**绝不硬来**。

**你那条的求解示例**（蓝3 绿2 红1，B5、B9 已占用）：

```
可用 3 格线：第1列(B1,B4,B7) ✓ / 第3行(B7,B8,B9) ✗(B9被占) / 其它线都不是3格
→ 蓝(3件) 只能放 第1列：B1、B4、B7
→ 绿(2件) 与 红(1件) 再从剩余可用格里各占同线：例如 绿→B2,B5✔? (B5被占→换) …
最终(一例)：蓝→B1/B4/B7(第1列)  绿→B2/B3(第1行前两格)  红→B6
```
★ 这只是**一个合法解**；界面必须把"我采用的摆法"写出来，并提供「换一种」（等价解之间切换），
because "同色成行或成列"本身**有很多种摆法** —— 这正是你说的"还有好多种摆放方式"。

### 3.2 占用 / 禁放（修"料上放料"）

- 「B5,B9 **已有**摆放物体」→ 识别为 **occupied（= 禁放）**，并在计划卡回显：
  「B5、B9 按**已有料**处理（不放）」。
  → 规则侧"已有"的识别本轮已加；本方案再加**回显**与**占用语义**（不只是禁放）。
- 落位时：`occupied ∪ banned` 一起跳过（现有 `skip_slots` 机制）。
- **可选（本轮不做，先记着）**：指令里没有说 B 区现状时，AI 页仍是"不知道" —— 要么用户明说，要么做一次「**盘点 B 区**」（需要 B 区拍照能力，现在没有）。

### 3.3 无效色 → 放回原格 → **继续**（且不是固定次数）

现状：判色失败 → `_put_back` 放回原格 → **抛 `_Stop`（整轮停）**。
改为（口径变更，**需你确认**）：

```
取 → 判色
  ├ 红/绿/蓝 且该色还缺 → 放该色对应格（配额−1）
  ├ 红/绿/蓝 但不缺     → 放回原格（不消耗配额）
  └ 无效色（黑/判不出） → **放回原格** → **continue**（不抛停）
重复直到：配额凑齐 ✅ 或 A 区可取件试完 ❌（如实报"未凑齐，还剩 X"）
```

- **循环上限 = A 区当前可取的件数**（不是 `counts` 之和"硬 6 次"）——
  这样 1 个黑/2 个黑/3 个黑都只是"多试几次"，不会漏也不会死循环。
- 三条链路（**分拣页 / AI 页 / 井字棋自证**）统一这条口径。

### 3.4 黑色识别（视觉层）

- **已实现**（本轮，只加不改）：`camera/vision_color.py` 新增"**暗色兜底**" ——
  彩色掩膜一个候选都没有时，再用低亮度掩膜找一遍；黑/深色物体因此变成**候选**，
  判色为 `未知` + `reason="无效颜色（暗色/非红绿蓝）"` → 上层据此走 §3.3 的"放回 + 继续"。
  红/绿/蓝这条路径**零改动**（不存在把三色判丢的风险）。
- **待办（必须）**：现场真图回放（`camera/tools/vision_e2e_replay.py`）——
  现在 `camera/captures/vision/` 里没有现场图，**没法验证**；需要一张含黑块的现场照。

### 3.5 解析链路（"让 AI 思考"，但可控）

```
用户话
  → ① 规则解析（nl_intent）：能解析出【动作 + counts + zone + pattern + occupied/banned】
        · pattern："一行或者一列 / 同行同列 / 一列一列摆 / 排成一排…" → row_or_col / row / col
  → ② 规则解不出 → 大模型（智谱 glm-4-flash，key 已配）**只翻成同一套约束 JSON**
        · 白名单字段；**禁止给格号**；点位名不在 38 点内直接丢弃（现有 sanitize 已如此）
        · 模型返回的东西仍要过**同一套求解器**才出摆法
  → ③ 约束求解器（规则）算摆法（多解选一）
  → ④ 计划卡**回显**：件数 / 摆法 / 占用与禁放 / 遇到无效色的处理 → 说「执行」才动
```

> 这样"AI 思考"体现在**约束层面**（能听懂各种说法），
> 而"摆哪几个格"永远由**确定性求解器**决定 —— 可回归、可复现、不会瞎编。

## 5. 需要你拍板的 3 件事

1. **"放回原位"之后是"继续"还是"停"？**
   你这条指令写的是"**继续**"；但上一轮你明确过"放回完即停"。本方案按**指令里说了"继续"就继续**来做
   —— 没说的仍按旧口径停。请确认。
2. **多解时怎么选？** 我按"列优先、列序、件数降序"选一个并回显 + 提供「换一种」；
   还是你要**每次自己指定**具体摆法（例如"蓝放第1列"）？
3. **B 区已有料怎么让我知道？** 只能靠"你在指令里说"（例如"B5、B9已有物体"）；
   要不要顺带做一个「**盘点 B 区**」（需要给 B 区拍照/或你手动确认一遍）？

## 6. 验收（先把回归钉子定下来）

| 层 | 钉子 |
|---|---|
| 解析 | "一行或者一列 / 同色成排 / 排成一列 / 同色一行" 等说法都能解析成 `pattern`；解不出时走大模型 |
| 求解 | 蓝3绿2红1 + 占 B5/B9 → 解**合法**（同色同线、不占占用/禁放格、不叠放）；**无解时明确拒绝**并说清原因 |
| 执行 | 遇无效色 → **放回原格 + 继续**（源码顺序钉 + 单测）；循环上限 = A 区可取件数（**不是固定 6**） |
| 视觉 | 黑块能被检出为"无效颜色"（本轮已加 4 条钉子；现场真图回放待补） |
| 回显 | 计划卡必须写出"我采用的摆法"，且与真正执行的摆法**同一份**（沿用现有 plan_id 绑定） |
