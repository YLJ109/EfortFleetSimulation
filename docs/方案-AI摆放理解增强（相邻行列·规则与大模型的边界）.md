# 方案：AI 摆放理解增强 —— 大模型优先推理 + 可行性闸门

> 2026-10-10 · 状态：**已实现并验证**（结果见文末 §11）
> 起因（用户原话）：
> 「不要给系统硬写啊，我说了让大模型思考判断，怎么一下就解析出来了啊？这个是大模型解析的吗？」
> 「好好理解用户说的不要乱跑啊，按相邻列或者行去实现的问题你思考一下，全面升级 ai 理解能力…要逻辑推理，判断，要准确的理解用户的意思！！！」

---

## 1. 先回答那句"这个是大模型解析的吗？"

**不是。** 现在的解析顺序（`backend/app/api/ai.py::_parse_to_plan`）：

```
规则解析 nl_intent.py  →（认得出）→ 直接出计划         ← 你看到"一下就解析出来"走的是这条
        └─（认不出）→ 大模型 llm.parse() → 仍要过白名单
```

你那句「B5,B9 已有…按同颜色一行或者一列摆放…无效颜色放回原位继续」**规则已能识别** → 所以**没走大模型**。
格位**不是写死的**，是 `services/placement.py` 穷举"同色的行/列"算出来的。

## 2. 现状（如实）

| 环节 | 现在怎么做 | 局限 |
|---|---|---|
| 听懂 | `nl_intent.py` 规则**优先**；失败才用大模型 | 规则命中 → **大模型根本没参与** |
| 摆放约束 | `pattern ∈ {row_or_col, row, col, any}` | **没有"相邻/连续"**；大模型**不许给格号** |
| 落格 | `placement.solve()` 穷举，跳过已有料/禁放格 | 只解 3×3 的"同行/同列" |
| 失败处理 | 解不出 → 当场拒绝（只给一句原因） | **没有"给建议/告诉我怎么才行"** |

## 3. ★ 已拍板（用户 2026-10-10 口径）

| # | 决定 |
|---|---|
| **Q1** | ① **先查"已有摆放/禁放"格，绝不把料压在已有料上面**；② **多规则试算**（按行、按列、相邻…），**能做才做**；**做不到就不能执行**，要**明确报"不符合逻辑 / 无法摆放 / 无法实现"，并给建议** |
| **Q2** | **每一句话都必须由大模型推理** —— 不再"规则优先" |
| **Q3** | **可以**：允许大模型直接给出**格号** |

## 4. 定稿设计

### 4.1 解析入口：大模型为**唯一主入口**
- `_parse_to_plan`：**每句话先调大模型**（`llm.parse`）；大模型返回结构化意图（动作 + 起点/目标 + 格号/约束 + 需不需要盘色）。
- 规则 `nl_intent`：**只在大模型不可用**（无 key / 断网 / 超时 / 报错）时作为**显式降级**，界面必须标注 **"降级：规则解析（大模型未连上）"** —— 不静默、不冒名。
- 大模型不可用且规则也认不出 → 明确报"没听懂"。

### 4.2 大模型可给格号 —— 但必须过**三道闸**（安全线不松）
1. **白名单** `llm.sanitize`：动作、格号（`A1..A9` / `B1..B9`）、颜色（红/绿/蓝）、`pattern`、`on_invalid`、数量（>0 且 ≤ `batch_max`）越界即拒。
2. **占用/禁放校验**（Q1①）：
   - 目标格 ∈ **已有料**（本页占位表 + 用户说的"B5/B9 已有"）或 **禁放格** → 拒绝（**不许叠放**）；
   - 取件格 ∈ 禁取格 → 拒绝。
3. **可行性校验**（Q1②）：用 `placement.solve()` 对**用户要求的约束**试算（行 / 列 / **相邻连续**），包括对"大模型直接给的格号"做**合法性+是否可行**双检。

### 4.3 不可行 → **不执行 + 报告 + 建议**（Q1②的核心）
返回 `{ok:false, reason, suggestions[]}`；**界面不显示"执行"按钮**，只显示"无法实现"和**可操作的建议**，例如：
- "按**列**摆不下（B5 已有料占了第2列）；改按**行**可以：蓝→B1·B2·B3"；
- "要 3 件蓝，但每列只剩 2 格：建议减少到 2 件，或先清掉 B5/B9"；
- "放不下是因为第 3 列被禁放占掉；换第 1 列可放 2 件"。
> 建议由**确定性求解器**穷举各种规则产生（不是大模型随口说）—— 大模型负责"听懂"，求解器负责"算能不能/怎么才行"。

### 4.4 摆法生成
- 用户说了摆放方式（含"相邻"）→ 求解器按约束算，**列优先/行优先都试**，取能成的；
- 大模型直接给了格号 → **校验通过就用它**；不通过 → 用求解器重算或**拒绝并给建议**（绝不"顺着"错格号执行）。

### 4.5 计划卡
显示：动作 + 起/目标 + **摆法**（每色→格，标注 行/列/相邻）+ **已有料/禁放格** + **备选摆法**；无法实现时只显示 **原因 + 建议**。

## 6. 不做什么（边界）

- ❌ 大模型再"能"，也**不能绕过白名单/占用/可行性校验**直接执行。
- ❌ 不引入新的执行原语（仍走 `_move/_air/_capture`）。
- ❌ 不改分拣页既有的"颜色→列"默认行为（没提摆放方式时保持现状）。
- ❌ 不静默降级（用规则必须**显式标注**）。

## 7. ★ 断网降级（用户 2026-10-10 拍板）

- 断网/无 key → **允许降级到规则解析**；
- 但**必须提醒用户**："这是**系统解析规则**，不是云端大模型" —— 界面上要有**显式标注**（`source="rule-degraded"` → 计划卡标"降级：系统规则（大模型未连上）"），不静默、不冒名。

## 8. ★ 数量二次确认（用户 2026-10-10 拍板）

- 解析出的**件数**在计划卡上**醒目回显**（"本次将搬 **3 件**（蓝×3）"）；
- **警告一次**："现场只有 3 个红，你确认要执行？"；
- **用户确认后直接执行**（不再多问）。
- 仍保留硬上限：数量 ≤ `batch_max`，超过直接拒。

## 9. ★ "相邻"的确切含义（用户 2026-10-10 拍板）

同色的几件必须落在**连续相邻**的一行或一列，且：
- **不能隔空**（中间不能跳空格 —— 如 B1、B3 不算相邻）；
- **中间不能有盒子/已有料**（被占格隔断 → 不算相邻）；
- 若因"中间有盒子"导致**无法相邻摆放** → **不能执行**，要向用户**提示**："中间有盒子（B5），逻辑不通/无法相邻摆放"，并给建议。

## 10. 施工顺序

1. **先修判色回归**（真 bug，与大模型无关）：见 [方案-判色回归修复](方案-判色回归修复（黑暗色与红绿蓝共存）.md) —— 红/绿漏检、黑→蓝。
2. **再做本文的 AI 大模型优先改造**（要动执行通道，改完必须跑全量回归 + 真机前先空跑）。

**验证**

| 项 | 结果 |
|---|---|
| 后端 `pytest -q` | 全绿 |
| 前端 `npm run build` + `npm run verify`（22 脚本） | 全绿 |
| **实网** `/api/ai/parse` | 「让机器人回到起点」→ `goto_start`（**source=llm**）；「盘点A区」→ `inventory`；「开始分拣」→ `sorting`；「急停」→ **source=safety** |
| **实网** 配额+约束句 | `move_quota`，`quotas={蓝3,绿2,红1}`、`pattern=row_or_col`、`on_invalid=continue`，摆法 `蓝→B1·B4·B7…`（**避开 B5/B9**） |
| **实网** 做不到（相邻+4件） | `ok=false, understood=true`，原因写明"「相邻」要求中间不能隔空、也不能有盒子"，**建议："「蓝」最多只能放 3 件（现在要 4 件）：建议减少到 3 件"** |

**必须如实说清的 3 点**

1. **急停是唯一绕过大模型的"安全直达"**（`source=safety`）：你要求"每句话都过大模型"，但**急停不能等网络** —— 这一条走规则并**在界面标注**，不冒名成大模型。
2. **现在每句话都会真的打一次 DeepSeek**（联网 + 有延迟）；断网时自动降级到规则，界面会**明确标注"不是云端大模型"**。
3. 大模型**能编数量**：已用"白名单（1..9/三色）+ 摆法求解 + 件数回显 + 说「执行」才动"四道防线兜住；若它把"3 个红"说成"8 个"，**件数回显**会让人在执行前看见。
