# 方案：原位禁转 + 未就绪统一门控

> 2026-10-12 · 用户两条需求（逐字在下方各节引用）· 已全量落地并回归

---

## 0. 一句话

**没就绪 → 一切"会让机器人动"的按钮（含急停）全部不可点，但可以录点；**
**在原位 → J6 一步都不许转（切面命令直接拒绝），原位之间不许直冲。**

---

## 1. 需求2：未就绪 → 全部禁止（可录点）

用户原话：
> 「如果没有就绪，把所有能执行到点，姿势，执行等等所有按钮禁止掉，不能点击的状态」
> 「如果示教器不是 auto，禁止一键就绪」
> 「让程序没有示教器的 210 程序没有加载完成，不要显示就绪成功」
> 「AI 也不能执行」「手柄的、井字棋的哪些执行按钮也不让点（没有就绪的话）」
> 「智能分拣的执行和点位可以预留，**不能到达，但是可以录点**」
> 「**如果没有就绪急停 / 复位急停也用不了**」
> 「一键就绪的要求是**程序加载、上电**等等」「**拿不到实时姿态禁止就绪**」
> 「**没有就绪可以录点，但是不能移动**」

### 1.1 ★★ 先修一个真 bug：`ready` 在正常运行时**恒为 false**

现场实测（`modbus.rc_vacuum_prepare` / `rc_ready._prog_ok` 的注释）：
> **正常运行态 = `prog=210 / run=1 / prog_loaded=0`** —— "已加载"位(bit11)在程序 RUN 起来之后会**落下**。

而旧判据是 `servo and prog_loaded and run` → `1 and 0 and 1 = 0` → **`ready` 永远是 false**
⇒ 前端 `rc.ready` 永远为假 ⇒ 所有"就绪门控"的按钮**本来就点不动**（这正是现场感觉"状态不对"的根）。

**修法（唯一实现）**：新增 `motion.readiness_reason(snap)` / `motion.snapshot_ready(snap)`

```
就绪 = 伺服上电
      + 常驻服务程序已就位（prog == motion.jog.service_program）**且运行位=1**
      + AUTO/远程档 + 无报警 + 无极停
```

- `api/robot.py`（`/api/rc-status`）与 `services/collector.py`（WS 广播）**都改为调它**（同屏同源）；
- **不再要求 `prog_loaded`**（它 RUN 起来会落下）。

### 1.2 后端闸门升级为"完整就绪"

`motion.servo_not_ready_reason`（`api/control.py::reject_if_not_ready` 的唯一判据）
由**只看伺服位**升级为 `readiness_reason`（完整就绪）。拒绝文案统一以
**「机器人没有就绪：…」** 开场，冒号后**如实**说明是哪一条不满足（不笼统写"伺服未上电"）。

- 覆盖入口（原有）：`/control/move|run-file|jog/*|vacuum`、`/sorting/start|goto`、
  `/tictactoe/start|restore`、`/ai/exec`、`/api/vision_rules` 自动执行；
- **豁免（必须放行）**：空跑 `dry_run`、模拟模式（双闸未开）、以及**就绪流程本身**（防死锁）。

### 1.3 前端统一灰化（各处"只看控制权限"的缺口全部补上）

| 位置 | 改法 |
|---|---|
| `ExecControlCard.vue` 吸/放 8 键 + **急停 / 复位急停** | 统一 `canAct = canControl && rc.ready` |
| `SortingView.vue`「开始」 | `canStart` 加 `rc.ready` |
| `SortingView.vue`「到点 / 切面」 | 新增 `canGoto = canTeach && rc.ready` |
| `SortingView.vue`「存点 / 删除」 | **保持可点**（录点允许） |
| `TicTacToeCard.vue`「开始 / 复原」 | 新增 `canRun = canCtrl && rc.ready`；**停止/暂停不加**（刹车必须可点） |
| `AiControlView.vue`（store `ai.canExec`） | 加 `auth.controlActive && rc.ready` |
| `PadExecView.vue` / `stores/pad.js` | `pad._gate()` 加第三道 `rc.ready`（A/Y/X/B/LB/RB 全走它） |
| `PointExecView.vue`「取当前位姿」 | 改 `canControl`（只**读**实时姿态，不动机器人） |
| `PointExecView.vue`「存为点位」 | 改 `auth.controlActive`（**只写配置** → 未就绪也能录点） |
| `RcReadyCard.vue`「一键就绪」 | 加 `!rc.joggable`（非 AUTO）禁用；`canControl` → **拿不到实时姿态即禁用**（需求4） |

**没改**：速度口径、围栏互锁、40135 位表、`keep` 面语义、18 原料位禁转黑名单。

## 2. 需求1：原位禁转 + 原位安全路径

用户原话：
> 「不能原位到原位进行移动……你直接**原位，正上位，目标的正上位，原位**就行了，任何程序也是」
> 「原位到正上位更不能旋转……**必须正上位旋转完成后才可以来到原位**」
> 「原位也不能进行 J6 旋转」「**原位禁止旋转拒绝指令！**」
> 「我的意思是**禁止旋转**就行了，J6 **保持每个点的自己的正反方向**就行了」
> （⇒ **不引入新的 `hold` 面语义**，继续用现有 `keep`：正面=该点自身录制 J6、反面=自身−180）

### 2.1 判据："现在停在哪"（唯一、无状态）

新增 `services/sorting.py::current_raw_slot(live, poses, tol=3.0)`

```
当前停在原料位 = 实时 6 关节 vs 18 个原料位的示教姿态，任一轴偏差 ≤ 3°（J6 按环形差 ±360 等价）
```

- **无状态** ⇒ 点动 / 手动下发 / 丢事件之后**自动正确**，不靠"上一次到了哪"那种会撒谎的状态；
- 拿不到实时姿态 / 拿不到原料位示教值 → 返回 `None` = **判不出** → 调用方按 **fail-safe 拒绝**；
- 数据源 `services/sorting.py::raw_slot_poses()`（读库一次；坏行跳过；延迟导入 db 以保持模块可独立导入）。

### 2.2 规则（一条总规则 + 各入口的落地方式）

| # | 规则 | 落点 |
|---|---|---|
| 1 | **原位不转**：停在原料位时发起 `J6正面`/`J6反面` → **不拒绝，自动补段**：先抬到正上位、**在那里转**、再回原位（见 §5） | `/sorting/goto`、`_move_flip_j6`、`/control/move`、`_run_file_job` / `execute_rule` |
| 2 | ★★ **唯一安全模型**：**垂直只在"某格原位 ↔ 该格正上位"；横向只在"正上位 / 起点 / 摄像头"之间** —— **进出原料位都必须经该料位自己的正上位** | 唯一 planner `services/sorting.py::raw_slot_safe_path`（点名 → 完整路径）+ `raw_slot_step_segments` / `raw_slot_step_targets`（脚本·显式下发 → `(pre, post, err)`） |
| 3 | **交互入口**（`/sorting/goto` / 手柄 A·Y / 分页到点）**自动补段**，回执带 `path` 并如实显示：<br>· `X → 另一原位 Y` = `X上 → Y上 → Y`<br>· `X → 起点 / 摄像头 / 其它点 Z` = `X上 → Z`<br>· `X → X上` = 单段（抬起本身）<br>· `… → 原位 Y`（从正上位/起点/摄像头来）**必经 `Y上`**<br>· **已在目标点** → 如实 409「无需移动」 | `/sorting/goto`（`_goto_segment` 链式传 `base`） |
| 4 | **程序 / 脚本 / 显式下发**（`/control/move` 显式 6 轴、`_run_file_job` 点名+显式步骤、`vision_rules.execute_rule`、`_move` 兜底）**同样自动补段**：走 `pre` → 原目标 → `post`（点位姿态表**每次执行惰性只读一次**；`pmap` 里没有该段则跳过，不硬造） | 各入口 + `raw_slot_step_targets` |
| 5 | **原位切面**（`J6正面`/`J6反面`）= `X上`（抬起）→ 切面 → `X`（回原位，**沿用刚切好的面**） | 同上（`post` 段） |
| 6 | **升降两段 J6 冻结**（「原位到正上位更不能旋转」「必须正上位旋转完成后才可以来到原位」）：垂直段目标 J6 = **上一段终点的 J6**，途中绝不转 | `compose_j6_only`；`/sorting/goto` 多段链式 `base` |
| 7 | **笛卡尔（IK）步骤不补段**（已知限制，见 AGENTS §7）：IK 目标天然不等于任何示教姿态 | 各入口限定 `mode == "joint"` |

**没改**：`keep` 面语义（正面=自身、反面=自身−180）、`is_raw_material_slot` 黑名单、
`_rotation_guard`、`resolve_target_joints`、`effective_face`、旋转授权（`allow_rotate`）白名单。

### 2.3 为什么不引入 `hold`（冻结实时 J6）

一度考虑"原位↔正上位两段把 J6 冻结成实时值"，但那会**推翻** 2026-10-12 刚定稿的
`keep`（正面=该点自身录制值，解决 A1上/A3上 对位偏差）。用户口径是
「**禁止旋转**就行，J6 **保持每个点自己的正反方向**」⇒ 维持 `keep`，**不做冻结**。
