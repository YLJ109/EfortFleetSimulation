## 1. 铁律（违反任意一条，代码必错）

### 铁律 1 —— `WAIT` 只等「读区」，绝不等「写区」

- 上位机 → 机器人 的触发位是 **读区** `fidbus.mtcp_ro_b[n]`
- 机器人 → 上位机 的回执位是 **写区** `fidbus.mtcp_wo_b[n]`

程序里 `WAIT` 的条件**必须**是 `ro_b`。若误写成 `wo_b`，程序第一句刚把它置 `false`，
于是永远等不到，**程序卡死在 WAIT 那一行**。

**现场现象**：上位机「运行」位常亮、`40035` 完成位恒 `0`、机器人一动不动。
**确认方法**：示教器打开程序，看「当前执行行」是不是停在 `WAIT`。
这是 2026-09-23 现场实测**最高频**的故障。

### 铁律 2 —— 多个服务**禁止串联阻塞式 WAIT**

一条 `WAIT` 会把整个程序停在那一行。所以**不能**把点动、吸气、放气写成三段落地的 `WAIT`：

```rpl
(* ❌ 错误写法：点动服务会一直堵在这里，吸气/放气永远轮不到执行 *)
WHILE true DO
    WAIT(fidbus.mtcp_ro_b[0]);      (* 没有点动请求 → 堵死 *)
    MJOINT(...);
    WAIT(fidbus.mtcp_ro_b[1]);      (* 永远到不了这一行 *)
    io.DOut[8] := true;
END_WHILE;
```

**正确写法**是用「`WHILE 触发位 DO` 门控」——触发位为真才进服务体，为假立刻跳过，
主循环不阻塞，三个服务可以独立调用、互不干扰：

```rpl
(* ✅ 正确写法 *)
WHILE true DO
    WHILE fidbus.mtcp_ro_b[0] DO      (* 点动：Bit0 为真才进，撤位即退出 *)
        ... 点动服务体 ...
    END_WHILE;

    WHILE fidbus.mtcp_ro_b[1] DO      (* 吸气：Bit1 *)
        ... 吸气服务体 ...
    END_WHILE;

    WHILE fidbus.mtcp_ro_b[2] DO      (* 放气：Bit2 *)
        ... 放气服务体 ...
    END_WHILE;

    DWELL(0.02);                      (* 扫描节流 20ms *)
END_WHILE;
```

> 依据：`210_示教服务.XPL` 的注释原文——
> 「用 `<while cond="触发位">` 来实现：它的元素形状与 200 里已验证的
> `<while><cond>true</cond><pouref>1</pouref></while>` 完全一致，只换了条件表达式。」

### 铁律 3 —— 触发位 / 完成位必须错开分配

| 服务 | 触发位（上位机写 → 机器人读） | 完成位（机器人写 → 上位机读） |
|---|---|---|
| 点动 | `fidbus.mtcp_ro_b[0]` = 40135.Bit0 | `fidbus.mtcp_wo_b[0]` = 40035.Bit0 |
| 吸气 | `fidbus.mtcp_ro_b[1]` = 40135.Bit1 | `fidbus.mtcp_wo_b[1]` = 40035.Bit1 |
| 放气 | `fidbus.mtcp_ro_b[2]` = 40135.Bit2 | `fidbus.mtcp_wo_b[2]` = 40035.Bit2 |
| 关节角 | `fidbus.mtcp_ro_i[0..5]` = 40139~40144（J1~J6 ×100） | — |

**永远不要复用同一个位。** 新增服务一律往下取 `[3]`、`[4]`……

### 铁律 4 —— 纯文本 RPL 的书写形态

由官方手册示例确认（`MJOINT(*, v500, fine, tool0);`、`p0 := POINTC(...);`、`IF res = 1 THEN` / `END_IF ;`）：

| 要素 | 写法 | 备注 |
|---|---|---|
| 语句结束 | `;` | 每条语句都要 |
| 赋值 | `:=` | 不是 `=` |
| 注释 | `(* 注释 *)` | 不是 `//`，不是 `#` |
| 关键字 | **全大写** | `WHILE` / `DO` / `END_WHILE` / `WAIT` / `MJOINT` / `IF` / `THEN` / `END_IF` / `DWELL` |
| 布尔 | `true` / `false` | 小写，与 200.XPL 中 `<expr>true</expr>` 一致 |
| 取反 | `NOT fidbus.mtcp_ro_b[0]` | |
| 循环 | `WHILE <条件> DO ... END_WHILE;` | |
| 等待 | `WAIT(<条件>);` | |
| 等待时间 | `DWELL(<秒>);` | |
| 运动 | `MJOINT(POINTJ(j1,...,j6), v50perc, fine, tool0);` | |

> ★★ **易踩坑（2026-09-29 实测确认）：`.XPL` 导出里的取反是 `!`，但文本 RPL 必须写 `NOT`。**
>
> 同一条等待语句，两种形态长得不一样：
>
> | 形态 | 写法 |
> |---|---|
> | 在示教器/IDE 里**敲的文本**（本规范、`点动服务程序缺失排障.md` 的口径） | `WAIT(NOT fidbus.mtcp_ro_b[0]);` |
> | 导出/保存后的 **`.XPL` XML**（`200.XPL`、`210.XPL` 实测都是这样） | `<wait><condition>!fidbus.mtcp_ro_b[0]</condition></wait>` |
>
> 也就是说 `!` 是编辑器**规范化后的内部表示**，不是可照抄的文本语法。
> 反面教材：曾照 `210.XPL` 里的 `!` 写纯文本源码，交付稿里写成
> `WAIT(!fidbus.mtcp_ro_b[0]);` —— 用户当场指出应为 `NOT`。
> **判据：抄写文本一律以本表（`NOT`）为准；只有直接编辑 `.XPL` 的 XML 时才写 `!`。**

### 铁律 5 —— `.XPL` 是结构化 XML，**禁止手写文本文件当 `.XPL` 用**

`.XPL` 的文件体是**结构化指令 XML**（`<Pous>/<Pou>/<Body>/<while>/<mjoint>/<set>/<wait>/<dwell>`）。
手写一份纯文本、改后缀成 `.XPL` 再导入，控制器会报 **4902（XPL 文件 API 错误：程序文件内容损坏）**，
或表现为「程序在，就是不动」。

**纯文本 RPL 的正确用途只有两个**：
1. 在**示教器【指令】菜单里逐条点选插入**时的对照稿（点选后由系统生成 XML）；
2. 在**墨斗IDE 离线编程**里作为 `.pgm` 源码编辑，再由 IDE 导出/下装。

> 官方原文：**「如不保存到文件，对程序的修改将是暂时的」** —— 改完必须点【保存】。

### 铁律 6 —— 速度：程序内常量 × 40103 倍率

- 有效速度 = **程序内 `v…perc` 常量 × 速度设定寄存器 40103**
- 现场实测基线：`v100perc` × `40103 = 5%` ≈ **1.3°/秒**
- 本规范统一：**程序内常量写 `v50perc`**（不写 `v100perc`），需要更快就调 40103，**不改程序**
- 40103 由上位机面板的「速度 %」写入，默认 **5%**（最慢安全档）
- ⚠ 速度控制必须写 **40103**，写 40102 无效

### 铁律 7 —— 文件与工程结构

- 文件名：**以字母开头**，只含字母/数字/下划线，**≤31 字符**
- **每一个 `.pgm` 必须配一个同名的 `.var`**（如 `jogsvc.pgm` ↔ `jogsvc.var`）
- 墨斗IDE 工程目录：`RPLAPP/Program/*.pgm` + `RPLAPP/Var/*.var`
- 新建 RPL 工程的默认文件：**不要删、不要改名**

### 铁律 8 —— 参数区写入后必须静置，不能「写完就触发」

写 `40139~40144` 后**立刻**置触发位，控制器还没把读区同步进程序变量空间，
`MJOINT` 读到的是上一轮旧目标角（= 当前角）→ **不动，但照常回执**。

**现场现象**：触发后 0.1 秒内就收到完成位，可角度一动不动。
**已修**：程序回读校验 + **静置 0.15 秒**后才触发（`tools/jog_axis.py` 与 `app/worker.py`）。

## 2. 200 服务程序 · 纯文本 RPL（主交付物）

> ⚠ **现场当前口径已统一到程序号 210（三合一：点动 + 吸气保持 + 停止吸气），
> 见 §2.5。** 本章的 200 版本保留为历史参考（控制器上的 200 仍是可用的纯点动
> JOGSVC，作为回退保留）。**新建/修改服务程序请以 §2.5 为准。**

### 2.1 程序文件 `jogsvc.pgm`

```rpl
(* ================================================================
   程序号 : 200          （控制器里的程序号，上位机认这个号）
   名称   : jogsvc       （文件名以字母开头，≤31 字符）
   用途   : 点动 + 吸气 + 放气 三合一常驻服务程序
   速度   : v50perc —— 有效速度 = v50perc × 速度设定寄存器 40103
   ================================================================ *)

WHILE true DO

    (* ---------- ① 点动服务：等 40135.Bit0 ---------- *)
    WHILE fidbus.mtcp_ro_b[0] DO
        fidbus.mtcp_wo_b[0] := false;
        MJOINT(POINTJ(fidbus.mtcp_ro_i[0]/100.0,
                      fidbus.mtcp_ro_i[1]/100.0,
                      fidbus.mtcp_ro_i[2]/100.0,
                      fidbus.mtcp_ro_i[3]/100.0,
                      fidbus.mtcp_ro_i[4]/100.0,
                      fidbus.mtcp_ro_i[5]/100.0), v50perc, fine, tool0);
        fidbus.mtcp_wo_b[0] := true;
        WAIT(NOT fidbus.mtcp_ro_b[0]);
    END_WHILE;

    (* ---------- ② 吸气服务：等 40135.Bit1 ---------- *)
    WHILE fidbus.mtcp_ro_b[1] DO
        fidbus.mtcp_wo_b[1] := false;
        io.DOut[8] := true;
        DWELL(0.30);
        fidbus.mtcp_wo_b[1] := true;
        WAIT(NOT fidbus.mtcp_ro_b[1]);
    END_WHILE;

    (* ---------- ③ 放气服务：等 40135.Bit2 ---------- *)
    WHILE fidbus.mtcp_ro_b[2] DO
        fidbus.mtcp_wo_b[2] := false;
        io.DOut[8] := false;
        DWELL(0.30);
        io.DOut[9] := true;
        DWELL(0.40);
        io.DOut[9] := false;
        DWELL(0.10);
        fidbus.mtcp_wo_b[2] := true;
        WAIT(NOT fidbus.mtcp_ro_b[2]);
    END_WHILE;

    DWELL(0.02);

END_WHILE;
```

**逐行说明**

| 行 | 作用 |
|---|---|
| `WHILE true DO` | 死循环 —— 让程序常驻，不退出 |
| `WHILE fidbus.mtcp_ro_b[0] DO` | **门控**：Bit0 为真才进点动服务；为假直接跳过，不阻塞后面的服务 |
| `mtcp_wo_b[0] := false` | 清完成位，告诉上位机「我准备好接新指令」 |
| `MJOINT(POINTJ(...), v50perc, fine, tool0)` | 运动到 6 个绝对关节角（通道里是 ×100 整数，`/100.0` 还原成度） |
| `mtcp_wo_b[0] := true` | 置完成位 = 40035.Bit0，告诉上位机「到位了」 |
| `WAIT(NOT fidbus.mtcp_ro_b[0])` | 等上位机撤触发位 → 同一发不会被执行两遍 |
| `io.DOut[8] := true` | 吸真空 |
| `io.DOut[8] := false` | 断吸真空 |
| `io.DOut[9] := true/false` | 吹气破真空 开 / 关（0.4 秒） |
| `DWELL(0.02)` | 扫描节流 20ms，保证 IO 桥接刷新延迟可忽略 |

### 2.2 配对变量文件 `jogsvc.var`

本程序**不声明自定义变量**：6 个关节角直接在 `MJOINT` 的参数位置用表达式
`fidbus.mtcp_ro_i[n]/100.0` 取，与真机上已验证可用的 `200.XPL` 写法一致。

> 若你的固件版本**不接受「参数位置写表达式」**，改用备选版：
>
> 在 `jogsvc.var` 里声明 6 个 LREAL 程序变量（用途 `Routine`、存储 `Var`、作用域 `LOCAL`）：
>
> ```rpl
> Routine   Var   LREAL   j1
> Routine   Var   LREAL   j2
> Routine   Var   LREAL   j3
> Routine   Var   LREAL   j4
> Routine   Var   LREAL   j5
> Routine   Var   LREAL   j6
> ```
>
> 然后把 `.pgm` 里那条 `MJOINT` 换成先赋值再调用：
>
> ```rpl
> j1 := fidbus.mtcp_ro_i[0]/100.0;
> j2 := fidbus.mtcp_ro_i[1]/100.0;
> j3 := fidbus.mtcp_ro_i[2]/100.0;
> j4 := fidbus.mtcp_ro_i[3]/100.0;
> j5 := fidbus.mtcp_ro_i[4]/100.0;
> j6 := fidbus.mtcp_ro_i[5]/100.0;
> MJOINT(POINTJ(j1,j2,j3,j4,j5,j6), v50perc, fine, tool0);
> ```

## 2.5 ★ 现场当前口径：程序号 210 · 四服务常驻程序（2026-09-29 定案，v3.0）

**为什么改成 210 且必须"一个程序装下所有服务"**：控制器**同一时刻只能加载并运行一个程序**。
点动与吸放拆成两个号（200 点动 / 210 吸放）后，Web 每按一次按钮都要
「停当前程序 → 加载另一个号 → 运行」；来回切程序 = 反复报 **5005** + 切换竞态。
合到一个程序号后零切换。

**五个服务（位分配遵循铁律 3：一个位只干一件事）**：

| 服务 | 触发位 | 控制器动作 | 完成位 |
|---|---|---|---|
| 点动 | `40135.Bit0` | `MJOINT(POINTJ(...), `**`v100perc`**`, fine, tool0)` | `40035.Bit0` |
| 吸 | `40135.Bit1` | `io.DOut[N] := true`（**电平保持**） | `40035.Bit1` |
| 停止吸 | `40135.Bit2` | `io.DOut[N] := false` | `40035.Bit2` |
| 放 | `40135.Bit3` | `io.DOut[M] := true`（**电平保持**，吹气） | `40035.Bit3` |
| 停止放 | `40135.Bit4` | `io.DOut[M] := false` | `40035.Bit4` |

★★ **速度常量必须是 `v100perc`**（2026-09-29 现场治理）：
`有效速度 = 程序内 v…perc × 40103`。用 `v50perc` 时，上位机为了"右上角 = 实际速度"
必须把 40103 写成本身的 **2 倍**（右上角 17% → 写 34%），于是**示教器速度显示 34%、
右上角 17%**，现场报"点动速度突然飘升到 34%"。改 `v100perc` 后：
`有效速度 = 100% × 40103 = 40103` → **上位机写多少、示教器显示多少、机器人走多少，三者一致**。
必须同步 `config/robot.yaml` 的 `motion.jog.service_program_vperc: 100`（改一边不改另一边会差一倍）。

★ **为什么"放"要独立占一个位**：现场实测「吸 → 停止吸之后**工件一直贴着不掉**」——
只关真空阀挡不住残余负压/密封，必须给一下正压。但有些场合只需轻轻松手、不想吹气，
所以两者不能合并。`N` = 真空阀输出号（参考 8）、`M` = 吹气阀输出号（参考 9），
**都以示教器 IO 监控实测为准**（程序不读回 DO，写错号时上位机照报"完成"而阀没动）。

★ **四路气路全部电平保持**：吸/放 置位后一直保持，靠对应的"停止"动作关断。
想"吹一下就收"，在上位机序列里排 `[放, 等待 0.4s, 停止放]`，**不要**在程序里写自动停 ——
大件/需要持续吹的场合，自动停会吹不到位。

**交付物**（都在 `programs/`）：

| 文件 | 用途 |
|---|---|
| `210_service_merged.pgm` | **纯文本 RPL**，照抄/点选插入用（最终稿） |
| `210_merged.XPL` | 结构化 XML，直接导入用（元素序列与 .pgm 一一对应） |
| `210_old_vacuumonly_backup.XPL` | 历史：只有吸放、**没有点动段**的旧版（已弃用，留档） |

**与本章 §2 的 200 版本的三处关键差异**：

| # | 200 版（§2） | 210 版（当前） | 为什么改 |
|---|---|---|---|
| 1 | 吸气 `DWELL(0.30)` + 0.5s 脉冲自动停 | 吸气 `io.DOut[N] := true` **电平保持**，须由 Bit2 显式关断 | 脉冲会让阀自动松手 → 工件脱落 |
| 2 | 只清块内完成位 | **循环顶 + 块内**两处都清 0 | 上位机逻辑是「置触发 → 轮询完成位 → 撤触发」；完成位残留 1 会被误判"已完成"并立刻撤触发，对应分支永不执行（症状：第二次按吸气/点动没反应）。循环顶清保证**空闲期恒 0** |
| 3 | 放气会 `io.DOut[9]` 吹气 0.4s | 只 `io.DOut[N] := false` 关断 | 现场不需要吹气破真空；需要时再开 |

**易错点（真机踩过）**：

1. `WAIT(NOT fidbus.mtcp_ro_b[N]);` —— 取反**必须写 `NOT`**。`!` 只出现在 `.XPL`
   的 `<condition>` 里（编辑器规范化后的内部表示），文本源码照抄 `!` 不合规范。
2. `io.DOut[N]` 的 **N ≡ 现场电磁阀实际输出号**，以 IO 监控实测为准
   （参考项目 CARRY.XPL 是 8）。程序**不读回 DO** → N 写错时上位机仍报"吸气完成"
   而阀不动，所以必须人工在示教器 IO 页面确认。
3. **改完必须「保存 → 下载到控制器 → 重新运行」**。示教器上编辑的版本 ≠
   控制器上正在运行的实例（真机踩过：编辑版有点动段，控制器上跑的还是旧的纯吸放版）。
4. 常驻程序里**不要**再调用 `CMD_LOAD`：程序运行中发加载命令，控制器会抛
   **5005** 并锁存报警；此后 `MJOINT` 被拒、完成位永不置位。清报警也必须
   **先停机再清**，否则运行中的程序会把 5005 重新顶上（0.5s 内复现）。

对应上位机配置（`config/robot.yaml`）：

```yaml
motion:
  jog:
    service_program: 210       # 点动
    service_program_vperc: 50  # 程序内写 v50perc，与之一致
  vacuum:
    service_program: 210       # 吸放（必须与 jog 同号，否则来回切程序）
  ready:
```

## 4. 寄存器 / 变量映射速查

来源：官方手册《C30 RPL 指令手册》15.4.5 ModbusTCP 映射表（RP-2 实测吻合）。

| 方向 | Modbus 地址 | 位区 / 类型 | RPL 变量 | 含义 |
|---|---|---|---|---|
| PC → 机器人 | 40135~40138 | BOOL 位区 | `fidbus.mtcp_ro_b[0..63]` | Bit0 点动触发 / Bit1 吸气触发 / Bit2 放气触发 |
| PC → 机器人 | 40139~40144 | I16 | `fidbus.mtcp_ro_i[0..5]` | J1~J6 目标绝对角 ×100（0.01° 分辨率） |
| 机器人 → PC | 40035~40038 | BOOL 位区 | `fidbus.mtcp_wo_b[0..63]` | Bit0 点动完成 / Bit1 吸气完成 / Bit2 放气完成 |
| PC → 机器人 | 40103 | I16 | — | **速度设定（%）** —— 速度闸门，必须写这个地址 |
| PC → 机器人 | 40101 | 控制字 | — | `0x1001` 伺服上电 / `0x1004` 停止 / `0x1005` 急停 / `0x1008` 清报警 |
| PC → 机器人 | 40104 | I16 | — | 程序号 |

**IO 映射**：`io.DOut[8]` = 吸真空（true 吸 / false 断）；`io.DOut[9]` = 吹气破真空；
`io.DIn[8]` = 真空到位反馈。

**点动参数区写入顺序（必须遵守铁律 8）**：
写 40139~40144 六个绝对角 → **静置 0.15 秒** → 置 40135.Bit0 → 等 40035.Bit0 → 撤 40135.Bit0。

## 5. 错误对照表（报错先查这里）

| 报错 / 现象 | 根因 | 处置 |
|---|---|---|
| **4902** XPL 文件 API 错误：程序文件内容损坏 | 用文本手打了 `.XPL` | 改回示教器指令栏点选插入，或墨斗IDE 导出 |
| **5005** 程序不存在 | 没保存 / 示教器停在文件管理界面 | 保存后退出编辑态再试 |
| 运行位常亮、点了不动、40035 恒 0 | **WAIT 条件选错**（写成写区 `wo_b`） | 必须等读区 `ro_b`；查「当前执行行」是否停在 WAIT |
| 加载成功但点了不动 | MJOINT 参数问题（速度倍率为 0 / 坐标系没选）/ 面板「速度 %」是 0 | 检查 40103 与 MJOINT 的 `zone`/`tool` |
| **完成位秒回、机器一点没动** | 写 40139~44 后立刻触发，读到旧目标角 | 回读校验 + 静置 0.15 秒后再触发（铁律 8） |
| 吸气/放气指令没反应 | 服务被前面的阻塞 `WAIT` 堵住 | 改成 `WHILE <触发位> DO` 门控（铁律 2） |
| 「程序运行位未置位」 | 控制器侧常驻服务程序没在运行 | 示教器切【自动】→ 加载并运行 200 服务程序 |
| 401 Unauthorized | 后端重启导致控制令牌失效 | 重新登录（口令见 `.env` 的 `EFORT_ADMIN_PASSWORD`） |
| 按文件名执行未命中 | 后端文件匹配大小写/扩展名 | 后端已修：无扩展名时先原样查，再试 `.xpl` / `.json` |
