# 方案：颜色无法识别 → 一律「放回原位」（分拣 / AI / 井字棋统一）

> 2026-10-10 用户口径：
> ①「如果颜色无法识别**放回原位**，分拣、AI、游戏等等全部一样」
> ②「跳过这件事情，**如果完成了停就行了**」—— 不做"跳过继续"，放回完就停
> ③「要**两种模式**：一个是**拍照自证**，一个是**默认的**」

---

## 1. 背景：现在三条链路各干各的（且都不是"放回原位"）

| 链路 | 判色失败时的**现状** | 问题 |
|---|---|---|
| 分拣 | `raise _Stop("检测不到…")` → 整条流程停住；异常处理只关两路气 → 件**就地掉在 C 检测位** | 件不回原位、位置随机，现场得人工找件 |
| AI 执行 | 内部调的就是分拣同一条链路 → 同上 | 同上 |
| 井字棋 | **不判色**（符号由格位决定：A1–A5=圆、A6–A9=叉），无 C 检测位 | "无法识别"这个场景根本不存在 → "全部一样"落不了地 |

---

## 2. 统一规则（本方案的核心，只有一条）

> **凡是要判色的地方，判不出来 → 把件「原路放回取料格」→ 然后停止。**

- **放回**：走完整工艺（下落 → 停止吸 → 放气 → 等 blow_ms → 停止放气 → 抬起 → 回开始/结束点），
  不是"就地松手"。
- **停止**：放回完成后**结束本轮**，不跳过、不继续（用户 2026-10-10 明确否掉"跳过"）。
  停止原因如实写：`颜色无法识别（真原因），已放回原位 A{n}` —— 界面/日志/审计三处一致。
- **不允许**：就地掉件、投到别处（本项目**没有**"待复核区"点位，本方案也不新增）。

---

## 3. 两种模式（井字棋）

分拣/AI 判色是**本职**，没有开关。井字棋的符号本来由格位决定，判色属于"加一道自证"，所以做成开关：

| 模式 | 行为 | 节拍 |
|---|---|---|
| **默认**（`verify_color=false`，缺省） | 不判色、不去 C 位，取料→直接去 B 落子（= 现在的行为） | 快 |
| **拍照自证**（`verify_color=true`） | 取料抬起后**先去 C 检测位拍 3 帧**判色，颜色必须 = **该格应有的颜色**；一致才去 B 落子 | 每手多一次"送检 → 停顿 → 拍照" |

**"该格应有的颜色"= 装料约定**（写成常量，卡片上显示，便于现场纠正）：

```python
SYMBOL_COLOR = {"O": "红", "X": "蓝"}   # 圆=红（A1–A5 装红件）/ 叉=蓝（A6–A9 装蓝件）
```

自证失败分两种，**处置相同（放回原位 + 停）**，但**文案要分清**（不然现场会往错的方向查）：

| 情况 | 停止原因 |
|---|---|
| 判不出色 | `颜色无法识别（< votes 真原因>），已放回原位 A{n}` |
| 判出色但**不是该格应有色** | `自证不符：该格应为 红，实拍 蓝，已放回原位 A{n}` |

## 4. 实现清单（做什么）

### 后端
1. **`api/sorting.py`**
   - 抽出 `vision_preflight(body_min_conf=None) -> float`：把 `api_start` 里那段"视觉服务前置校验 + 取 min_conf"
     （现状 L287–298 的 4 条校验与文案）原样提成函数 —— 分拣与井字棋共用，**行为与文案不变**。
   - 新增 `_put_back(ctx, pmap, src_slot, speed, dry, blow_ms=500, stage_prefix="放回原位")`：
     **从当前位置原路放回取料格**（下落 → 停吸 → 放气 → 等 → 停放 → 抬起 → 回起点）。
   - 判色失败分支改为：先 `_put_back(...)`，再 `raise _Stop("…已放回原位 A{n}")`；
     同时把 `suck_on/blow_on` 置 False（两路气已在 `_put_back` 内正常关断，异常收尾不再重复关）。
2. **`api/tictactoe.py`**
   - `StartIn` 增 `verify_color: bool = False`；`_new_state` 记 `verify_color`。
   - `api_start`：`verify_color and 真实下发` 时走 `vision_preflight()`（相机没就绪**开局就拒**，
     不给"跑了但做不了"的假象），并把 `min_conf` 存进 state。
   - `_carry`：`verify_color` 时在"抬起"之后插入 **送检 C 位 → dwell → `_capture` 拍 3 帧判色**；
     通过 → 继续经起点去 B 落子；不通过 → `_put_back` → `raise _Stop(…)`（见 §3 双文案）。
   - `SYMBOL_COLOR` 常量 + 停止/事件文案带"已放回原位"。

### 前端
3. **井字棋卡片**：新增**模式**选择（默认 / 拍照自证），开局前可选；卡片显示当前模式与"自证约定：圆=红 / 叉=蓝"；
   自证模式给出节拍提示（每手多一次送检）。
4. **`stores/tictactoe.js`**：`start()` 传 `verify_color`；state 回显模式。

### 文档
5. 本文件 + 更新《方案-井字棋对弈》§5 的搬运时序（补自证分支）。

---

## 5. 不做什么（明确边界）

- **不改判色阈值/算法**（`fill_min`、min_conf 等一个都不动 —— 要改必须先跑现场
  `camera/tools/vision_e2e_replay.py`）。
- **不新增"待复核区"点位**，也不做"跳过继续/重试该件"。
- **不动真机安全口径**：速度（沿用右上角全局速度）、围栏互锁、轴锁、40135 触发位互斥一律不变。
- **不判色的场景保持不判色**：空跑 / 双闸未开时**绝不调相机**（物体没到 C 区，判了必然是"检测不到"）——
  放回逻辑同样只在"真的判色"时才会触发。

---

## 6. 验收

| 场景 | 期望 |
|---|---|
| 分拣·真实下发·判不出色 | 机器人把件放回 A{n} → 回开始/结束点 → 停止；原因写明"已放回原位 A{n}" |
| AI 执行·同上 | 与分拣逐字一致（同一条链路） |
| 井字棋·默认模式 | 全程不拍照、不去 C 位（与现状一致） |
| 井字棋·拍照自证·颜色正确 | 送检 → 通过 → 正常落子 |
| 井字棋·拍照自证·判不出 / 颜色不符 | 放回 A{n} → 停止；两种文案分别给出 |
| 井字棋·自证模式但相机没就绪 | **开局即 400/502 拒绝**（不进入运动） |
| 空跑（任何模式） | 不调相机、不判色、不触发"放回" |

回归钉子：`pytest`（新增：放回点位序列、停止文案、自证通过/不符/无画面、模式默认值、模式缺省不判色）
+ 前端 `verify_tictactoe.mjs`（模式开关与 `verify_color` 透传）。
