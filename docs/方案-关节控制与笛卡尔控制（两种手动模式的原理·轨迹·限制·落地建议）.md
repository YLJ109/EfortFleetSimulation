# 方案：关节控制与笛卡尔控制（两种手动模式的原理 · 轨迹 · 限制 · 落地建议）

> **本文只写方案，不改任何代码、不提交、不启服务。**
> 目的：把「示教器上两种手动控制方式——**关节控制**（只动一个轴）与**机器人整体控制**
> （TCP 按笛卡尔方向移动）」讲透：**定义 → 运动空间/轨迹/插补 → 正逆运动学 → 限制与范围
> → 主流示教器做法 → 本项目现状（逐条对照代码）→ 在本项目如何落地**。
>
> 术语纠正（务必先对齐）：「**笛卡尔积**」是集合论概念（A×B 的有序对集合），
> 与"机器人整体移动"无关；这里说的是「**笛卡尔空间 / 笛卡尔坐标系**（Cartesian space）」，
> 即以直角坐标 `X/Y/Z + A/B/C` 描述末端（TCP）的位置与姿态。下文统一用「笛卡尔空间」。

---

## 0. 结论摘要（TL;DR）

1. 两种模式的本质区别是**"在哪一个空间里做插值"**：关节模式在**关节空间**插值（各轴角值直接线性过渡），
   笛卡尔模式在**笛卡尔空间**插值（末端位姿走直线/定轴旋转），后者**必须先逆解成关节角才能下发**。[S1][S4][S7]
2. **关节插值时 TCP 走的是弧线**（因为 FK 是非线性映射），**笛卡尔直线插值需要沿路径逐点做逆运动学（IK）**，
   这是二者的根本差别，也是"整体移动要贵得多"的原因。[S1][S7][S8]
3. 主流工业机器人把二者做成 **PTP（关节/`MOVJ`）· LIN（直线/`MOVL`）· CIRC（圆弧/`MOVC`）** 三种运动指令；
   `MOVJ` 最快、路径不可控，`MOVL` 路径可控但更慢、且靠近工作空间边缘/奇异点时关节速度会飙升。[S3][S19][S20][S21]
4. **限制与范围**主要有六类：关节限位（软/硬/机械）、**奇异点（腕/肩/肘）**、可达工作空间（外/内边界）、
   姿态限制、速度/加速度限制、坐标系（基/工具/用户）与 TCP 选择。[S9][S11][S12][S13][S24][S27]
5. **本项目现状（关键）**：关节模式**已完整实现**；笛卡尔"整体移动"**后端已有坐标系求解器与 IK**
   （`jog_frames.py` 支持 base/tool/user，`/control/jog/step|start` 已接受 `frame` 参数），
   但**前端点动界面从未接线**（只发 J1~J6）、**没有直线插补**、控制器常驻程序只有 `MJOINT`（关节 PTP）。
   → 结论：**"整体移动"在当前真实下发的意义上尚不可用；缺的是前端接线 + 逐点校验 + 直线插补的取舍**。
6. 推荐路线：**先**把已有直角点动接到前端（低成本、复用现有求解器），并**如实标注"整体移动是逐拍逼近，不是严格直线"**；
   **再**评估是否做 PC 端离散直线插补（把 TCP 直线采样成 N 段、每段 IK + 校验 + 逐段 `MJOINT`），
   并将其明确标注为"**离散近似直线（N 段）**"。**不做**"假直线"。

## 1. 两种手动模式：定义与官方对应

### 1.1 关节控制（关节坐标 / JOINT）

- **定义**：选一个关节轴（J1~J6），只让它绕自身轴旋转一个角度，其余轴不动。[S18][S35]
- **单位**：度（°）。
- **坐标系**：各关节**自身**的坐标系（"各处一个系"）。
- **直观说法**：**"只移到一个轴"。** 关节模式是机器人最"原生"的空间（关节角就是控制器的自由变量）。
- **适合**：大范围搬运、脱离奇异点、机械对位与排障。[S14][S17][S18]

### 1.2 机器人整体控制（基坐标 / WORLD / "机器人坐标系"，以及工具、用户坐标系）

- **定义**：把末端（TCP）当作一个整体，按**笛卡尔方向**移动/转动——沿 `X/Y/Z` 平移、绕 `A/B/C` 旋转，
  六个关节**一起联动**以保持末端沿指定方向走。[S14][S17][S34][S38]
- **单位**：平移 `X/Y/Z` 为 **mm**，旋转 `A/B/C` 为 **°**（**单位是按轴决定的，不是按坐标系**）。
- **官方叫法**：埃夫特/多数厂商叫「**机器人坐标系**」；ABB 叫 `World`/`Base`；FANUC 叫 `WORLD`（另含 `USER`、`TOOL`）。[S14][S18]
- **直观说法**：**"机器人整个移动"**——末端走直线、整臂跟着摆。
- **适合**：贴着工具轴进给、沿工件方向取放、需要"路径可控"的接近/退出动作。[S14][S17]

### 1.3 必须与"运行模式档位"区分（不要混为一谈）

用户口中的"两种控制方式"是 **运动坐标系** 层；它**不同于**运行模式旋钮层：

| 层 | 名称 | 决定什么 | 例 |
|---|---|---|---|
| L1 运行模式 | `T1` / `T2` / `AUTO` / `REMOTE` | **谁在控制**机器人（示教器 or 控制器跑程序） | AUTO 档下上位机点动被忽略 |
| L2 运动坐标系 | `关节` / `机器人` / `工具` / `用户` | **往哪个方向走**、步长单位 | 按 `1+` 在关节系转 J1，在机器系沿 X 平移 |

→ 本项目 **L1 已有实现**（`services/runmode.py`，见 §5.4），**L2 后端已有、前端未接线**。

## 2. 运动空间、轨迹与插补

### 2.1 关节空间 vs 笛卡尔空间（本质对照）

| 维度 | 关节空间（Joint Space） | 笛卡尔空间（Cartesian / Task Space） |
|---|---|---|
| 描述量 | 6 个关节角 (θ1..θ6) | 末端位姿 (x,y,z,rx,ry,rz) |
| 插值对象 | 直接对关节角线性过渡 | 对末端位姿插值（位置线性 + 姿态 SLERP） |
| 末端路径 | **不可控，通常是弧线** | **可控，可设计成直线/圆弧** |
| 计算量 | 低（不需要 IK） | **高（每一步都要 IK）** | 
| 直观性 | 差（末端路径难预测） | 好（可精确设计路径） |
| 速度 | 通常更快（可各轴同时满速） | 靠近边界/奇异点时更慢 |
| 来源 | [S1][S2][S4][S5] | [S1][S4][S7] |

一句话：**"在哪插值，末端就走什么形状的轨迹"。**

### 2.2 三种标准插补（工业机器人通用三件套）

| 运动类型 | 常见指令 | 插值空间 | 末端路径 | 何时用 |
|---|---|---|---|---|
| 点到点 | `MOVJ` / `MoveJ` / PTP | **关节空间** | 弧线（不可控） | 大范围快速搬运；精确路径不重要时 |
| 直线 | `MOVL` / `MoveL` / LIN | **笛卡尔空间** | **直线**（控制器沿途连续解 IK） | 接近工件、插销、涂胶、焊缝 |
| 圆弧 | `MOVC` / `MoveC` / CIRC | **笛卡尔空间** | 圆弧（经中间点） | 圆弧轮廓、绕行 |

来源：[S3][S20][S21]（`MOVJ`/`MOVL`/`MOVC`）；[S19][S20]（`MOVL` 由控制器连续解 IK 以维持直线）。

### 2.3 为什么"关节插值 TCP 走曲线" / "直线插值必须沿途连续 IK"

- **关节插值走曲线**：关节角做线性过渡，经**正运动学（FK）**映射到末端时，由于三角函数/连杆几何的
  **非线性**，末端位置不是直线，而是一条弧线（甚至可能出现较大绕行）。[S1][S5][S8]
  Flexiv 官方文档直接写明：按关节运动到目标位姿，"typically in a curved line, by calculating inverse kinematics"。[S8]
- **直线插值必须连续 IK**：要让 TCP 走直线，必须在**每个时间步**先取该步的笛卡尔目标位姿，
  再**逆解（IK）**成关节角交给控制器；上一步的解是下一步很好的初值，因此 IK 可以**增量式**求解。[S7][S19]
  这带来两个直接后果：**① 靠近奇异点/工作空间边缘时，微小直线位移可能对应巨大的关节角速度**；
  **② 直线运动通常比关节运动慢**。[S19][S21]

### 2.4 正/逆运动学、DH 参数与多解选解

- **FK（正运动学）**：关节角 → 末端位姿，唯一确定、有闭式解（本项目 `kinematics.forward_kinematics`）。[S31][S32]
- **DH 参数（Denavit-Hartenberg）**：用 4 个参数（`d/a/alpha/theta`）逐连杆描述相邻坐标系的变换
  `A_i = Rz(θi)·Tz(di)·Tx(ai)·Rx(αi)`——这正是本项目采用的约定（`config/robot.yaml` 顶部注释）。[S31][S32][S40]
- **IK（逆运动学）**：末端位姿 → 关节角。特点是**非线性、多解、可能无解**。[S22][S23]
  - **多解**：常见"**肘上/肘下**（elbow up / elbow down）"两组，以及绕基座/腕部的其它分支。[S22][S23]
  - **选解原则**：一般取**离当前关节角最近**的解（最小运动量、构型连续），
    否则机械臂会"突然翻肩/翻肘"；也可固定某分支或取限位余量最大的解。[S22]
  - **无解**：目标超出可达空间或接近奇异 → 必须**拒绝**，不能"尽力而为"。

## 3. 限制与范围（全方位）

### 3.1 关节限位（软限位 / 硬限位 / 机械限位）

| 类型 | 含义 | 触发者 |
|---|---|---|
| **软限位**（software limit） | 软件设定、通常比硬限位内缩几度（如内缩 5°） | 控制器/上位机 |
| **硬限位**（hard limit） | 控制器固件级急停 | 控制器固件 |
| **机械限位/止挡**（mechanical stopper） | 物理挡块，最后的机械保护 | 机械结构 |

来源：[S28]（软限位可预先拦住、无停止距离）、[S29]（出厂即设软件限位 + 机械止挡）、
[S30]（软限位应比硬限位内缩约 5°）。**软限位必须比硬限位更保守**，这是通行工程口径。

### 3.2 奇异点（笛卡尔运动必须处理）

| 奇异类型 | 成因 | 后果 |
|---|---|---|
| **腕部奇异** | J5 ≈ 0°，J4 与 J6 轴共线 | 绕工具 Z 失去一个自由度；可能需要 J4/J6 反向高速旋转 |
| **肩部奇异** | 腕心与 J1 轴线共线 | J1 方向失去意义 |
| **肘部奇异** | J2/J3 与腕部轴共线（手臂完全伸直） | 直线轨迹规划失效 |

来源：[S9][S10][S11]；UR 还区分"**外工作空间/内工作空间/腕对齐**"三类并给出规避建议[S12]；
学术上分为"**边界奇异**（伸到最远/最近）"与"**内部奇异**（轴对齐）"[S13]。
**通行处置：接近奇异时切换回关节坐标系，用单轴微动挪开。**[S9][S10][S11][S35]

### 3.3 可达工作空间（reachable / dexterous workspace）

- **可达工作空间**：末端能够到达的位置集合（对 ER8-700H 近似一个半径 `reach_mm=712 mm` 的球域）。
- **边界 = 奇异**：伸到最远/最近时出现边界奇异，关节速度趋于无穷。[S12][S13]
- 判断可达的工程做法：算目标点到基座的距离，与最大/最小可达半径比较。

### 3.4 姿态/朝向限制

- 末端不仅要到位置，还要到姿态；姿态约束会让可达性变窄（位置可达但姿态不可达 = 仍求解失败）。
- **工具坐标系（TCP）**：工具原点相对法兰的偏移（本项目当前**只有位置、没有姿态**，见 §5）。
  工具姿态不标定时，工具坐标系的姿态与法兰相同。[S27]

### 3.5 速度/加速度限制

| 层面 | 口径 | 来源 |
|---|---|---|
| 关节速度 | 各轴角速度上限（°/s） | 通用 |
| **TCP 笛卡尔速度** | 末端线速度上限（mm/s）；协作安全典型 **250 mm/s**（ISO/TS 15066） | [S24][S25] |
| 加速度/加加速度 | 影响启停冲击与振动 | [S27] |
| 控制器实现 | 例：UR 的 `SF6 速度限值 TCP 和肘部`；KUKA 的 `$SIB_TCP_LIMIT` / `$SIB_JOINT_LIMIT` | [S25][S26] |
| 示教器设置 | 可分别设置各关节最大速度/加速度/限位，以及末端 TCP 速度上限、奇异规避 | [S27] |

★ **关键**：**"TCP 速度"与"关节速度"是两个不同的约束**——直线运动靠近奇异时，为维持很小的 TCP 速度，
某些关节角速度可能已经超限（这正是 §2.3 的后果）。所以直角点动**必须**把"关节角速度"也一起夹住。[S26]

### 3.6 坐标系（基/工具/用户）与 TCP

| 坐标系 | 原点/轴向 | 移动含义 |
|---|---|---|
| 关节 | 各关节自身 | 各轴独立转动 |
| **机器人 / 基坐标（WORLD/Base）** | 底座中心；Z 竖直向上；X 由底座朝向确定 | 沿基座 X/Y/Z 平移、绕 A/B/C 转 |
| **工具（TOOL）** | 当前激活的工具 TCP | 沿**工具自身**轴进给（贴工具方向） |
| **用户（USER/wobj）** | 用户自定义（一般取在工件上） | 沿**工件坐标系**移动 |

来源：[S14][S17][S18]；埃夫特官方：坐标系切换顺序 **关节 → 机器人 → 工具 → 用户**，切换结果在状态栏显示[S34][S37]。

## 4. 主流示教器在手动模式下的坐标切换（工程对照）

| 厂商 | 手动坐标选项 | "关节"对应 | "整体"对应 | 来源 |
|---|---|---|---|---|
| **ABB (IRC5/FlexPendant)** | World / Base / Tool / **Joint** | Joint（各轴旋转） | World/Base（X/Y/Z 平移，COORD JOG LINEAR） | [S14] |

| **FANUC CRX（协作）** | Cartesian（X/Y/Z + 姿态）/ Joint | Joint jog | Cartesian jog（三轴三向 + 绕轴姿态） | [S15] |
| **埃夫特 (EFORT)** | **关节 / 机器人 / 工具 / 用户** | 关节运动（`4+` 转 J4 等） | 笛卡尔运动：切到"机器人"参考系后整体移动 | [S34][S35][S36][S37] |

**共性**：几乎所有示教器都把"**单轴（关节）**"与"**整体（笛卡尔）**"作为两个可切换的手动档，
并在**状态栏显示当前坐标系**；切换坐标系会**同时切换轴按钮的含义与步长单位**。[S14][S15][S17][S18]

## 6. 方案：在本项目怎么落地

### 6.1 两种模式的定义（本项目口径）

| 模式 | 定义 | 输入 | 求解 | 下发 |
|---|---|---|---|---|
| **关节模式（JOINT）** | 只动一个/多个关节角 | 关节角增量或目标关节角 | 直接加减 + 限位夹紧 | 关节目标 → `MJOINT`（**PTP，TCP 走弧线**） |
| **整体模式（机器人/工具/用户）** | TCP 沿笛卡尔方向移动/转动 | 沿某轴的方向 + 步长（mm/°）或目标位姿 | 每步/每拍 **IK** → 关节角 | 关节目标 → `MJOINT`（**逐拍逼近；非严格直线**） |

**必须如实标注**：本项目的"整体移动"是**在笛卡尔空间定义方向、经 IK 落到关节**，
但**真实下发通道是关节 PTP**——所以**中间路径不保证是直线**。这一点与真机示教器的
`MOVL`（控制器级直线插补）**不同**，界面**不许让用户以为"整体移动 = 走直线"**。

### 6.2 轨迹与插补：该走关节插补还是笛卡尔直线插补？

| 选项 | 做法 | 优点 | 代价/风险 | 建议 |
|---|---|---|---|---|
| **A. 关节插补（PTP）** | 直接下发目标关节角（现状） | 简单、最快、复用现有一切 | TCP 走弧线；对"路径可控"场景不适用 | **整体到点的默认方式**，UI 明确标注"不保证直线" |
| **B. 逐拍笛卡尔点动**（后端已有） | 每拍沿笛卡尔方向走一小步 → IK → 下发 | 手动微调整体移动手感接近示教器 | 只保证"小步到位"，不保证整段直线；沿途无碰撞校验 | **先落地（接前端）**，标注"逐拍逼近" |
| **C. 笛卡尔直线插补（LIN）** | 把 TCP 直线**采样成 N 段**，每段 IK → 限位/奇异/围栏校验 → **逐段 `MJOINT`** | 路径**近似可控**（N 足够密时接近直线） | 占执行通道、节拍随 N 线性增长、误差/抖动、并非控制器级真直线 | **第二阶段可选**，且**只用于短距离**；UI 标注"**离散近似直线（N 段）**" |
| **D. 圆弧插补（CIRC）** | 同上，路径为圆弧 | 圆弧轮廓 | 更复杂，收益低 | **不做**（本期） |

**推荐**：**A 为默认 + B 先落地 + C 作为可选第二阶段（明确标注离散近似）+ D 不做。**
理由：本项目控制器**只暴露 `MJOINT`**（`programs/210_service_merged.pgm:59`），
PC 端**无法让控制器做真 LIN**；做真直线只能靠 PC 端离散成密集关节目标，
本质仍是**一串 PTP**，只是把步长做小——**收益（路径可控）与代价（节拍/抖动）必须让用户知情后再定**。

### 6.3 限制与范围（全方位实施建议）

| 限制项 | 现状 | 建议（具体到文件/函数） |
|---|---|---|
| 关节软限位 | 已有 | 复用 `limits.in_limits/clamp`；**直角求解结果也必须过同一判据**（`jog_frames.solve_delta` 出口统一 `limits.in_limits`） |
| 关节硬/机械限位 | PC 不可见 | **不改**（控制器/机械负责）；UI 标注"软限位=配置值，硬限位以控制器为准" |
| 奇异检测 | 仅启发式 | 增加**雅可比条件数/可操作度**阈值（`kinematics.jacobian_space` 已就绪，算 `‖J‖·‖J⁻¹‖` 或 `sqrt(det(J·Jᵀ))`），并在直角点动**每一步**检查 |
| 可达性 | 粗判 | 目标点半径与 `reach_mm` 比较（外边界），并加最小半径（内边界）判断；IK 不收敛 = 不可达，已拒绝 |
| 姿态限制 | 无 | 工具姿态未启用前，"整体旋转"不承诺工具姿态；启用 `tool.rpy`（`jog_frames.tool_matrix` `85`~`97`）后再说 |
| 速度（关节） | 已有夹紧 | 复用 `plan_tick` 的 `scale`；对增量/直线插补也逐段夹紧 |
| 速度（TCP 笛卡尔） | 常量 50 mm/s | 在 `config/robot.yaml → motion.jog` **新增** `max_speed_mmps` / `max_speed_rot_dps`（`jog.py:97/:105` 已读这两个键，只差配置） |
| 加速度 | 无 | **不做**（由控制器内部速度规划负责）；UI 不承诺加加速度 |
| 单步步长 | 关节 `[0.1,1,5,10]°` | 直角系步长按轴给（mm / °），复用 `amount` 字段；配置化直角步长档位 |

### 6.4 安全护栏建议

**沿用（不得削弱）**：

- 残影预演（下发判据，非仅视觉）：`three/manager.js:333` `evalSafety()` + `three/ghost.js:146` `withTarget()`；
- 安全围栏互锁：`services/safety_guard.py:93` `check()`；
- 未就绪闸门：`motion.servo_not_ready_reason()`（`motion.py:85`）；
- 18 原位禁止旋转：`api/sorting.py:521` `_rotation_guard()`；
- 速度跟随滑块（唯一口径）：`control.py:2278` `_jog_speed_pct()`；
- 轴锁、急停、看门狗：`jog.py:162` `_block_reason()` / `jog` 主循环。

**新增（针对整体模式）**：

1. **每步 IK 校验**：直角点动/直线插补的**每一步**都要过
   `limits.in_limits` + 奇异阈值 + 可达性；任一不过 → **拒绝该步**（不"尽力而为"）。
2. **奇异点拒绝 + 引导**：命中腕/肩/肘奇异（升级后的可操作度判据）时，**拒绝并提示"切回关节模式"**（对齐官方做法[S9][S10]）。
3. **越界拒绝**：目标超出关节软限位或可达半径 → 拒绝并说明原因（不要静默夹紧后继续，夹紧只在关节系允许）。
4. **直线插补沿途逐段校验**（若做 C）：每一段都做"限位 + 奇异 + 围栏"三查，
   任一段不过 → **整段不下发**并报告第几段失败。
5. **速度如实回报**：把 `scale`（实际限速比例）回传前端显示（`plan_tick` 已有 `scale`，前端显示"已限速 X%"）。

### 6.8 回归钉建议

**前端（新增 `tools/verify_frames.mjs`，挂进 `npm run verify`）**

1. `unitOfAxis(frame, axis)`：关节系全 `deg`；直角系 1~3→`mm`、4~6→`deg`；

5. 奇异分级边界值逐个钉死（含恰好等于阈值的临界点）。

### 6.9 风险（尤其真机安全）

| 风险 | 说明 | 缓解 |
|---|---|---|
| **方向写反** | 左乘/右乘、基座 yaw 符号、`axis_sign` → "能动但方向错" | 先真机核对方向再做 UI（§6.7 P1 后核对） |
| **奇异附近关节飞车** | 微小直线位移 → 巨大关节角速度 | 逐点可操作度阈值 + 关节角速度夹紧（已有 `scale`） |
| **"以为走直线"** | 关节 PTP 实际走弧线，撞到工装 | **如实标注**，禁用"直线"字样除非做离散直线且标注近似 |
| **沿路径碰撞** | 现在只校验起/终点 | 做 C（直线插补）时**逐段**校验；否则只承诺"终点安全" |
| **占执行通道** | 直线插补多段下发会长时间占用执行锁 | 限制段数/距离；期间拒绝手动吸放（后端已有 `_reject_if_run_active`） |
| **真机安全总则** | 绝不在分拣运行中做打断性操作 | 遵守 `AGENTS.md` §5.1：先查 `/api/sorting/state` 的 `running` |

3. **是否需要工具坐标系与用户坐标系**，还是只用"关节 + 机器人"两种？（决定工作量，可省约 1/3）
4. **基座 X 轴方向**：现场能否在真机上按一次 `1+` 看它往哪走，以标定 `frames.base.x_axis_yaw_deg`？
5. **速度上限**：整体移动的 TCP 速度上限取多少？（官方 T1 参考 ≤50 mm/s[S27][S34]）
