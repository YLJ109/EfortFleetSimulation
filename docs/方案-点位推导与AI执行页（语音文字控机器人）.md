# 第一部分 · 点位推导：给哪些点，能推出哪些点

## 1. 推导原理

3×3 槽位是**等距、共面、同姿态**的规则网格，所以直角坐标空间里是**线性**的：

```
P(r,c) = P00 + (c−1)·ex + (r−1)·ey          ← 位置可精确算
P上(r,c) = P(r,c) + up                       ← "正上方" = 平移一个实测向量
ex = P(行1,列2) − P(行1,列1)                  ← 列间距向量（实测）
ey = P(行2,列1) − P(行1,列1)                  ← 行间距向量（实测）
up = P(A1上) − P(A1)                          ← 上方偏移（实测，不假设"垂直向上"）
```

算出直角坐标后，每个点再用 **IK 反解**成关节角（含限位/奇异校验）。

## 2. 推导表（★ 你要的答案）

| 你示教这些 | 我能推出 | 数量 | 前提 |
|---|---|---|---|
| `A1`、`A2`、`A4` | A 区 **A3/A5/A6/A7/A8/A9** | 6 | 等距、共面、姿态一致 |
| `A1`、`A1上` | A 区 **A2上…A9上** | 8 | 同一个"上"偏移向量 |
| **上面 4 个** | **A 区全部 18 个** | **18** | — |
| `B1`、`B2`、`B4`、`B1上` | **B 区全部 18 个** | **18** | 同上 |
| `C检测`、`开始/结束点` | **推不出来**（不在网格里） | — | **必须人工示教** |
| **合计最少示教 4+4+1+1 = 10 个** | **推出全部 38 个** | **38** | — |

**反向（全给了之后还能算什么）**：

| 输入 | 能算出 |
|---|---|
| 全部 9 个 A 槽位 | 行距/列距的**一致性**、每个点相对理想网格的**偏差 mm**、**离群点**（示教偏了的那个）→ 点位质检 |
| 全部 9 个"上"点 | 上方偏移的一致性 → 发现"某个上点高度没示教好" |
| 18 个槽位（A+B） | **平面高度 planeZ**（中位数）、**不重叠判定**（中心距 vs 方块尺寸）→ 3D 摆位 |
| 任意 3 个不共线槽位 | 该区整片网格（若原 3 个点丢了，换 3 个也能重建） |

**我推荐的实际用法**：**先按 38 个点完整示教**（最稳，也是第一条基准线）；
推算作为**备用**——某点被撞偏、换工装、或临时补点时才用。
**推算值我不会直接写进点位库**，而是出预览（带 IK 误差/限位/奇异警告）→ 你逐点「到点」复核 → 确认才存。

# 第二部分 · AI 执行页方案

## 3. 架构（★ 关键：大模型**不碰**控制通道）

```
语音/文字
  ├─ 语音：复用已做好的腾讯云 ASR → 实时字幕（已可用）
  └─ 文字：输入框
        ↓ 原文
  ┌─────────────────────────────┐
  │ 语义解析（两级，可降级）        │
  │  A. 规则解析（正则/关键词）     │ ← 默认就够用：第X行第Y列 / 红列 / 取 / 放 / 开始 / 停
  │  B. 大模型解析（可选增强）      │ ← 只在 A 解析不出时调用，输出**受限 JSON**
  └─────────────────────────────┘
        ↓ 结构化意图 JSON（白名单动作）
  ┌─────────────────────────────┐
  │ 后端校验（安全闸，缺一不可）    │
  │  白名单动作 / 点位存在 / 限位   │
  │  / 围栏互锁 / 轴锁 / 速度夹取   │
  │  / 件数上限 / 运行中互锁        │
  └─────────────────────────────┘
        ↓
  ★ 回显「执行计划」给人看 → **点确认才执行**
        ↓
  既有执行通道：motion.command(写目标+40135触发位 → 常驻210)
               rc_vacuum(吸/停止吸/放/停止放)
               sorting runner(分拣)
```

**为什么解析要两级**：大模型有不确定性、要联网要 key、还会"编"不存在的点。
规则解析能覆盖 90% 的现场指令（行列、颜色列、取放、启停），**没 key 也能用**；
大模型只在规则解析不出时才上，且只作为"把话翻译成 JSON"的一环，**绝不直接生成寄存器值/代码**。

## 4. 支持的意图（白名单，五种，不做更多）

| # | 意图 | 例句 | 落地动作 |
|---|---|---|---|
| 1 | **看颜色** | "A区第一行第一列是什么颜色" | ⚠️ 见 §6 问题 1：需先去取来送 C 区判色 |
| 2 | **搬运单件** | "把 A区第一行第一列放到 B区第一行第一列" | 取 A1 → C 判色 → 按**指定**槽位或**按色**放 |
| 3 | **批量搬运** | "B区全部矩形随机摆放回 A区" | 逐件循环（上限保护） |
| 4 | **分拣流程** | "开始分拣" / "停止" / "暂停" / "继续" | 走既有 sorting / run-cancel / run-pause |
| 5 | **急停/复位** | "急停" / "停一下" / "复位急停" | 急停通道（最高优先级，不需确认）|

**明确不做**：不解释"快一点/慢一点"（速度只认右上角那一份，模糊词直接拒绝并说明）、
不做轨迹规划/避障、不做多机器人、不接任意脚本。

## 5. 中文表达归一化（现场怎么说话 → 结构化）

| 说的话 | 解析成 |
|---|---|
| A区第**1**行第**1**列 / A区左上 / A一 | 槽位 `A1` |
| A区第2行第3列 | `A6`（行优先：第2行第3列 = (2−1)×3+3 = 6）|
| B区**红**列第2个 | `B5`（红列 = B1/B4/B7 → 第2个 = B5）|
| B区第1列 | 按色列语义 → 红列 |
| 正上方 / 上面那点 | `A1上` |
| 放到**红**列 | 目标 = 该列**第一个空位**（占位表判定）|
| 放到 B区第1行第1列 | 目标 = 明确槽位 `B1` |
| 全部 / 所有 / 都 | 批量（触发上限保护 + 二次确认）|
| 随机摆放 | ⚠️ 见 §6 问题 3：需定义"随机"的含义 |

## 6. ★★ 必须如实说明的问题（先行列出，避免做完才发现）

| # | 问题 | 影响 | 建议 |
|---|---|---|---|
| **1** | **相机只对着 C 区，照不到 A 区** | 「A区第一行第一列是什么颜色」**无法直接回答** —— 颜色只有把件送到 C 区才看得到 | 两个选择：**(a)** 该指令解释为"去取来看"（**是运动**，要确认；看完可放回原格）；**(b)** 给 A 区加相机/视野标定（另一件事）。**这条要你定** |
| **2** | 大模型会"编" | 可能解析出不存在的点位/动作 | 只信**受限 JSON schema** + 后端白名单；解析出的点名不在 38 点内 → 直接拒绝并回显"我没听懂/这个点不存在" |
| **3** | "随机摆放"有歧义 | 是**随机顺序**取，还是**随机位置**放？ | 我按**随机顺序**（原地取、按色/按序放）实现；如果你要"随机放到 B 的任意空格"，**说一声** |
| **4** | 语音误识 | ASR 把"第1行"听成"第7行" → 取错件 | **回显执行计划 + 二次确认**是硬要求，不是可选项；界面同时显示识别到的原话 |
| **5** | 批量指令风险 | "全部搬回 A 区" = 9 次搬运，中途出错 | 上限 N 件（默认 3，可配）；超过必须**明确说"确认执行 N 件"**；异常仍走"停止 + 回起点" |
| **6** | 谁在动 | 分拣在跑时又来一条 AI 指令 | 沿用既有互锁：运行中**拒绝**新指令并提示（一次只跑一件事） |
| **7** | 权限 | AI 页不能成为绕过控制令牌的后门 | 与其它页一致：**必须持控制令牌**；急停同样要令牌（既有口径） |
| **8** | 审计 | "谁让它动的"必须可查 | 每条 AI 指令把**原话文本 + 解析出的 JSON + 执行结果**一起落事件表 |
| **9** | 大模型从哪来 | 需要 provider + key；离线/断网就不可用 | **规则解析兜底**（无 key 也能用）；大模型作为可选增强，key 放 `.env`（同 ASR 的做法，密钥不出后端） |
| **10** | 延迟 | 语音 → 解析 → 确认 → 执行，比手点慢 | 明确的**单件、明确坐标**指令允许"免确认直接执行"（可配开关）；批量/模糊指令强制确认 |

## 7. 页面设计（AI 执行页）

```
┌── 左：3D 视口（复用 MonitorLayout，能看到机器人和 3D 方块/残影）──┬── 右：AI 面板 ──┐
│                                                              │ ① 就绪（复用底栏/就绪卡）│
│                                                              │ ② 输入区              │
│                                                              │   [🎤 语音] [文字输入] │
│                                                              │   识别原话：A区第一行… │
│                                                              │ ③ 解析结果（可编辑）   │
│                                                              │   动作：搬运            │
│                                                              │   取：A1 放：B1(红列第1)│
│                                                              │   速度：右上角 5%       │
│                                                              │   [确认执行] [取消]     │
│                                                              │ ④ 执行进度/日志（复用）│
│                                                              │ ⑤ 常用指令快捷键（可选）│
└──────────────────────────────────────────────────────────────┴─────────────────────┘
```

- 语音直接复用**已做好的腾讯云 ASR**（底栏麦克风），识别文本落到输入框
- 解析结果**必须可编辑**（听错/解析错时人工改一个字再执行）
- 默认先**空跑**（dry_run）验证解析与路径，再真机

## 8. 接口（草案）

| 方法 | 路径 | 说明 |
|---|---|---|
| `POST` | `/api/ai/parse` | 原文 → 结构化意图（**只解析、不执行**；返回 `{intent, plan[], warnings[]}`）|
| `POST` | `/api/ai/exec` | 确认后执行（`plan_id`，或用同一次返回值防止"确认的和解析的不是同一条"）|
| `GET` | `/api/ai/config` | 是否启用大模型、provider、是否需确认、批量上限（**不回传 key**）|

`/api/ai/parse` 与 `/api/ai/exec` 之间用 `plan_id` 绑定 —— 防止"界面显示的"和"真正执行的"不是同一份计划。

## 9. 实施顺序（分两期，先可用的）

**第一期（不依赖大模型，规则解析 + 全链路安全闸）**
1. 中英文表达归一化（行列/列色/正上方/全部）
2. `/api/ai/parse`（规则）+ `/api/ai/exec`（白名单 + 回显确认 + 上限 + 审计）
3. AI 执行页（输入 + 解析回显 + 确认 + 进度 + 语音复用 ASR）
4. 空跑 → 单件真机 → 批量

**第二期（可选，大模型增强）**
5. 大模型解析（仅在规则解析失败时调用）→ 输出同一套受限 JSON
6. `.env` 配 provider/key；无 key 自动退回纯规则

## 10. 验收

| # | 判据 |
|---|---|
| 1 | 「A区第1行第1列放到B区红列」→ 解析对、回显清楚、确认后按序执行 |
| 2 | 说错/解析不出 → **拒绝执行**并回显"我没听懂"，绝不猜 |
| 3 | 点位不存在 / 超出 38 点 → 拒绝 |
| 4 | 批量超上限 → 必须先明确确认 |
| 5 | "停止"能打断飞行中的动作；"急停"走急停通道 |
| 6 | 每条指令可审计（原话 + JSON + 结果）|
| 7 | 无大模型 key 时，规则解析仍能用 |
| 8 | 权限、围栏、轴锁、速度全部与手动页面一致（AI 不是后门）|
