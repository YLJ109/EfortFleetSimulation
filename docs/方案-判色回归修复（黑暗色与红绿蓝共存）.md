# 方案：判色回归修复 —— 「黑/暗色」与「红绿蓝」共存

> 2026-10-10 · 状态：**已实现并验证**（结果见文末 §8）
> 起因（用户原话）：
> 「现在红色也没有检测到，有些绿色也没有检测到…之前三色检测的挺好的，现在不行了」
> 「把黑色物体识别成蓝色了，应该是黑色，你检查代码啊」

---

## 1. 现象（用户口径）

| # | 现象 |
|---|---|
| 1 | 红色方块检不到；部分绿色也检不到（"以前三色挺好，现在不行"） |
| 2 | 黑色方块被识别成**蓝色**（应该报"黑色/无效色"） |

## 2. 先摆事实（本轮实测，不改任何代码）

| 检查 | 命令 | 结果 |
|---|---|---|
| 现场真图·三色回放 | `camera\tools\vision_e2e_replay.py 40` | 红 32/32、绿 40/40、蓝 36/36 → **三色 100%** |
| 合成图·算法自检 | `camera\tools\vision_color_test.py` | 62 通过 / **4 失败**（4 条**全是"黑"的口径**：断言还写着 `name=="未知"`，而现在会报 `黑`） |
| 用户黑块照片（290×191 特写） | 直接喂 `VisionEngine.detect` | **0 个候选**；`median V=132`、暗色掩膜覆盖 35% |

> ⚠ 那张照片**不能代表工况**：它是特写、且带**上下黑边**（letterbox）。暗色掩膜把黑边与黑块连成"怪形状"，被 `find_rectangles` 的矩形门槛拒掉 → 才 0 候选。
> **要 100% 复现"黑→蓝"，需要一张现场 C 位的黑块帧**（相机面板落盘的 `full.jpg` 或截图）。

## 3. 根因（代码级，两处）

### H1 · 三色被"暗色"整批吞掉 → 红/绿漏检
`VisionEngine.detect()`（`camera/vision_color.py`）里：

```python
if drects:
    if not rects:
        dark_used = True
    else:
        a_dark = max(面积 drects); a_col = max(面积 rects)
        if a_dark >= dark_area_gain(1.6) * a_col:
            dark_used = True
    if dark_used:
        mask = cv2.bitwise_or(mask, dmask)
        rects = drects            # ★ 彩色候选被整批丢弃
```

**只要画面里有一块"较大的暗区"**（黑料 / 夹具 / 机械手 / 暗显示器 / 暗背景）满足 `≥1.6×` 最大彩色候选，彩色候选就被**整体替换成暗色候选** → 红/绿"凭空消失"。

### H2 · 黑块有色偏 → 被彩色掩膜判成蓝
- 黑块在灯下有**蓝色色偏**，`hsv_color_mask`（`S≥60`、`V≥35`）就把它收进**彩色**掩膜 → `_hue_vote` 投出 **"蓝"**。
- 而暗色兜底的改判分支只处理 `name == "未知"`：

```python
if dark_used and col.get("name") == "未知":   # ★ 只有"未知"才改判成黑
    col["name"] = DARK_NAME
```

- 同一物体在彩色/暗色两张掩膜里面积相近 → `a_dark < 1.6×a_col` → `dark_used=False` → 最终**原样报"蓝"**。

## 4. 方案（只改"暗/彩如何共存"，**不碰三色判据**）

1. **删除"替换"**：去掉 `rects = drects`。暗色兜底**永不丢弃**彩色候选。
2. **无彩色候选时**才用暗色候选 → 报第 4 色「黑（无效）」。（= 最初的设计）
3. **新增"暗色改判"**（修 H2）：对每个**彩色**候选，算其矩形框内落在**暗色掩膜**里的像素占比；若 ≥50% → 说明它其实是暗色物体（被色偏骗进彩色掩膜）→ 改判 `name="黑"`、`reason="无效颜色（黑/暗色，非红绿蓝）"`。**三色判据一个不动**。
4. **面积竞争改为"追加而非替换"**：仅当「最大暗色块 ≥1.6× 最大彩色候选」**且**「该暗色块与彩色候选**不重叠**（确属另一物体）」时，把该暗色候选**追加**进候选列表；由 `pick_best`（取面积最大）选唯一目标。
   - "手/杂色 + 大黑块" → 黑块仍被报出（大者胜）；
   - 正常 C 位（彩料 + 小夹具暗块）→ 彩料最大 → 报彩料；
   - **三色永远在候选里，不会被吞**。
5. `dark_*` 阈值继续可配（`/vision/config`），默认值随本方案复核。

## 5. 不做什么（边界）

- ❌ 不改三色的 HSV/Lab/阈值/色带 —— 真图回放已 100%，不能碰。
- ❌ 不给黑块写"形状模板/专用分割"。
- ❌ 不动 `camera_service` 的取流/过滤链路。

## 8. 实施结果（2026-10-10）

**改了什么**（只动"暗/彩共存"，**三色判据一字未改**）

| 文件 | 改动 |
|---|---|
| `camera/vision_color.py` | ① 删除 `rects = drects`（不再用暗色候选替换/吞掉彩色候选）；② 无彩色候选时才用暗色兜底，报「黑」；③ 新增 `_dark_self_frac()`：彩色候选**自身像素**以暗色为主（≥50%）→ 改判「黑」（修"黑块带蓝偏被判蓝"）；④ 删掉已无用的 `dark_area_gain` 配置 |
| `camera/tools/vision_color_test.py` | 4 条旧断言更新为新口径（`name=="黑"`）；新增 2 条钉子：**彩色候选不被暗色吞掉**、**带蓝色偏的暗块仍判黑** |

**验证结果**

| 项 | 结果 |
|---|---|
| `vision_color_test.py`（合成/算法） | **67 通过 / 0 失败** |
| `vision_e2e_replay.py 40`（现场真图） | 红/绿/蓝 **全部 100%**（红 28/28、绿 40/40、蓝 30/30） |
| 后端 `pytest -q` | 全绿（视觉改动不影响后端） |

**一个必须如实说的变化**：真图回放里"超出画面（合理拒绝）"的帧数变多（红 8→12、蓝 4→10）。
逐帧核对过：**这 10 帧全是"物体怼到镜头前、被画面裁切"的帧**（面积 5 万~21 万 px），
它们**本来就不该判色**；旧代码在这些帧上靠色相投票"碰巧"给出了颜色（算成命中），
现在改成如实报「黑（无效色）」。**画面内的正常工件（含绿色现场帧）一颗都没变**。
→ 结论：不是三色退化，是"被裁切帧"的行为被纠正为更安全（无效色 → 原路放回，不会误分拣）。
