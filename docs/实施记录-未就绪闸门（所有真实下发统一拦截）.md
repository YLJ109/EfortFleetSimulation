# 实施记录 · 统一「未就绪」闸门（所有真实下发一律拦截）

> 用户原话：「**如果没有上电，执行点到点，移到什么的全部提醒机器人没有就绪，所有的。**」
> 本文写清：覆盖面清单 / 判定字段 / 豁免项 / 统一文案 / 风险 / 回归钉子 / 不做的。

`tictactoe.py` / `vision_rules.py`；前端 `rcReady.js` / `PointExecView.vue` /

## 1. 现状核对（改之前）

| 项 | 改前结论 |
|---|---|
| 「就绪/伺服上电」权威字段 | `/api/rc-status` 的 **`snap.bits.servo`**（位 3）；`snap.servo_on = servo and not alarm and not estop` 是给按钮用的合成字段；前端 `stores/rcReady.js` 的 **`servoOn`** 读的就是它 |
| `motion.command` 是否被就绪流程使用 | **否**。`services/rc_ready.py` 直接用 `mb.rc_command/rc_snapshot/write_reg`（伺服上电 `0x1001`、停机、清报警都走 `rc_command`），**不经过** `motion.command` → 闸门放哪都不会把就绪流程拦死 |
| 已有"未就绪"拦截的入口 | **0 个**（后端没有任何入口按伺服上电判拒）。前端只有"按钮禁用 + 一句话旁注"（`exec.readyGate` / `PointExecView` 锁提示 / `ProgramExecView` 就绪盒），**点了不给原因**、且各写各的措辞 |
| 真实下发入口清单 | `/control/move` · `/control/run-file` · `/control/jog/step` · `/control/jog/start` · `/control/vacuum` · `/sorting/start` · `/sorting/goto` · `/ai/exec` · `/tictactoe/start` · （后台）`vision_rules.execute_rule` |

结论：**没有一个入口拦"未就绪"**，且前端是"禁用+静默"，与用户要的"点了就提醒"不符。

## 2. 判定字段（唯一权威）

- 后端：`motion.servo_not_ready_reason()` → 读 `motion.modbus.rc_snapshot()` 的
  **`bits.servo`**（与 `/api/rc-status`、前端 `servoOn` **同源**）。`servo` 为 0 → 拒绝。
- **读不到状态也拒绝**（快照为 `None` 或抛异常）→ fail-safe，宁可拒绝不蒙。

## 3. 覆盖面清单（实现方式：一个共用前置校验 + 逐入口调用）

> 闸门函数只有一处：`motion.servo_not_ready_reason(dry=False)`；
> API 层的统一 raise 只有一处：`app/api/control.py::reject_if_not_ready(dry=False)`
> （拒绝用 **HTTP 409** —— 全局异常处理器把它转成 `{code:"HTTP_ERROR", message:<原因>}`，
> 前端各入口读 `message` 显示；**不用 403/401**，否则会误触发前端"去登录"分支）。

| 入口 | 是否已拦 | 空跑豁免 | 提示怎么给 |
|---|---|---|---|
| `POST /control/move`（点到点/移动/示教到位） | ✅ 409 | 无 dry（本就真实下发） | 前端 `exec.doTeach` 读 `d.message` |
| `POST /control/run-file`（程序/序列/文件） | ✅ 409 | ✅ `dry_run=true` 放行 | `exec.runFile` 解析 `message/detail` |
| `POST /control/jog/step`（增量点动） | ✅ 409 | 无 dry | `exec.stepJog` 读 `d.message` |
| `POST /control/jog/start`（连续点动） | ✅ 409 | 无 dry | `exec.startJog` 读 `d.message` |
| `POST /control/vacuum`（吸/停止吸/放/停止放） | ✅ 409 | 无 dry | `exec.vacuum` 解析 `message/detail` |
| `POST /sorting/start`（分拣，含 `dual_face`） | ✅ 409 | ✅ `dry_run=true` 放行 | `SortingView.errText` 读 `d.message` |
| `POST /sorting/goto`（到点/复核） | ✅ 409 | 无 dry | `SortingView.errText` 读 `d.message` |
| `POST /ai/exec`（AI 执行，运动/看颜色类） | ✅ 409 | ✅ `dry_run=true` 放行 | `stores/ai.js` 读 `message/detail` |
| `POST /tictactoe/start`（开局） | ✅ 409 | ✅ `dry_run=true` 放行 | `stores/tictactoe.js` `errMsg` 读 `message/detail` |
| （后台）`vision_rules.execute_rule` 自动执行 | ✅ blocked | 规则路径无 dry | 记进 `res.note`（与用户入口同一句文案） |
| `POST /ready` `/ready/cancel` `/control/clear-error` | ⛔ **不拦（豁免）** | — | 就绪/取消/清报警本身 |
| `POST /control/estop` `/estop/reset` `/jog/stop` `/jog/keepalive` `/run-cancel` | ⛔ **不拦（豁免）** | — | 停/急停必须永远可用 |

## 4. 豁免项（必须放行）

1. **空跑 `dry_run=true`**：不下发真实运动，是预演路径，拦了就没法预演。
2. **模拟模式（双闸未开 `real_write_enabled()=false`）**：`motion.command` 只播放仿真。
3. **强制模拟链路**（`connection.simulate=always` / 采集器已降级）：交给 `motion.command`
   的"模拟链路"分支给更准确的原因，闸门不抢答。
4. **就绪流程本身**（`/ready`、`/ready/cancel`、`/control/clear-error`）：闸门**不在**该路径里
   （`rc_ready.py` 不引用闸门函数）→ 结构上不可能死锁。
5. **急停/停止类**：不调用闸门函数。

## 5. 统一文案

- 后端（`motion.SERVO_NOT_READY_MSG`，唯一来源）：
  **`机器人没有就绪：伺服未上电，请先点「一键就绪」`**
- 读不到状态时（fail-safe）：
  `机器人没有就绪：读不到控制器伺服状态（<err>），请先点「一键就绪」`
- 前端各入口"未就绪旁注"（`rcReady.js::NOT_READY_HINT`，同一句开场白）：
  `机器人没有就绪：请先在「真机链路」点「一键就绪」`
  （前端旁注**不写死"伺服未上电"** —— 本页判据是完整就绪，写死会与实际不符。）

## 6. 为什么不把闸门塞进 `motion.command`

1. 点动（`jog._loop`）每 ~100ms 调一次 `command`，逐拍 `rc_snapshot`（3 次 FC3）会把点动
   链路拖慢近一倍；放**接口层**每请求只查一次。
2. `motion.command()` 是大量单测的纯逻辑出口（`test_audit_p0` 的假 modbus 没有 `rc_snapshot`），
   塞进去会整片打断。
3. 就绪流程**本就不走** `command`，无死锁风险；接口层收口更清晰、也便于逐条回归。

## 7. 风险与应对

| 风险 | 应对 |
|---|---|
| 逐拍读伺服状态拖慢点动 | 闸门放**接口层**（每请求一次），不进点动主循环 |
| 与"禁半截状态"互锁冲突 | 闸门只**读**快照、不持 `_exec_lock`、不写任何寄存器 |
| 前端"点了没反应"（按钮禁用） | 主路径（分拣/井字棋/AI 执行）按钮**可点**→后端 409→显示统一文案；点位/点动为"禁用+旁注"，旁注已统一为 `NOT_READY_HINT` |
| 前端把 `detail` 读成 `undefined` | 后端 409 → 异常处理器映射成 `message`，前端各入口读 `message/detail`（回归 `verify_not_ready.mjs` 断言） |
| 与既有"真实下发未开启"403 混淆 | 未就绪用 **409**（不触发前端"去登录"分支），403 仅留给"总闸未开" |

## 8. 回归钉子

- 后端 `tests/test_not_ready_gate.py`（22 条）：逐入口 409+统一文案（参数化 8 入口 + AI）；
  空跑/模拟放行；读不到状态按未就绪；就绪流程不被拦（行为 + 静态）；覆盖清单静态核对。
- 前端 `frontend/tools/verify_not_ready.mjs`（34 条，已并入 `npm run verify`）：
  后端唯一闸门/文案、各入口接入、就绪流程不引用、前端 `message` 解析与无 `undefined`。

## 9. 不做的（有意）

- **不改**下发时序、触发位语义、`_exec_lock`、`modbus.py` 寄存器、`rc_ready.py` 步骤顺序、
  `camera/*`、速度口径、`dual_face` 默认值。
- **不把**闸门塞进 `motion.command`（理由见 §6）。
- **不删**"真实下发未开启"的双闸检查（那是另一道闸，语义是"没开真机模式"）。
- 不把"未就绪"做成静默失败（一律给明确原因）。
