# 方案：速度统一（全部跟随右上角滑块 · 启动默认 10%）与底部状态区五选一

> 用户口径（2026-10-11，最高优先）：
> 「速度全部跟随右上角滑块，1:1，不做百分比反算；每次启动默认 10%、下限仍 5%；
>  任何下发路径都必须读滑块。底部真机链路跟机器人/摄像头/示教器一样样式，运行日志也放进去，
>  五个片五选一，点外部自隐藏，默认开运行日志，绿黄红点按真实状态亮。」

---

## A. 速度：全部跟随右上角滑块

### A.0 一句话结论（含真机安全显著标注）

| 项 | 现状 | 改后 |
|---|---|---|
| 默认速度 | 5% | **10%（★ 提速一倍）** |
| 速度下限 | 5% | **5%（不变；需要更慢仍可往下拖）** |
| 速度上限 | 100% | 100%（不变） |
| 滑块 → 下发 | 1:1（`40103 = UI`，由 `robot.yaml: service_program_vperc=100` 保证） | 不变 |

> ★★ **真机安全显著提示**：默认从 5% → 10% 是**提速一倍**。
> 依据 `有效速度 = 程序内 v100perc × 40103/100`，程序内已是 100%（`service_program_vperc: 100`），
> 所以 `40103 = UI%`，1:1 直通。启动默认值上调后，**未动滑块就下发时的实际速度翻倍**。
> 这是**用户明确要求**（"每次启动默认 10%"），且下限仍 5%、上限不变；
> **绝不改动** `config/robot.yaml` 的 `service_program_vperc`（保持 100）。

### A.1 做什么

1. **前端默认值**：`frontend/src/core/safetyConst.js` 新增 `SPEED_DEFAULT = 10`；
   `stores/exec.js` 的 `speed` 初值由 `SPEED_MIN`（5）改为 `SPEED_DEFAULT`（10）。
   下限仍 `SPEED_MIN = 5`，滑块 `min` 仍引用 `SPEED_MIN`。
2. **连续点动速度 BUG 修复**（唯一确凿未绑滑块的下发路径）：
   - 前端 `startJog` 已发 `speed_pct: this.speed`，但后端 `JogStartIn` **没有 `speed_pct` 字段**，
     Pydantic 静默丢弃 → 回退 `speed_dps=15` → **固定 50% 下发**。
   - 给 `JogStartIn` 增加 `speed_pct: Optional[int] = Field(default=None, ge=5, le=100)`（与 `JogStepIn` 对齐），
     使其走已有的 `_jog_speed_pct(body)`。**不改下发时序/互锁。**
   - 删除 `JogStepIn` 里**重复定义**的 `speed_pct` 两行。
   - `control.py` 连续点动日志文案如实化（不再对 `speed_dps` 折算的情形写成"全局速度"）。
3. **DB"点位序列"程序不得覆盖滑块**：`_steps_from` 里 DB/XPL item 自带的速度
   （默认 5）会经 `st.get("speed_pct") or body.speed_pct` **压过请求里的滑块值**。
   改为：**忽略 item 速度、一律用请求级 `speed_pct`**（见 A.2 理由）。
   `_point_steps` / `_norm_seq_items` 本就不带 item 速度，**不动**。
4. **文档同步**：`AGENTS.md §5.3` 的"反算 40103 = UI ÷ 0.5"改为如实口径
   （由 `robot.yaml: service_program_vperc` 决定；现场为 **100 → 1:1**）；
   并把"三套速度独立、默认 5%"的旧口径更新为"**全部跟随右上角滑块；启动默认 10%、下限 5%**"。

### A.2 关键技术选择：为什么"直接忽略 item 速度"

`_steps_from`（`control.py`）**拿不到请求级速度**（它只收 items + db）。两条路：

| 方案 | 做法 | 评价 |
|---|---|---|
| ① 请求级优先（item 只在请求没给时用） | 需把 `body.speed_pct` 一路传进 `_steps_from` | 改动面大；且 `RunFileIn.speed_pct` 有默认值 5，**永远"给了"** → 等价于方案② |
| ② **直接忽略 item 速度** | `_steps_from` 一律 `speed_pct=None`，由执行端 `st.get("speed_pct") or body.speed_pct` 回落到请求值 | **更简单、更可解释**；与既有 XPL 解析器的既定意图一致 |

**选②**。理由（写进代码注释）：
- 项目既有口径是"**滑块是唯一速度权威**"——`_parse_xpl_xml` 的 `_parse_target` 早就**刻意不写** `speed_pct`，
  正是为了"XML 自带的 v100perc 不会压掉前端档位"（见 `control.py::_parse_xpl_xml` 注释）。
  本改动把这条口径**推广到全部程序来源**（DB 点位序列 / 磁盘 JSON / XPL）。
- 磁盘 JSON 的 items 由 `_norm_seq_items` 产出，**本就不带** `speed_pct`；
  DB 程序 items 才可能带（历史遗留）。忽略它不会有功能损失。

> 备注：执行端 `sp = int(st.get("speed_pct") or body.speed_pct)` 保持"先取步骤、回落请求"的写法不变；
> 因为步骤侧现在恒为 `None`，所以**实际恒取请求值**。这样 `_point_steps`/`_norm_seq_items` 的行为**完全不受影响**。

### A.3 不做什么

- **不改** `motion.py` 下发时序/互锁、`modbus.py` 寄存器地址、`rc_ready.py` 就绪流程。
- **不改** `config/robot.yaml` 的 `service_program_vperc`（保持 100）、`dual_face` 默认值（仍 False）。
- **不改** `points.py`、DB 模型、`camera/*`。
- **不启服务、不跑真机脚本、不 git commit。**

## B. 底部状态区改版：五选一（含运行日志）

### B.1 结构与顺序

底部 `#bottom-zone` 里的状态区由**一个五选一 tab 条**承载，从左到右：

```
[运行日志] [机器人] [摄像头] [示教器] [真机链路]
```

- 前四个沿用**现有 `StatusStrip.vue` 的 `link-pill` 样式/主题/风格**（点 = `.lp-dot`，ok/warn/err/off 四档配色）。
- **真机链路**按**同样样式**做进来；其面板内容**原样保留** = 复用 `RcReadyCard`
  （双闸/档位/伺服/报警/急停/程序/点动 + 一键就绪·取消就绪·清除报错）。
- 原先 App.vue 里独立的「真机链路」切换按钮与其浮窗 `LinkPanel` 取消（内容迁入 tab 面板）
  —— **真机链路面板内容（`RcReadyCard`）一字未删**。

**实现承载**：扩展 `frontend/src/components/StatusStrip.vue`（组件名保持不变），
`tabs` computed = `[ log 片, ...link.pills(机器人/摄像头/示教器), link 片 ]`。
五选一位复用在 `stores/ui.js` 的 `statusPopover`（同一时刻只开一个）。

### B.2 交互

| 行为 | 规则 |
|---|---|
| 五选一 | 点某片 → 只显示该片对应面板（浮在底栏上方，沿用 `.link-pop`） |
| 再点同一片 | **收起**（toggle） |
| 点击外部 | 关闭当前面板。用 **document `mousedown` 捕获**判定"是否在 `#bottom-zone` 内"，**非阻塞**（不铺全屏遮罩，页面照常可点） |
| 默认 | 进入页面默认开「运行日志」（`ui.statusPopover` 初值 = `"log"`） |
| 运行中 | 有执行在跑时**自动开「运行日志」**，且**运行中不允许整体隐藏**（会被立刻重新打开 = "运行中一定可见"）；运行结束**不强行关** |

**自动开日志的判据（`anyRunning`）**：
`exec.running`（程序/点位/序列 — 前端）**或** `sorting3d.running`（后端 `/control/scene-state` 的 `running`，
= 分拣/AI/其它后端执行）。为此给 `stores/sorting3d.js` 增加 `running` 字段：
在 `tick()` 里写 `this.running = !!d.running`；分拣页自带轮询处（`SortingView.poll`）同步写一次。

> Esc 语义保护：`ui.statusPopover === "log"`（默认开、非用户主动开的被动面板）**不算"弹层"**，
> Esc 仍是**急停**；只有用户主动打开的其它四片才算弹层（Esc 先关面板）。
> 否则"默认开着日志"会把全局急停快捷键 Esc 永久吃掉。

### B.3 ★ 状态灯判据表（按真实字段，绝非常亮/编故事）

每个片自己的灯用**它自己那类状态**；颜色取自真实字段，取不到就是灰（不兜底成绿）。

| 片 | 灯色 | 判据 | 取自哪个真实字段 |
|---|---|---|---|
| **运行日志** | 绿 | 最新一条日志级别 = `ok`/`info` | `exec.log[last].level` |
| | 黄 | 最新一条 = `warn` | 同上 |
| | 红 | 最新一条 = `err`（有失败/异常） | 同上 |
| | 灰 | 无日志 | `exec.log.length === 0` |
| **机器人** | 绿/黄/红/灰 | 真实链路→绿；强制模拟→黄；模拟降级/离线→红；无数据→灰 | `/system/guide` → `links.robot.level`（`linkview.robotPill`） |
| **摄像头** | 绿/黄/红/灰 | 已连接→绿；打开中/服务未开/相机未开→黄；相机未连接→红；无数据→灰 | `links.camera.level`（`linkview.cameraPill`） |
| **示教器** | 绿/黄/红/灰 | AUTO/远程→绿；未确认/声明过期→黄；T1/T2→红；无数据→灰 | `links.run_mode.level`（`linkview.modePill`） |
| **真机链路** | 红 | ① 读不到控制器寄存器快照（`rc.ok === false`：模拟/离线/未连接）；② 报警 `rc.bits.alarm`；③ 急停 `rc.bits.estop`；④ **非 AUTO/远程档**（`rc.joggable === false`） | `stores/rcReady.js`（`/rc-status` 寄存器快照：`snap.ok`/`bits.alarm`/`bits.estop`/`snap.mode`/`ready`） |
| | 绿 | 以上都不成立且 `rc.ready === true`（伺服+程序+运行+AUTO/远程+无报警+非急停） | 同上 |
| | 黄 | 其余（有快照、档位对/无报警，但伺服未上电或程序未加载 = 中间态/正在就绪） | 同上 |

> 判据集中在 `StatusStrip.vue` 的 `logTab` / `linkTab` computed 与 `link.pills` 里；
> 灯色永远由真实字段算出，字段缺失一律灰（沿用 `linkview.toneOf` 的"未知绝不回退成绿"原则）。

### B.4 可见性规则

底部状态区所在的 `#bottom-zone` 是 **App 级常驻**（所有页面都在），本次**不扩大/不缩小**它的页面可见性。
被移除的只是 MonitorLayout 里那块**左下角浮动运行日志**（其功能整体迁入「运行日志」片），
以及 App.vue 里**独立的「真机链路」按钮**（功能整体迁入「真机链路」片）。

### B.5 不做什么

- **不加**新的状态数据源、不加新的轮询者（复用 link / rcReady / sorting3d 既有唯一轮询）。
- **不改** `linkview.js` 的机器人/摄像头/示教器三灯判据；**不删** `RcReadyCard` 任何内容。
- **不改** `#bottom-zone` 的页面可见性；**不重构**无关组件。

## D. 回归钉（加法）

### D.1 后端（pytest，纯逻辑/接口级，不连真机）

- 连续点动带 `speed_pct` **被真正采用**（回读 `speed_pct` 与请求一致；`speed_dps` 被忽略）。
- `JogStartIn` 无重复字段（源码解析：`speed_pct` 定义恰好一次）。
- DB 序列 item 自带 `speed_pct` **不再覆盖**请求值（`_steps_from` 产出的步骤速度恒为 `None`）。

### D.2 前端（`npm run verify`，解析源码断言）

- `SPEED_DEFAULT === 10`、`SPEED_MIN === 5`，且 `exec.speed` 初值 = `SPEED_DEFAULT`。
- 底部五个片的名字与顺序：`运行日志 · 机器人 · 摄像头 · 示教器 · 真机链路`（运行日志最左）。
- 默认开日志（`ui.statusPopover` 初值 = `"log"`）。
- 运行中自动开日志（`anyRunning` + watch 存在）。
- 点击外部收起的逻辑存在（document 监听 / `#bottom-zone` 判定）。
- 灯的三态判据存在（`logTab`/`linkTab` 判据字符串）。

> 复用现有 verify 脚本风格（`frontend/tools/verify_*.mjs`，解析源码断言），不新造框架。
