### A.2 ★ 关键结论：现场"从反面切回正面"的**根因**（已证实）

> **不是**"写死的 0"在作怪；真因是 **A-6：点到点移动把 J6 重置成"该点自带值"**。

- 双面编排里 `_move_flip_j6` 把 J6 转到「反面」后，**下一步 `_move`（到 `A2上` / `B{n}上` / `C检测`…）会按该点位自带 6 轴整姿态下发** → J6 被拉回**该点自身的值**（= 它的"默认正面"）。
- 于是现场看到的现象就是：**"刚从反面翻过来，一移动到下一个点又变正面"**。
- 现有 `J6正面`/`J6反面` 两点**解决的是"在当前位置原地切面"**（A-5），**没解决"每个点位自己的正/反面"**（用户本轮的新诉求）。

**一句话**：现状的"面"是**全局两点 + 原地切面**；用户要的是**每个点位都可切面**（以该点自身的 J6 为正面基准）。

### A.3 方案（取值规则 —— **做什么 / 不做什么**）

**取值规则（推荐）**

| 项 | 规则 |
|---|---|
| **正面（默认）** | = **该点位自身录的 `joints[5]`**（现状即如此，**保持**，不写死 0） |
| **反面** | = **该点位自身 J6 ∓ 180 归一**（**推荐**）：`back = v − 180`；若 `v−180 < −360` 或不便，则用 `v + 180`（两者对夹爪"面"等价，相差 360），取**落在 `[−360,360]` 且离当前 J6 更近**的那个 |
| **切回正面** | **恢复该点自身的 J6**（本轮要修的）—— 切面原语必须能"按点名 + 目标面"算出 J6 |
| **J1~J5** | **保持该点位自身的 J1~J5**（"像点位执行那样，只旋转 J6"）—— 见 §A.4 取舍 |
| **`J6正面`/`J6反面` 两点** | **保留**，继续作为"原地切面"（A-5）与"双面流程翻面基准"；**不再是唯一的反面来源** |
| **可选覆盖** | 允许现场为**某特定点**用另录的点值覆盖"反面"（若该点反面**不是**严格 ±180）；**默认不启用** |

**落地形态**：新增**运行时"面"模式**（不落库）——
`resolve_target_joints(name, joints, base_provider, face="front")` 扩一个 `face` 参数；
`face="back"` 时对**普通点位**返回 `[J1..J5 该点自身] + [J6 = 该点 J6 ∓180]`；
对 `J6正面`/`J6反面` **两点**仍走既有"原地切面"语义（A-5）。
流程侧用一个运行时 `state.face`（"当前面"，**推断**）驱动 `_move(... face=...)`。

**不做什么（边界）**
- ❌ **不改点位库存储格式**（`_norm_joints` 的"6 值"铁律不动）、**不加新存储 / 不迁移 DB**。
- ❌ **不动 38/40 点位清单与数量**（`test_double_face.py::test_optional_extra_point_does_not_change_the_38` 钉死）。
- ❌ **不改** `_move_flip_j6` 的**既有语义**（保留"基姿态不可得 → 回退整姿态 + 日志如实标注"，`test_flip_falls_back_and_logs_when_base_unavailable` 钉死）——新面语义走**新入口**，不覆盖旧行为。
- ❌ **不改** 18 原位禁转黑名单、速度口径（右上角滑块唯一权威）、下发时序/触发位/互锁（`motion._exec_lock`）。
- ❌ **不自己乱算**：只在"该点自身 J6"上做 ±180（相对），**不套用全局 `J6反面` 的绝对值到别的点**。

### A.4 优化 / 取舍（同一问题 ≥2 备选 + 为什么选它）

**问题 1：反面取值来源**

| 备选 | 说明 | 优点 | 代价 / 风险 | 判断 |
|---|---|---|---|---|
| **D1 各点自身 J6 ∓180**（推荐） | 每个点按自己的 J6 算反面 | ① 天然覆盖**每个点位**（用户核心诉求）；② 合"0°正 −180°反 / 不要写死"；③ 无需为每点各录一个反盘点 | 若现场某点反面**不是**严格 ±180，自算会有零头 → 需"可选覆盖" | ✅ **推荐** |
| **D2 用另录的全局 `J6反面` 点值** | 沿用现状（`DUAL_FACE_FLIP_POINT`） | 与既有"正反面由用户示教"口径 100% 一致 | 只有**一个全局反面值**，**无法**表达"每个点各有反面"；用户明确说"每个点位的默认 J6 是正面、不写死" → 不满足 | ❌ 不单独用（**保留为双面流程的翻面基准 + 可选覆盖**） |

**问题 2：切面时 J1~J5 取"该点位自身"还是"当前实时"**

| 备选 | 说明 | 判断 |
|---|---|---|
| **E1 该点位自身 J1~J5**（推荐，用于"到某点 + 用某面"） | 真正"到那个点"，只是 J6 用正/反面 —— 合用户"像点位执行那样，只旋转 J6"+"每个点位可切面" | ✅ 推荐 |

### B.2 方案

**做什么**
1. **用面由"持件槽位"驱动**：`lower`=正面、`upper`=反面（`S.FACE_SLOTS`，B-4）；**第 1 件正面、第 2 件反面**（B-2 顺序不变）。
2. **移动时保持面**：把流程里"取第 2 件 / 送检 / 放料"的 `_move` 调用改为 **face-aware**（`face = 当前面`），使 J6 **不被该点默认正面顶掉**（依赖 A 块的 face-aware move）。**这是 B 块的核心修复。**
3. **落料用面**：放"下板件"用正面、放"上板件"用反面（与取件面一一对应）；放件后 `face_slot_take` 如实记录。
4. **异常 / 中断恢复**：沿用现状 —— `_Stop` 收尾**先关两路气**（`:1029-1040`）再回起点；**如实报错**（不掩盖）。
5. **失败如实提示**：沿用 `emit_event`（`:1004-1010`、`:1078-1083`）。

**不做什么**
- ❌ **不改** `dual_face` 默认值（仍 `False` → 原单件路径零回归）。
- ❌ ~~**不改** `_dual_drop` 的四步时序（`停止吸→放→停止放→立刻吸`）—— 一路真空的既有口径。~~
  ★ 2026-10-11 **前提更正**：两面**独立气路** → `_dual_drop` 改为**三步**、**复吸取消**（见文首更正）。
- ❌ **不改** `_move_flip_j6` 的既有语义；`_put_back` 只在其**调用处/签名**补 `face`（并移除 `keep`）。
- ❌ **不做**未确认的自动化（例如"每个点都自动翻面"）。

### B.3 优化 / 取舍

| 问题 | 备选 | 判断 |
|---|---|---|
| 用面顺序怎么定 | **F1 由持件槽位驱动**（lower→正面 / upper→反面） | ✅ 推荐：与 `FACE_SLOTS` 同源、可测 |
| | F2 固定"第 2 件必反面"（按趟序） | ⚠ 等价但不如 F1 通用（换编排就会错） |
| 移动怎么"保持面" | **G1 给 `_move` 加 `face` 参数**（依赖 A 块） | ✅ 推荐：与 A 块同一原语，结构上不分叉 |
| | G2 在每个 `_move` 后**补一次** `_move_flip_j6` | ❌ 多一次运动、时序乱、易漏 |

### B.4 回归钉建议

| # | 钉子 | 断言要点 |
|---|---|---|
| 1 | 一趟两件用面顺序 | 取 lower 在**正面**、取 upper 在**反面**（源码/调用参数断言） |
| 2 | ★ **移动不重置面** | 取第 2 件 / 送检 / 放料的 `_move` 带 `face=back` 时，实发 J6 = 该点 J6∓180（**≠** 该点正面） |

### D.2 方案

**两种模式（推荐）**

| 模式 | 一趟取几子 | 流程 |
|---|---|---|
| **正常（默认）** | **1 子**（现状） | 机器人回合：取机器人子 → 落机器子；用户回合：**等用户落子** → 取用户子 → 落用户子 |
| **快速** | **2 子**（J6 双面，复用分拣双面原语） | **等用户落子**（`_wait_move`）→ 算机器人应对格 → **一趟**：取机器人子（正面）+ 翻面 + 取用户子（反面）→ **先落机器子（正面）、再落用户子（反面）** |

**触发方式（推荐）**：**界面开关**（卡片上"正常 / 快速"段，与分拣页 `SortingView` 的 normal/fast 同风格）→ `StartIn.fast`。
（可选）后续再支持 AI 口令；**本轮先做界面开关**（用户说"也是正常模式和快速模式两种"，与分拣页一致）。

**"等用户消息"的语义**
- **快速模式**：**必须先等到用户落子**（否则机器人不知道该放哪一子），然后一趟取两子。
- **正常模式**：维持现状（到用户回合就等）。

**"最后一子只剩一个空位 → 免等待直接完成"**
- 判定：`len(TT.empties(board)) <= 1`（`services/tictactoe.py:72-73`）。
- 实现：`_run` 里在 `turn=="user"` 分支**先判**：若只剩 1 个空位 → **不调 `_wait_move`**，直接把 `empties[0]` 作为用户落子（**唯一选择**）执行；机器人回合本就由 `ai_move` 选（只剩一格时必选它）。→ 免等待、直接完成。
- 文案：`stage`/日志如实写"只剩一个空位，直接完成（免等待）"。

**兼容**
- 难度（`difficulty`）、拍照自证（`verify_color`）、复位/复盘、空跑 `dry_run`、速度（右上角）**全部保持正交**，均不受影响。
- 快速模式**依赖** `J6正面`/`J6反面` 两点 + C 检测位（若开自证）→ 开局前置校验（同分拣页 `dualFaceBlocked` 的守卫思路）。

**不做什么**
- ❌ **不改** 井字棋映射（cell↔B、O=A1–A5 / X=A6–A9）、难度算法、胜负判定。
- ❌ **不新增下发通道**（复用 `_move/_air/_move_flip_j6/_dual_drop`）。
- ❌ **不把快速设为默认**（默认**正常**）。
- ❌ **不改** 复位/复盘逻辑（快速模式下复位仍逐子搬回）。

### D.3 优化 / 取舍

| 问题 | 备选 | 判断 |
|---|---|---|
| 快速模式"一趟两子"谁先落 | **J1 先落机器人子（正面）再落用户子（反面）** | ✅ 推荐：与"正面=lower=先取那件"一致、顺序可测 |
| | J2 先落用户子再落机器子 | ⚠ 与双面"先放先取的那件"相反，易乱 |
| 快速模式"等用户"的位置 | **K1 先等用户落子，再一趟处理** | ✅ 推荐：合用户原话"等等用户消息然后…一起拿" |

| | L2 仅用户回合免等待 | ⚠ 机器人回合本就不等待，L1 已覆盖 |

### D.4 回归钉建议
- `tests/test_tictactoe_api.py`：快速模式一趟取 2 子（源码/调用断言）；快速模式**先等用户落子**（序列断言）。

## F. 安全注意（★ 所有"让机器人动"的改动都要遵守）

- ★ **真机改动一律 5% 速度、单点先验证**；先**空跑 + 残影预演**，再切真机。
- ★ **执行前先确认 `GET /api/sorting/state` 的 `running=false`**；**不在真机分拣/对局运行期间**做任何可能打断它的操作。
- ★ **18 个原位（A1–A9 + B1–B9）严禁旋转**（`is_raw_material_slot`，黑名单）。任何"带 J6 翻转/切面的下发"**先过** `_rotation_guard`。
- ★ **未就绪闸门**：伺服未上电（`bits.servo` 为假）时，**所有真实下发一律拒绝**（`motion.servo_not_ready_reason` + `control.reject_if_not_ready`）；**空跑放行**，就绪流程本身不受影响。
- ★ **残影与实际下发同源**：目标的唯一解算口是 `resolve_target_joints`（残影走只读 `/control/point-target`）；**残影绝不下发**。
- ★ **上报必须自证**："哪面在用/吸住没有"是**流程推断**（现场无真空/面传感器），界面/3D **必须标注为推断**，**未知就说未知**。
- ★ **不写死**：不把"正面=0 / 反面=−180"写死；不把"某点位的反面"写死成全局值。
- ★ **失败即停 + 异常收气**：放了一半/取了一半 → 先关两路气（避免悬空带料），再回起点（沿用现有口径）。
- **本方案文档本身不产生任何运动**，全部改动**实施时才落地**。

| 3 | **C（AI 快速完成）** | 只做"解析 + 传参 + 回显"，**不新增下发通道**；依赖 B 已能正确走双面。**纯解析可单测**。 |

## I. 井字棋「真实复盘」（2026-10-11 落地）

> 用户口径（原话）：「机器人复盘要真实复盘，机器人要动起来，每一个棋子放到原位」。

### I.1 口径（做什么 / 不做什么）

| 项 | 口径 |
|---|---|
| **什么是「复盘」** | **真实复盘** = 机器人**真的动**，把 B 区已落的子**逐个搬回各自来源 A 格（= 该子的「原位」）**。 |
| **「原位」的定义** | 该手棋谱里的 `src` —— 取料来源 A 格（`services/tictactoe.py::pick_source`，圆 A1–A5 / 叉 A6–A9）。 |
| **顺序** | **落子逆序（LIFO）**：最后一手先搬回。理由见 I.2。 |
| **终态** | 全部搬回后 **棋盘清空 / 复位到初始**（`board/moves/used/result/win_line` 全清），与 3D / 2D **同源**一致。 |
| **触发** | 卡片「复盘」按钮（`POST /api/tictactoe/replay`）；**真实局二次确认**（手柄用"Y×2"二次确认，空跑免确认）。 |
| **回执** | 用现有 `stage` 机制：`复盘：搬回第 i/n 个棋子 → A?（原位）`（前端日志面板逐条显示）。 |
| **空跑** | `st.dry_run=True` → **只走预演路径**（`_carry(..., dry=True)` 全程只 `_set` 阶段、**不下发任何真实运动**），但流程/显示/终态逐字一致。 |
| **停止** | **沿用既有语义**：`/tictactoe/stop` → `request_cancel` → 步边界停止（`ctx.cancelled()`）；异常不收件就回起点。 |
| **悬空带料** | **不许**：停止时若 `holding` 为真 → 收尾 `_release_air`（先后关两路气）。 |
| **未就绪闸门** | **生效**：真实复盘（非空跑）伺服未上电 → 409 + 既有**统一文案**（`motion.SERVO_NOT_READY_MSG`）。 |

**不做什么（边界）**
- ❌ **不新增下发通道**：复盘复用 `sorting._carry`（= 分拣同一套 `_move`/`_air`），不绕开 `motion.command`、不新增触发位。
- ❌ **不改**下发时序 / 触发位 / 互锁 / 寄存器 / `rc_ready.py` / `camera/*` / 速度口径 / `dual_face` 默认值。
- ❌ **不翻转 J6**：复盘只走普通 `_move`（到点整姿态），**不动 J6**，故天然不碰"18 原位严禁旋转"。
- ❌ **不改**「复位」（`_reset_run`）与 2D「回放」查看器（逐手回看，只读、不动机器人）—— 两者都在。

### I.2 为什么选「落子逆序」（同一问题 ≥2 备选）

| 备选 | 说明 | 判断 |
|---|---|---|
| **逆序（LIFO）**（选中） | 最后一手先搬回 | ✅ ① 与既有 `_reset_run`（复位）**同一口径**，不新造第二条路；② 语义="把整局倒着撤销"，与棋谱对得上；③ 实现最简（`reversed(moves)`） |
| 行 / 列顺序 | 按 B1→B9 搬回 | ⚠ 与复位口径不一致，且"复盘"看起来像重下，不直观 |
| 任意 / 并发 | 谁近先搬 | ❌ 不可复现、不可测，真机上更难解释 |

> 注：各子各占一格、**不堆叠**，顺序只为"可读 + 与复位一致"，**不是防撞**（撞的风险由围栏/残影另管）。

### I.3 与既有安全口径的关系

- ★ **18 原位严禁旋转**：复盘**不做任何 J6 翻转**（只 `_move` 到点），该黑名单不会被触发，也不被削弱。
- ★ **速度唯一口径 = 右上角滑块**：复盘照 `st["speed_pct"]`（=`/replay` 可带 `speed_pct`，前端传 `exec.speed`），不另立速度。
- ★ **未就绪闸门**：真实复盘走 `reject_if_not_ready(dry=st.dry_run)`（与 `/start` 同源同文案）。
- ★ **残影与实际下发同源**：复盘不产生新的"目标解算口"，仍走 `resolve_target_joints`（`_move`）。
- ★ **异常收尾**：`finally` 第一件事必须 `ctx.finish(...)`（与 `_run`/`_reset_run` 同口径，回归钉已扩到 `_replay_run`）。
- ★ **推断如实**：手上是否有件是**流程推断**（现场无真空传感器），界面/3D 照旧标注，不编故事。

### I.4 真机验证方式（★ 所有"让机器人动"的改动都要遵守）

1. **先离线**：`pytest -q`（含 `test_tictactoe_api.py` 的复盘钉：逐子搬回 / 逆序 / 目标=原位 / 空跑不下发 / 未就绪被拒）。
2. **再空跑**：`dry_run=true` 下打完一局 → 点「复盘」→ 机器人**不动**，但阶段/回执逐条走过、棋盘清空。**这一步不需要伺服上电**。
3. **再真机 5%**：**先确认 `GET /api/sorting/state` 的 `running=false`**；把顶栏速度调到 **5%**；
   真实下发打完一局（或直接用「复位」口径先单子验证）→ 点「复盘」→ 观察**逐子搬回原位**、终态棋盘清空。
4. **异常/停止**：中途「停止」→ 应**步边界**停住、且**不悬空带料**（气路已收）。
5. ★ **绝不在真机分拣/对局运行期间**做任何可能打断它的操作。

### I.6 已知边界 / 故意没做

- **「复位」`_reset_run` 未改**：它当前对 `_carry` 传的是 `dry=True`（= 复位在真实局其实不真搬）。
  这与本轮需求（复盘要真动）无关，且**改它会变更"复位"行为**（超出本轮范围），故**故意不动**，
