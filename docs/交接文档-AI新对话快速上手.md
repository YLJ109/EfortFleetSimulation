## 1. 项目定位与仓库

埃夫特 ER8-700H 六轴工业机器人：**真实监控 + 数字孪生 + 远程控制**全栈 Web 系统。
用 **Modbus TCP** 读真实控制器（`192.168.1.12:502`），用 **Three.js** 按官方 DH 参数驱动 GLB 1:1 跟随；
含七色识别与分拣、数字孪生预演、自然语言指令、工业安全围栏。

**核心主张**：不做"能连上"的远程控制，做"**每一步都能自证**"的远程控制 —— 下发必须回读确认；
推断必须标注来源；**不知道就说不不知道**。

| 服务 | 端口 | 说明 |
|---|---|---|
| 后端 API + WS | `8000` | FastAPI，**同时托管前端构建产物 `frontend/dist`** |
| 视觉/相机 | `8100` | OpenCV 三色识别，**独立进程**（无鉴权，默认只绑 127.0.0.1） |
| Vite dev | `5173` | 仅开发调试（改前端热更新用；后端仍要跑） |

**规模（2026-10-12 实测）**：后端 59 模块 / 前端 80 源文件 / **后端测试 751 条** /
**前端回归脚本 31 个** / **文档 58 份**。

## 2. 三步跑起来 + 常用命令

```bat
REM ① 体检（只读）：PASS=就绪 / WARN=可选缺失 / FAIL=必须先修
scripts\doctor.bat

REM ② 一键启动：清理旧进程 + 视觉服务(8100) + 后端(8000) + 自动开浏览器
run.bat

REM ③ 浏览器 http://localhost:8000 → 登录（口令见 .env 的 EFORT_ADMIN_PASSWORD）
```

```bat
REM ---- 测试（每轮收尾必跑，全绿才算完）----
cd backend   && .venv\Scripts\python.exe -m pytest -q        REM 751 条，不连真机
cd frontend  && npm run verify                              REM 31 个 headless 回归脚本
cd frontend  && npm run build                               REM 改完前端必须 build（8000 托管的是 dist）

REM ---- 真机只读排查（★ 只读：不下发、不动机器人；先确认分拣没在跑）----
REM 一次读全状态 + 用新判据给结论（现场常用）
cd backend && .venv\Scripts\python.exe -c "from app.services.motion import motion, readiness_reason; s,e=motion.modbus.rc_snapshot(); print('err=',e,'ready_reason=',readiness_reason(s))"
cd backend && .venv\Scripts\python.exe tools\probe_regs.py            REM 40103 设定 vs 40003 实际（速度对不上时用）
%CAM_PY% camera\tools\vision_e2e_replay.py 40               REM ★ 改判色阈值前必跑（现场真图）
cd frontend && npm run preview:3d                           REM 3D 摆位核对
cd frontend && npm run measure:ee                           REM 量末端工具尺寸
```

> 端口约定：`8000` 后端（同时托管 dist）· `8100` 视觉 · `5173` 前端 dev。
> ★ 后端与视觉服务**默认只绑 `127.0.0.1`**；跨机访问要设 `EFORT_HOST/EFORT_CAMERA_HOST=0.0.0.0`
> （视觉服务无鉴权，强烈建议同时设 `EFORT_CAMERA_TOKEN`）。
> ★ 后端**没有 --reload**：改完后端必须重启进程才生效。
> ★ 真机 HTTP 脚本必须禁代理：`curl --noproxy '*'` 或设 `no_proxy=127.0.0.1`。

## 3. 硬口径速查（详情一律见 AGENTS.md §5，别凭印象）

| 主题 | 一句话口径 |
|---|---|
| 控制器机理 | PC 只能"写目标数据 + 触发位"；真正运动由**常驻程序 210** 执行 ⇒ "下发成功"≠"动作完成" |
| 寄存器 | `40101` 命令字 · `40103` 速度（40102 无效）· `40104` 程序号 · `40135` 触发/完成位（**位表见 AGENTS §5.3**） |
| 就绪顺序 | 停机 → 清报警 → 伺服 → 加载 → 运行（顺序不可换）；清报警必须先停机 |
| 就绪判据 | `motion.readiness_reason`（唯一实现）= 伺服 + `prog==210` 且 `run=1` + AUTO + 无报警/急停 |
| 未就绪门控 | `reject_if_not_ready`（接口层）；**空跑/模拟/就绪流程本身放行**（防死锁） |
| 18 原料位 | `A1…A9 / B1…B9` **严禁旋转**（`is_raw_material_slot` 黑名单，一个字节未改） |
| 原位安全路径 | **垂直只在"原位 ↔ 其正上位"；横向只在"正上位/起点/摄像头"**；**一切入口自动补段** |
| 升降不转 | 原位 ↔ 正上位 两段 **J6 冻结**（不在升降途中转） |
| 面语义 | 正面 = 该点自身录制 J6；反面 = 自身 − 180；`J6正面/反面` = 虚拟切面（无需示教） |
| 静默失效五铁律 | 水位单调递增（用 `logSeq` 不用 `log.length`）· 状态以后端为准 · 未知不塌布尔 · 同屏同源 · 假功能要么接线要么删 |

**本轮（2026-10-12）关键结论（新对话务必知道）**

1. **修真 bug**：旧 `ready = servo and prog_loaded and run` 在**正常运行态**（现场实测
   `prog=210 / run=1 / prog_loaded=0`）**恒为 false** ⇒ 所有就绪门控的按钮本来就点不动。
   现收敛到 `motion.readiness_reason/snapshot_ready`（唯一实现），`/api/rc-status` 与采集器都调它。
2. **未就绪统一门控**：执行类按钮（含急停/复位）一律 `canControl && rc.ready`；
   **录点/存点/删除保持可用**；一键就绪在"非 AUTO / 拿不到实时姿态"时禁用。
3. **原位安全路径**：见 §3；实现 = `services/sorting.py::raw_slot_safe_path` /
   `raw_slot_step_targets`；**一切入口自动补段（不再拒绝）**。
4. 方案与钉子：`docs/方案-原位禁转与未就绪统一门控.md`、
   `backend/tests/test_origin_rotation_lock.py`、`tests/test_not_ready_gate.py`、
   `frontend/tools/verify_not_ready_gate.mjs`。

## 6. 协作纪律（用户偏好，别踩）

1. **先思考 → 出方案（写 `docs/方案-*.md`）→ 确认 → 再实现**；方案里写清"做什么 / **不做什么**"。
2. **诚实汇报**：未落地项、假报警、误导性提示语要**明说**，并当场改掉提示语本身。
   用户会追问「**我说的全部落地了吗？**」⇒ 汇报要能**逐条对上**。
3. 输出偏好：**中文**、**表格/清单式**、直给结论；**不要反复提问**（一次把待确认点列清）。
4. 每轮以 **pytest + verify + build 全绿**收尾；**git 提交由用户手动执行**。
5. 遇到"界面显示与实际不符"，**优先怀疑渲染层在编故事**，而不是先调参 ——
   本项目原则是"不知道就说不知道"。

## 7. 出问题先看哪里

| 症状 | 先看 |
|---|---|
| 点不动 / 按钮灰 | `GET /api/rc-status`（`ready`/`servo_on`/`mode`/`prog`）→ AGENTS §5.3 就绪判据 |
| "速度不对 / 我调了 40 它按 10 跑" | `tools\probe_regs.py`（只读，一次读 40103 设定 + 40003 实际） |
| 机器人 J6 乱转 / 卡住 | AGENTS §5.3「J6 旋转管控」+「原位安全路径」 |
| 判色不准 | 先跑 `vision_e2e_replay.py`（现场真图），再动阈值 |
| 界面数字与真机不符 | AGENTS §5.5「静默失效五铁律」 |
