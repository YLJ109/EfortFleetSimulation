> 用户需求（2026-10-11 原话，两轮）：
> ① 「现在我想设计一个手柄控制页面：**坐标新添加手柄执行页面**
> 1. 2D 出现 A 区，B 区，C 区，起点
> 2. 从 2D 画面可以选择方块点，左右上下进行，**左边 B 区，中间下面摄像头点位 C 区，
>    上面是起点，然后右边是 A 区**，A 和 B 9 个格就像井字棋一样，通过手柄的上下左右点之间切换，
>    3. 把井字棋游戏放在手柄执行模块里面，右侧做个 tab 栏井字棋和执行两个 tab 栏
>    你先思考，然后做方案吧」
> ② 「**手柄的 A 是原位，Y 是正上位，X 是吸气，再点一次 X 是停止吸气，B 是放气，再点一次停止放，
>    LB 停吸，RB 停止放，通过 Start 启动和关闭**，井字棋要**搬走**之前的移除掉，放在新页面，
>    设计一下，**移除掉没有的测试键**的要，应该是左边吧」

**状态**：★ **已落地**（2026-10-11）。用户已确认按键口径（X=吸气/停止吸气、B=放气/停止放气、Start=开启/关闭）。
落地清单见 §11；回归钉 `tools/verify_pad.mjs` + `tools/verify_pad_nav.mjs`。

## 1. 目标（一句话）

新增一个**纯手柄操作**的页面：**2D 图上选点 → 手柄按一下就真机移动 / 吸放**；
把**井字棋**从「智能分拣」页**搬**进来（右栏 tab：`执行` / `井字棋`）；
把**手柄测试盒**一并搬进来，并**只保留本页真实存在的按键**（去掉用不到的模拟键）。

## 3. 页面结构与导航

```
顶栏（新增，side:"left"）
  真实监控 | 点位执行 | 智能分拣 | AI 执行 | [手柄执行]        模拟仿真 | 运维审计 | 系统设置 | 关于

手柄执行页
├─ 中：3D 场景（沿用 MonitorLayout，全局常显）
├─ 浮层：2D 执行图（§4）                ← 手柄 ↑↓←→ 在这里选点
└─ 右栏
   ├─ 顶部 tab： [ 执行 ] [ 井字棋 ]     ← 复用全局 .srt-tabs / .srt-tab
   ├─ 执行 tab：选中点 / 手柄启停状态 / 气路状态 / 手柄按键图例 + 手柄测试盒（§7）
   └─ 井字棋 tab：现有 TicTacToeCard 整体搬入（§6）+ 手柄测试盒（按 tab 换表）
```

**同页两个 tab 的手柄归属**（★ 防"一次按键两个动作"）：

| tab | 谁响应手柄 | 守卫判据 |
|---|---|---|
| 执行 | 本页自己的执行逻辑（`stores/pad.js`） | `activeView==="pad" && pad.tab==="exec"` |
| 井字棋 | `TicTacToeCard` / `TicTacToeBoard`（原样复用） | `activeView==="pad" && pad.tab==="ttt"` |

两者**互斥**（同一时刻只有一个 tab），所以沿既有"两块各订阅、判据互不重叠"的写法即可，
**不新造中央分发器**。

## 5. ★ 手柄按键映射（最终口径）

### 5.1 逐键表

| 手柄 | **执行 tab** | 走哪个后端口 | **井字棋 tab** |
|---|---|---|---|
| ↑↓←→（十字键，其次左摇杆） | 2D 光标**选点** | —（纯前端） | 棋盘光标 |
| **A** | **去选中点的「原位」（槽位本身）** | `POST /sorting/goto {name}` | 落子 |
| **Y** | **去选中点的「正上位」**（`选中点+"上"`） | `POST /sorting/goto {name}` | 复原（真机） |
| **X** | **吸气** ⇄ 再按**停止吸气**（toggle） | `/control/vacuum {suck}` ⇄ `{release}` | 暂停 ⇄ 继续 |
| **B** | **放气** ⇄ 再按**停止放气**（toggle） | `/control/vacuum {blow}` ⇄ `{unblow}` | 停止（作废） |
| **LB** | **切 J6 正面**（原地切面，J1~J5 不动） | `POST /sorting/goto {name:"J6正面"}`（后端转 `compose_j6_only`） | —（本 tab 无此键） |
| **RB** | **切 J6 反面**（原地切面） | `POST /sorting/goto {name:"J6反面"}`（同上） | — |
| **Start** | **启动 / 关闭**（见 §5.2） | — | 开局 |
| **View** | —（本 tab 无此键） | — | 复原（真机，二次确认） |

> ★★ **2026-10-11 用户口径**：「**手柄的 LB 改成正面，RB 改成反面，J6 的**」——
> LB/RB 由"停止吸气/停止放气"改为**切 J6 正面 / 反面**。
> **停止吸气 / 停止放气由 X / B 的第二按承担**（toggle），不再单列按键。
> ★ 这两个点（`J6正面` / `J6反面`）后端走 `S.compose_j6_only`：**基姿态 = 当前实时关节、
> 只覆盖第 6 轴** → **不会跑回起点**；未示教 → 后端 404 如实显示；
> 回执带 `j6_only` → 界面文案写成「已在原地切到…（仅 J6）」，不假装"到点"。
> 点名必须与 `backend/app/services/sorting.py::OPTIONAL_EXTRA_POINTS` 一字不差（回归钉 `verify_pad.mjs` C14b）。

### 5.2 Start = 「启动 / 关闭」怎么落地（我的理解，请确认）

按 §5.1，**执行 tab 的 Start 是一个"总闸"**（toggle）：

- **落锁（默认）**：`A/Y/X/B/LB/RB` 一律**不动作**（面板显示「未启动」）——只有方向键能选点（纯前端，不动机器人）；
- **Start 一下 → 解锁**（面板显示「已启动」）；**再按一下 → 落锁**。

**为什么这么做**：手柄是最容易被误碰的输入。这不是新造安全逻辑，而是把"真机动作必须有明确意图"
这条既有约定，用 Start 表达出来（等价于现有井字棋那套"手柄专用二次确认"的思路，只是更直观）。

> 若你要的"启动/关闭"是别的意思（例如 Start 直接开局井字棋、或 Start 只是启停 3D 跟随），说一声，改 §5.1 第 8 行即可，其余不受影响。

### 5.3 「原位 / 正上位」的边界（只对 A/B 槽位成立）

- 选中 **`A1…A9` / `B1…B9`**：A 键 → 该点自身（后端 `face_for_target` → **`keep`、绝不翻面**）；
  Y 键 → 该点 `+"上"`（**正上方**，允许旋转）。
- 选中 **`C检测` / `开始/结束点`**：**没有"正上位"** → A 键 = 去该点；**Y 键不动作**，面板提示
  「该点没有正上位」。（绝不悄悄改去别的点。）

### 5.4 LB / RB 需要一个"新动作名"（代码事实）

`gamepad.js` 目前 **LB / RB 没有映射**（按了不产生动作）。本方案给它们加两个**中性动作名**：

```js
BTN_ACTION = { ...原有..., [BTN.LB]: "l1", [BTN.RB]: "r1" };
```

> ★ 为什么用中性命 `l1/r1` 而不是 `stop_suck/stop_blow`：**同一个动作名在两个 tab 里含义不同**
> （LB 在执行 tab = 停止吸气；井字棋 tab 无此键）。`gamepad.js` 只负责"哪个键被按了"，
> **含义由页面（tab）解释** —— 这与文件头"组件只认动作名，不认按钮号"的分层一致。
> A/B/X/Y 沿用既有名（`confirm/stop/pause/replay`），含义同样**按 tab 解释**（见 §3 归属表）。

## 10. 不做什么（划清边界）

- **不做**反面气路（Bit5~8）的手柄映射（按钮不够，且属"进阶"；等你提组合键）；

- **不做**光标拖拽 / 鼠标操作（手柄场景）；
- **不动**：40135 位表、18 原料位禁转、`keep` 面语义、未就绪闸门、`ui_speed`。
