# 方案 · 三色识别口径收敛（只识别矩形 · 三色 · 滤掉小目标与低置信度）

> 2026-10-08 · 用户要求：**只需要识别矩形，三种颜色，太小的不要检测，置信度太低的不要检测**。

---

## 1. 先纠正一处外部诊断（我逐个核了代码）

贴过来的分析说「CIE Lab / ΔE 是**死代码**，`de`/`alt_de`/`chroma` 恒为 null」——
**这一条不成立**。`vision_color._color()` 里的实际调用是：

```python
if dom["ok"]:
    cr = classify_rgb(dom["lab"])      # ← 真的在调（CIEDE2000 最近邻）
    de, alt, alt_de, chroma, lab_conf = cr["de"], cr["alt"], cr["alt_de"], cr["chroma"], cr["conf"]
...
# 置信度 = HSV 一致性 × 方正度，再与 Lab ΔE 置信**取较严者**（交叉门控更稳）
conf = round(min(hsv_conf, lab_conf), 3)
if name_l != name: reason = "HSV/Lab 分歧(%s)" % name_l
```

**Lab 是活的**：它不决定颜色**名**（名字由 HSV 色相投票定），但
① 参与**置信度交叉门控**（取较严者）；② 产出 `de/alt_de/chroma`；
③ 当 HSV 与 Lab 结论不一致时写"分歧"标记（这本身是一道交叉校验）。
→ 所以**不要按"死代码"去删它**，删了会丢掉一道交叉校验和所有色差信息。

## 3. 要做的改动（小而准）

### 3.1 矩形硬门槛（新增，唯一的新判据）
- 在 `DEFAULT_THR` 加 `fill_min: 0.72`（带 range，可由 `/vision/config` 覆盖）
- `_color()` 里：`fill < fill_min` → 直接返回 `{"name":"未知","reason":"非矩形(填充率 %.2f < %.2f)"}`
- ⚠️ **副作用要如实说**：`fill` 是"候选框内掩码像素占比"。方块**正对**相机时接近 1；
  一旦**倾斜/部分遮挡**，fill 会掉 —— 门槛设太高会把**斜着拿的方块**判成非矩形而漏检。
  → 默认 0.72 沿用它原来的告警线，**并在界面标注该副作用**，允许现场下调。

### 3.2 把尺寸阈值搬到界面（体验补齐）
在摄像头面板现有的「检测置信度 ≥ x%」旁边，再加：
- **最小短边 ≥ N px**（`min_side`，默认 30）
- **最小面积占比 ≥ x%**（`min_area_ratio`，默认 0.3%）
两个滑杆直接走既有 `/vision/config`，不必改后端。

### 3.3 结果可解释（让"为什么没检测到"看得见）
现在判"未知"有 6 种原因（采样不足/非红绿蓝三色/非矩形/太小/低置信/HSV-Lab 分歧）。
面板上**把最近一次未知的原因原样显示**（已有 `reason` 字段，只需展示），
现场就能立刻知道是"太小"还是"太斜"还是"颜色不对"。

## 4. 可选（**默认不做**，要动请明确说）

外面那份分析里两条色带偏差是**真的**，但它们是**改判据**，会改变现有识别结果：

| 现象 | 原因 | 若改的代价 |
|---|---|---|
| 青色/紫色偏蓝 | 蓝带 H∈[95,145) 偏宽（青~90、紫~137 落在里面） | 收窄蓝带 → 某些"偏青的蓝"会判未知（漏检） |
| 偏粉的红（H≈160）判未知 | 145~168 是空档 | 补一小段红带 → 粉/洋红系会被当红（新增误判面） |

**建议**：先按 §3 做（不改判据、只加硬门槛与旋钮），**用现场实物跑一遍**；
若现场确实出现"青色被当蓝"或"粉色判未知"，再动色带 —— 有实测数据再调，比现在纸上改稳。
