# 方案 · 井字棋 3D 棋子视觉与「复原」（颜色区分 · 圆/叉 · 坠落动作 · 真机移动）

> 用户原话（2026-10-11，附 3D 截图）：
> 「模拟的这些盒子要颜色区分呀，不是全部白色，放的时候要动作呀，怎么跟随机器人走了呀？
> 放的时候要坠落的动作，蓝色是圆，绿色是叉，复原和复盘合并，就是复原，不用空跑啊，要真机移动！
> 先思考理解，然后再做方案，再区执行」
>
> 本文 = **思考理解 + 方案**。用户点头后再动代码。

## 0. 用户原话逐条翻译（先把"要什么"钉死）

| # | 用户的话 | 我的理解（可执行口径） |
|---|---|---|
| 1 | 模拟的这些盒子要颜色区分，不是全部白色 | 3D 里井字棋棋子**按符号上色**（现在是一律灰 `0x8a8f95`） |

## 1. 只读调查结论（已核实到源码行，不是猜的）

| 编号 | 现象 | 根因（出处） |
|---|---|---|
| ① | 3D 棋子**全是灰的** | 井字棋覆盖时 `usedSlot.set("B"+(i+1), "__ttt__")`，`"__ttt__"` 不在 `matByColor` 里 → 一律落到 `matUnknown`（灰）。见 [sortingBlocks.js](../../frontend/src/three/sortingBlocks.js) `update()` | 
| ② | 落子**没有任何动作**（瞬移） | B 块可见性只在 `update()` 里由 `board` 直接翻转，**没有过渡**；`step()` 只管摄像头闪烁 + 手上料 |
| ③ | **"棋子跟着机器人走"** | 快速模式**机器人先手**时，后端 `board[cell_r]=robot_sym` 是**提前写**的（`tictactoe.py::_run` 快速分支）→ 3D 立刻在格子里画出子；而物理上机器人**还在搬运**，`hand` 那块仍贴吸盘跟随 → 看上去"格子有子 + 手上还有一块" |
| ④ | 2D 符号颜色不符 | `.ttt-cell.o .mk{color:#7fe3ff}`（青）、`.ttt-cell.x .mk{color:#ffc861}`（琥珀），见 [TicTacToeBoard.vue](../../frontend/src/components/TicTacToeBoard.vue) |
| ⑤ | 复位/复盘**两个按钮**并存 | [TicTacToeCard.vue](../../frontend/src/components/TicTacToeCard.vue) 有 `复位`(doReset→`POST /reset`) 与 `复盘`(doReplay→`POST /replay`) |
| ⑥ | **真实局的"复位"其实不真搬** | `_reset_run` 里写死 `_carry(ctx, pmap, st, True, ...)`（`dry=True`）→ 永远只 `_set` 阶段、不下发运动。见 [tictactoe.py](../../backend/app/api/tictactoe.py) `_reset_run` |
| ⑦ | 空跑局"复位"直接清棋盘 | `/reset` 里 `if st.get("dry_run"): 清棋盘 return` —— 空跑局**没有真搬过**，这条是**对的**（没有实体可搬），保留 |
| ⑧ | **日志满 240 行后不再自动滚到底** | [StatusStrip.vue](../../frontend/src/components/StatusStrip.vue) 用 `watch(() => exec.log.length, …)` 触发滚底；而 [exec.js](../../frontend/src/stores/exec.js) `logLine()` 超过 `LOG_MAX = 240` 会 `splice` 掉旧行 → **长度恒为 240、不再变化 → 水位失效**。偏偏日志越长越需要跟底，这里正好断掉 |

**两处逻辑事实（用来上色）**：
- 棋盘值就是 `"O"/"X"`，`setTtt` 已经拿到，**信息早就有，只是没用**；
- 来源映射：`A1–A5 = O（圆）`、`A6–A9 = X（叉）`（`services/tictactoe.py::O_SOURCES/X_SOURCES`），所以 **A 区那 9 块料也能按符号上色**（这正好能解释"不是全部白色"）。

## 2. 做什么

### A. 3D 棋子按符号上色 + 圆/叉标记（前端）

`sortingBlocks.js`：

1. 新增符号色表（**复用现有 `SORT_COLOR_HEX` 的"蓝/绿"，避免出现两种不一样的蓝**）：
   ```js
   export const TTT_SYM_HEX = { O: SORT_COLOR_HEX["蓝"], X: SORT_COLOR_HEX["绿"] };
   ```
2. `setTtt(o)` 的 `board` 值**直接驱动材质**：把 `"__ttt__"` 换成 `{sym:"O"|"X"}`；`update()` 按符号取材质。
3. **A 区料块**：井字棋模式下按来源符号上色（`A1–A5`→O 蓝、`A6–A9`→X 绿），已取走（`used`）的照旧隐藏。
4. **圆/叉标记**：方块顶面加一个**子网格**——
   - O → **圆环**（`RingGeometry`/细 `TorusGeometry`）；
   - X → **十字**（两条细长 `BoxGeometry` 交叉）。
   随方块一起显隐/坠落；`userData.sym` 记录符号（回归可断言）。
5. 颜色/标记**只是显示**，不写入任何分拣字段。

> **明确记录一个取舍**：3D 里棋子颜色 = **符号色**（身份：圆/叉），**不是**该格料的实测颜色（自证模式判出来的红/绿/蓝）。理由是用户本轮口径就是"蓝=圆、绿=叉"，且**默认模式根本不判色**、没有实测色可显示。若以后要"显示实测色"，另开一层（本轮不做）。

### B. 落子「坠落」动作（前端，纯视觉）

`sortingBlocks.js`：

- 常量：`FALL_H_MM = 60`（从格子上方 60mm 落下）、`FALL_DUR = 0.32s`。
- B 块（以及"被放回 A 格"的 A 块）在 **`visible: false → true` 跳变**时记一次 `fallT = 0`；
  之后由 `step(dt)` 推进：`y = cellY + FALL_H·(1−p)`，`p` 走 easeOutCubic（末段轻微回弹），
  `p ≥ 1` 时**严格回到 `cellY`**（一字不差，不能留残留偏移）。
- **只在 `step()` 里推进** → 不调 `step()` 时位置就是格子高度，`verify_sorting3d.mjs` 现有的
  "所有槽位同高"断言**不受影响**。
- 手上那块在 `holding` 变 `false` 时**立即隐藏**（现有逻辑）：视觉序列 = 贴着吸盘 → 吸盘松开 → 掉到格子。

### C. 快速模式「提前显示」的棋子渲染成**预告态**（前端 + 后端一个字段）

这是 ③ 的根因，必须治，否则"棋子跟着机器人走"还会被看到：

- **后端**：机器人先手提前写 `board` 时，同时 `st["pending"] = [cell]`；`_play_two` 真搬完成后清空
  `pending`（`_set_state` 收尾里也兜底清）。`/state` 原样带出。
- **前端**：`setTtt({board, used, holding, pending})`；3D 里 `pending` 的格子棋子 **半透明 + 不坠落**；
  2D 棋盘该格加 `pending` 虚框样式。
- 语义与后端 `stage` 文案「已显示，待搬子」**一字对应**（不编故事）。

### D. 「复原」= 复位 + 复盘 合并（前端 + 后端）

- **前端 [TicTacToeCard.vue](../../frontend/src/components/TicTacToeCard.vue)**：
  - 删掉「复盘」按钮；「复位」改名「**复原**」；
  - `复原` = 把 B 区已落的子**按落地逆序逐个搬回各自原位 A 格**（`moves[].src`）；真实局二次确认；
  - 手柄：`Y(复盘)` 与 `View(复位)` **都指向「复原」**（动作名保留，语义合一，避免一次改两处枚举）。
- **后端 [tictactoe.py](../../backend/app/api/tictactoe.py)**：
  - **删掉 `_reset_run`**（它写死 `dry=True`，就是 ⑥ 的病根）；`POST /tictactoe/replay` 用的
    `_replay_run` 改名语义为「复原」并**成为唯一实现**（台阶文案从"复盘"改为"复原"）；
  - `POST /tictactoe/reset` 改为**起同一条真实线程**（`dry = 本局的 dry_run`）：
    - 真实局 → **真机搬回**（过 §E 的闸门）；
    - 空跑局 → **没有实体可搬** → 只清棋盘，并**如实说明**（不假装搬过）。
  - `POST /tictactoe/replay` 保留为**兼容别名**（指向同一函数），界面上不再有入口。

### E. 「真机移动」与安全闸门

- 「复原」在**真实局**：过 `reject_if_not_ready(dry=False)`（伺服未上电 → 409 统一文案）
  + `_reject_if_run_active`，与 `/start`、`/replay` **同一套**。
- 速度：仍取 `st.speed_pct`（= 右上角滑块），`/reset` 可带"此刻"的 `speed_pct`（已有参数）。
- **★ 默认空跑翻掉（按你"不用空跑啊，要真机移动"）**：
  - 「复原」在**真实局**一律真机搬回（见 D）；**空跑局**没有实体可搬 → 只清棋盘并明说；
  - 井字棋**开局默认改为「真实下发」**（`dryRun` 默认 `false`）：你点「开始」就是真搬棋子；
  - 「空跑」勾选框**保留**（排练/离线演示用），勾上时界面明写"不动机器人"；
  - **真实下发开局前弹一次确认**（把"机器人真的会搬棋子、跟顶栏速度"说清），
    与既有"切到真实下发要确认"的安全口径一致；
  - 硬安全网不变：**伺服未上电一律 409 拒绝**（未就绪闸门）+ 顶栏速度 + 急停/停止。
- 铁律不动：「18 个原料位严禁旋转」「去原料位一律 `keep`」「伺服未上电所有真实下发一律拒」
  全部照旧，本方案**不碰**。

### F. 运行日志「来新消息就自动到底」（前端，修 ⑧）

- [exec.js](../../frontend/src/stores/exec.js)：新增单调递增 **`logSeq`**（`logLine()` 每条 `+1`，
  `clearLog()` 归零）。**用序号当水位**，不再依赖 `log.length`（会被 `LOG_MAX` 截断后不再变化）。
- [StatusStrip.vue](../../frontend/src/components/StatusStrip.vue)：把
  `watch(() => exec.log.length, …)` 改成 `watch(() => exec.logSeq, …)`。
- **保留**既有"粘底"语义：用户往上翻看历史时**不抢滚动条**（`logStick` + `LOG_BOTTOM_EPS = 24` 不变）；
  重新点开「运行日志」片、或翻回到最底 → 恢复跟随。
- 只改水位判据，不动渲染/配色/面板布局。

### G. 运行日志之外的对局日志（顺带覆盖）

井字棋阶段/结果也是写进同一个 `exec.logLine`，所以 F 修好后它们同样自动到底（无需另写一套）。

## 3. 不做什么（划清边界）

- 不改井字棋**算法/胜负/映射**（`cell i ↔ B(i+1)`、`O=A1–A5`、`X=A6–A9`、先手执圆）。
- 不改 `_carry` / `_play_two` 的**搬运时序与气路位**（1~4 下板 / 5~8 反面那套一字不动）。
- 不改 3D 的坐标系、托盘盒、C 检测相机模型的既有口径。
- 不动「18 原料位严禁旋转」「`keep` 面语义」「未就绪闸门」任何一条。
- 不引入新下发通道 / 新 40135 触发位。
- **不做物理仿真**：坠落只是**确定性缓动动画**，不参与任何安全/碰撞判定（围栏/残影仍是唯一判据）。
- 不改自证约定（圆/叉各自装料颜色）的可选值与判据。
- 不改 A/B 托盘几何尺寸与料尺寸。

## 5. 回归钉（把本轮口径钉死，防回退）

**前端 `tools/verify_sorting3d.mjs` / `tools/verify_tictactoe.mjs`**
- 井字棋覆盖下：B1（O）材质 == 蓝、B4（X）材质 == 绿；**不再**是 `matUnknown`。
- A 区：A1–A5 为 O 蓝、A6–A9 为 X 绿（井字棋模式下）。
- 圆/叉标记存在：O 块子网格里是环、X 块里是十字（按几何类型断言）。
- **坠落**：`update` 后不调 `step` → y 仍是格子面高（不破坏"同高"断言）；调 `step(dt)` 后 y > 格子面高；
  推进 ≥ `FALL_DUR` 后 **y 严格 == 格子面高**。
- **预告态**：`pending` 格子的棋子半透明、不下落。
- 卡片源码：**只有「复原」一个按钮**，不再出现"复盘"按钮字面量。
- **日志水位**：`exec.log` 满 `LOG_MAX` 后再 `logLine()` → `logSeq` **仍递增**、
  `log.length` **不变**（反证旧的 `watch(log.length)` 这条水位必失效）；`clearLog()` 后 `logSeq` 归零。
- 源码扫描：`StatusStrip.vue` 的滚底 watch **绑 `logSeq`**（不再绑 `log.length`）。

**后端 `tests/test_tictactoe_api.py` / `tests/test_run_recovery.py`**
- `_reset_run` 已删除（`test_run_recovery` 的 targets 列表同步收窄）。
- 真实局 `POST /reset` → 起真实线程（`ok=True`、有 `run_id`），且**闸门**：伺服未上电 → 409 统一文案。
- 空跑局 `POST /reset` → `dry_run=True`、只清棋盘（不动机器人）。
- `POST /replay` 与 `POST /reset` **走同一条实现**（禁止再出现"两条路各写一份"）。
