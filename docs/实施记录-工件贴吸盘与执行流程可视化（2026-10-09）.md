## 1. 工件"一吸气就消失"——根因与修法

### 1.1 症状与根因

| | |
|---|---|
| 症状 | 吸气后 3D 里手上那块料**看不见**了 |
| 根因 | 料原先挂在**法兰中心正下方 4mm**；而本工具是**从法兰沿 z 伸出 132mm、两个红色吸盘装在左右立板外侧（开口朝 ±x）** → 法兰中心那个位置**正好在腕部实体内部**，料被腕筒挡住 |
| 为什么以前没发现 | 只在"料可见"时看静态画面看不出来；一跟着机器人动就埋进腕部 = 只有真机动起来才暴露 |

### 1.2 修法（三层，缺一不可）

```
① endEffector.suckerLocalMm(料厚)  →  吸盘口在**法兰坐标系**的局部坐标（真实 mm）
     立板/吸盘几何常量提到模块级，使「吸盘坐标」与「建模几何」同源
     实测算得：吸盘口 x = 79.5mm、z = 87mm（料心再加半个料厚 → 86.5mm）

② manager 新增 piece-anchor（工件锚点），挂在 J6 末端工具上
     · 官方数模：挂 tcpNode，局部数值用 **mm**（因 root.scale = 0.001）
     · 程序化模型：挂 flangeNode，局部数值 **/1000**（因它是米坐标系）
     ★ 两边差 1000 倍，写错就是灾难 —— 已在代码里写明并加了回归
     导出 getPieceAnchor() → 世界位置(mm) + 世界四元数

③ sortingBlocks.step(dt, tcpMm, anchorMm) 把料放到锚点上
     位置 = 锚点世界位置 + 沿**锚点 +x 世界方向**外移「半个料厚」（吸盘开口朝 +x）
     朝向 = 锚点四元数 × 绕**自身 z 轴** 90°（把料厚方向对齐吸盘轴）
```

⚠ **踩过的坑**：第一版用"绕 y 轴转 90°"，那是把**料的长度**转到 x 方向 →
料会"竖着插进吸盘"。正确是绕 **z 轴**：`(x,y,z) → (−y, x, z)`，
原 y（14mm 厚）→ x 方向 ✓、原 x（70）→ y ✓、z（70）不变 ✓。
已写成回归断言（`|料的局部 y 轴 · 锚点 +x 世界方向| == 1`）。

⚠ **兜底**：锚点尚未建好时退回法兰附近（绝不把料丢在原点/不动）——同样有断言。

### 1.3 回归钉子（`tools/verify_sorting3d.mjs` F 段，4 条）

| 断言 | 判据 |
|---|---|
| 料心落在吸盘口外侧 | 与手算位置偏差 < 0.01mm |
| 厚度方向对齐开口 | `|dot(料 y 轴, 锚点 x 轴)| == 1` |
| 料可见且不消失 | `visible === true` |
| ★ 反证：锚点缺失时兜底 | 位置仍在法兰附近（不丢原点） |

### 2.1 交付物

```

│ 7  捕捉判色  3 张                        │
```

- 参数（500ms / 1000ms / 3 张）取**本轮真实值**，不写死在文案里
- 判色失败时**也**指出"最像的那一张"（否则现场只看到「检测不到」四个字）
- ★ 只映射**真实 stage，不编造步骤** —— 流程条要能当"机器人走到哪"的依据

### 2.3 用户清单里的"等待0.5秒"落实为真实动作

用户给的流程含「吸取 → **等待0.5秒** → 抬起」，而后端原先没有这一步。
新增 `StartIn.suck_hold_ms`（默认 **500**）：**吸牢再抬**。
理由：现场**没有真空反馈**，刚吸上就走一旦半空掉件，只能等判色失败才发现。

## 3. ★★ 实测抓到的两个真 bug（都是"跑一下"才发现的）

### 3.1 真机路径与空跑路径写的 stage **不是同一套**

| 路径 | 写什么 | 例子 |
|---|---|---|
| **真机** | `_set(st, stage=label)` → **气路标签** | `吸` / `停止吸` / `放` / `停止放` |
| **空跑** | `stage="%s(空跑)" % stage` → 语义名+(空跑) | `取料·吸(空跑)` |
| 运动（两条路径相同） | 语义名 | `取料·上方` / `送检` / `回起点` |

**只映射语义名 ⇒ 真机跑起来流程条认不出、不跳步**（而现场最常看的正是真机）。
实测证据：轮询真机 state 拿到的就是 `stage=吸 / 放 / 停止放`，与映射表对不上。

**修**：`STAGE_MAP` 补 4 个气路标签；
回归脚本**从后端 `label` 字典解析**这 4 个字面量来断言（手写一定会漏）。

### 3.2 空跑丢掉了语义化阶段名

`_air` 空跑分支原写 `stage="%s(空跑)" % label` → 只剩 `吸(空跑)` / `放(空跑)`，
而"吸"与"放"在流程里是**两个完全不同的步骤**（取料·吸 / 放料·放气）
→ 空跑时流程条跳错步 —— 而空跑恰恰是最常用来**排练流程**的模式。

**修**：改 `stage=("%s(空跑)" % stage)`，保留调用方传入的语义名。
离线验证（纯函数，不碰现场）：

```
OK  suck     → 取料·吸(空跑)
OK  release  → 放料·停止吸(空跑)
OK  blow     → 放料·放气(空跑)
OK  unblow   → 放料·停止放气(空跑)
```

## 7. 「取消就绪失败」根因（同日 · 伺服下电时序）

用户报：**"取消就绪失败：servo_off（已下发 0x2000→0x0000，但伺服状态位…）为什么取消失败？"**

### 7.1 现场证据（同一序列**有时成功有时失败**）

```
14:37:48  servo_off: 已下发 0x2000→0x0000，但伺服状态位 2.1s 内仍未落下（现值 1）  ✗
14:38:54  servo_off: 伺服已下电并回读确认（状态位已落，0.03s）                       ✓
14:46:46  servo_off: 已下发 0x2000→0x0000，但伺服状态位 2.1s 内仍未落下（现值 1）  ✗
```
档位全程 AUTO（14:37:22 后未再切换）→ **不是 T1/T2 导致的"下发被忽略"** ✗

### 7.2 根因：`0x2000` 与 `0x0000` 之间**没有等待**

对照**同一个仓里的上电序列**（`modbus.rc_load_run`）：

| | 序列 | 中间等待 |
|---|---|---|
| **上电** | `0x0000` → **sleep 0.6s** → `0x1001` | ✅ 有（注释写明"吸合延迟实测 ≈0.55s"）|
| **下电（旧）** | `0x2000` → **立即** `0x0000` | ❌ **没有** |

⇒ **`0x0000`（全清）会把还没执行完的"取消使能"意图一起清掉** → 下电不生效。
赶上控制器先执行了就成功（实测有 0.03s 就落下的），没赶上就失败 —— 这就是"间歇性"的来源。

### 7.3 修法（两条 + 一条诊断）

| # | 修法 | 理由 |
|---|---|---|
| ① | **先等状态位落下，再写 `0x0000`**（最多等 1.5s 轮询） | 不再打断未完成的取消使能；全清的设计意图保留 |
| ② | **失败自动重试一轮**（0x2000 → 等待 → 0x0000） | 偶发不响应；**下电是安全方向**动作，重发无风险 |
| ③ | **诊断可见**：0x2000 / 0x0000 的返回都记进步骤消息 | 以前 0x0000 的返回值**直接丢掉** → 无法区分"写失败"与"写了没生效" |

失败消息现在长这样（现场能直接看出是哪一种）：
```
已下发 0x2000→0x0000（重试 2 轮，3.0s），伺服状态位仍未落下（现值 1）
｜第1次 0x2000 已写；第1次 0x0000 超时；第2次 0x2000 已写；第2次 0x0000 ok
```

### 7.4 顺带修正一处**误报失败**的口径

旧实现在 `0x2000` 写失败时**直接判失败** —— 但如果伺服**本来就是下电态**，
"取消就绪"的目标其实**已经达成**，报失败属于**误报**。
新口径：`0x2000` 被拒但**状态位本就是 0** → 判**成功**，同时把"命令被拒"如实写进诊断；
只有"命令被拒 **且** 状态位仍在 1"才判失败。
（`tests/test_audit_p0.py::test_cancel_servo_off_failure_is_not_silent` 的 (a) 分支已按新口径拆成 a1/a2。）
