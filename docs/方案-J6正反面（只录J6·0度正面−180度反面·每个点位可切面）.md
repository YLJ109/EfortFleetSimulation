## 0. 你的原话与我提炼的口径（请核对；若读错请直接指出）

> 「J6 的点我说了只录 J6 的坐标啊，那个正反面，现在每个点的 J6 坐标根据录制好的两个 J6 的坐标进行，J6 的 0 度是正面，J6 的 −180 度是反面，每个点的 J6 坐标根据录好的 J6 来进行正面和反面，现在所有的点的位置提前录好的原因每个点的 J6 默认是正面了，像点位执行那样，只旋转 J6，两个点的你坐标存好，已经给你了，先思考吧，做一套建议和方案」

**我提炼出的 4 条口径**（供你核对）：

| # | 口径 | 我的理解 |
|---|---|---|
| 1 | **只录 J6 一个值** | `J6正面` / `J6反面` 本质只是**两个 J6 数值**：**正面 = J6 0°**，**反面 = J6 −180°**（你已录好存入点位库） |
| 2 | **每个点位天生是"正面"** | A1…A9、A1上…、C检测、开始/结束点、B 区格… 都是提前录好的，**它们的 J6 默认就是正面（0°）** |
| 3 | **要"反面"= 在那个点位自身姿态上，只把 J6 转 −180°** | J1~J5 **保持该点位自己的值**；**"像点位执行那样，只旋转 J6"** |
| 4 | **目标** | **任意点位都能以「正面/反面」两种方式执行**，而不是只有双面分拣那一次翻转能用 |

> ★ 与既有口径的**关键差异**（这是本轮新需求的实质）：
> 现有实现里"翻转"**只在双面分拣流程内部**发生一次（步 ②），且基姿态取的是**机器人当前实时姿态**；
> 本轮要的是**"某个点位"以自己的姿态为基**去切面 —— **底座从"当前实时"扩到"任意点名 + 当前实时"两种基**。

## 2. 建议（对 a~h 逐条**明确表态** + 理由 + 代价）

### a. 两个 J6 值放哪 —— ▶ 推荐：**继续用点位库的两个点，但把语义收窄为"只取 `joints[5]`"**

| 方案 | 优点 | 代价 / 风险 | 我的判断 |
|---|---|---|---|
| **A1. 继续用点位库两个点**（现状） | ① 不破坏 38 点位断言；② 你**已录好、可删可改**；③ 界面/白名单/测试**都已就绪**；④ 与 §7-e「正反面由用户示教」口径一致 | "点位库强制 6 值"与"只录 J6"**名义矛盾**（录时仍存了 J1~J5，但被无视） | ✅ **推荐**（代价最小、零破坏） |
| A2. 改成配置/专用字段（两个纯数值） | 语义最干净（"就两个数"） | ① 新增存储 + 迁移；② 与你"已录好的两个点"**重复**；③ 界面/白名单/回归钉全要改；④ 失去"可删可改/可示教" | ❌ 不推荐（收益小、改动大） |

**推荐的落地细节**（把名义矛盾降到最低）：
- 代码侧新增**唯一取数口**：`j6_of(point)`（= `joints[5]`）与 `face_j6_value(face)`（正面/反面分别取对应点的 `j6_of`）——
  **禁止任何别处再直接 `[5]` 或整组使用**，避免分叉。
- 界面「存点」时**明确只让用户关心 J6**（其余 5 轴仍按 6 值合法存下，但 UI 只显示 J6 —— **现状已如此**）。
- 我**不建议**去改点位库支持"部分值"（那是改 `_norm_joints` 铁律，牵动 40 个点与全部断言）。

### b. 面怎么表达 —— ▶ 推荐：**做成"执行时参数 `face: "front"|"back"`（默认 front）"，运行中另用 `state.face` 如实记录**

| 方案 | 说明 | 我的判断 |
|---|---|---|
| B1. 每个点位加**持久"当前面"状态** | 点位库多一个 `face` 字段 | ❌ 不推荐：引入隐性状态，"什么时候被改过"无法自证，**违背"不许编故事"** |
| B2. **执行时参数** `face`（默认 `front`） | 每次执行**显式告诉后端用哪一面**；无状态、幂等、可回读 | ✅ **推荐**：与现有 `dual_face` 同一风格；默认一律正面（合你口径）；**状态在运行中由 `state.face` 如实记录**（推断，非持久） |

**推荐组合**：**参数决定"目标面" + 运行时 `state.face` 如实反映"当前面"**。
- 默认 `face="front"`（你口径：每个点默认正面）。
- `state.face` 是**运行时快照**（供界面/3D 显示），**不确定时写"未知"**，绝不假设。

### c. "只旋转 J6"怎么落地 —— ▶ 推荐：**抽一个共用纯函数，复用它，而不是复用 `jog._step_joint` 的接口**

- 复用 `jog._step_joint` 的**思路**：`base → target = base[:] → target[5] = 定值 → motion.command(target… )`。
- 建议新增（实施时才落地）：
  - `compose_single_axis(base: list, axis: int, value: float) -> list`：**纯函数**，只覆盖单轴（可测）。
  - `set_face(ctx, pmap, base, face, ...)`：`base` 可以是**当前实时姿态**（= 现有翻转）**或某点位的 J1~J5**（新需求）。
- **不复用 `_step_joint` 接口**的原因：它是**增量 + 带速度换算 + 限位夹取**，语义是"走一格"；
  切面是"设到某个绝对 J6 值"，**直接复用会造成"夹取后到不了目标却报成功"**（见 §e）。

### d. 反面是否 = 严格 −180 —— ▶ 推荐：**以"录制的点值"为准；不自己算 −180；冲突时以录值为准**

| 方案 | 说明 | 我的判断 |
|---|---|---|
| D1. 用**录制的反面值**（`J6反面.joints[5]`） | 与 §2-e「正反面姿态由用户示教，代码不自算」**完全一致**；现场实测值可能带零头 | ✅ **推荐** |
| D2. **算出来**（`J6正面.joints[5] − 180`） | "0° 正面 / −180° 反面"在数值上更纯粹 | ⚠️ 仅在你**明确改口径**时采用 |

- **冲突处理（推荐）**：**以录点值为准**。可选做一条**只读校验提示**（如"`J6反面` 与 `J6正面` 相差 X° ≠ 180°，请确认"），**但不改变下发动作**。
- ★ 你说"0 度是正面、−180 度是反面"，又说"两个点你坐标存好，已经给你了" ——
  **这两句同时成立**意味着：**你录的值大概率就是 0 / −180**；即便如此，也**以录值为准**（万一现场有零头，自算会与你的录值打架 → 不可自证）。
- 若你希望"反面**恒** = 正面 − 180"，请在回报的问题①明确，我再把这个作为**独立口径**写成 D2。

### e. 边界与安全 —— ▶ 推荐：沿用**原料位黑名单** + **超限拒绝（不静默夹取）** + **转面慢速/预演**

| 安全项 | 建议 | 理由 / 证据 |
|---|---|---|
| 允许范围 | **除原料位（A 区格位本身）外全部允许**（沿用现行黑名单） | `is_raw_material_slot`（`services/sorting.py:507-518`）；你的原话「原位不能旋转」 |
| 转面必须过护栏 | 切面下发**先过 `_rotation_guard`** | 与现有 `_move_flip_j6` 一致（`:515`） |
| J6 限位 | 目标 J6 **超软限位 → 拒绝并写明**，**不静默夹取**（`J6: −360~360`，正常不会超） | `config/robot.yaml:46`；对照 `jog._step_joint` 会夹取（`:227-232`），切面**不应**照抄 |
| 撞线/绕线 | 转面是"原地纯关节运动"（J1~J5 不动），围栏/碰撞由现有 `guard_check` 兜底 | `_move_flip_j6:534-536` |
| 慢速 / 预演 | **转面一律走全局速度**（真机验证 **5%**）；建议**先残影预演**再下发 | 项目口径：真机 5% 单点、残影预演判碰撞 |
| 哪些点**额外**禁止 | ⚠️ **需你现场确认**（除原料位外，是否有某点 J6 转 180 会绕线/碰工装） | 我**不能**替你判 |

### f. 交互 —— ▶ 推荐：**两处都提供**，但语义分层；**默认一律正面**；**如实显示当前面**

| 页面 | 建议 | 理由 |
|---|---|---|
| **分拣页** | 保留现有双面开关；**到点/执行**入口可加"正面/反面"选择 | 双面流程是"面"的首个使用者 |
| **点位执行页** | 每个点位**执行时**可选面（默认正面）；执行前**预览将要下发的 6 值**（J6 = 对应面值） | 这是你说的"像点位执行那样，只旋转 J6"的**落点** |
| 默认 | **一律正面** | 你的口径：每个点默认正面 |
| 当前面显示 | **必须如实**：`state.face`（运行时推断）→ 界面/3D 标注"当前面（推断）"；**未知就说未知** | 项目铁律「不许编故事、不知道就说不不知道」 |
| 禁止编故事 | **不显示**未确认的"面"；转面按钮在原料位**禁用并写明原因** | 同上 |

### g. 与双面分拣的关系 —— ▶ 推荐：**双面分拣改为"切面原语"的第一个使用者（复用同一套）**

- 现有双面流程步 ②「转到 `J6反面`」= **切面到反面**；把 `_move_flip_j6` **泛化**后，它直接调用同一原语。
- 收益：**"面"从流程内部的硬编码步骤 → 通用能力**；未来"取料用正面 / 放料用反面"等编排只需加参数。
- **不改**双面流程的默认行为（`dual_face` 默认 False，原单件路径零回归）。

### h. 存储与兼容 —— ▶ 推荐：**不迁移、不动 38、不破坏既有数据**

| 项 | 建议 | 理由 |
|---|---|---|

## 9. 2026-10-11 本轮（残影与实际下发**同源**）

> 用户原话（本轮）：
> 「现在残影对不上」

### 9.1 根因（已证实，非推断）

残影（ghost）与"实际下发"**取的不是同一个目标**：

| 侧 | 目标怎么来 | 证据（`文件:行号`，改前） |
|---|---|---|
| **残影预演** | 前端直接把**点位自带的整 6 轴**摆到残影上（不经过后端） | `frontend/src/stores/exec.js` 的 `previewPointGhost` / `hoverPoint` / `pinPoint` / `pinPointB` 一律 `setGhostPose(p.joints)` |
| **实际下发** | `J6正面`/`J6反面` → **原地切面**：基姿态 = **当前实时关节**，只覆盖第 6 轴 | `backend/app/api/control.py::api_move`、`backend/app/api/sorting.py::api_goto`（均 `compose_j6_only(_live_joints(), joints[5])`） |
| 残影对不上的**具体差异点** | 对这两个点：残影停在**录点当时的整姿态**（在**起点**录的 → 残影站在起点附近），而实发**只原地转 J6**（J1~J5 = 当前位置）。两者**不同源** → "对不上" | 同上 |

★ **只有 `J6正面`/`J6反面` 两个点对不上**：其余点位（A1/C检测/起点…）两侧取的都是"点位自带 6 值"，
本来就一致。上一轮（§8）只把**实发**改成了原地切面，**没有同步改残影的数据来源** —— 这就是本轮的缺口。

### 9.2 口径（本轮定死）

| # | 口径 | 落地 |
|---|---|---|
| 1 | **"点位 → 将要下发的目标"只有一个入口** | `services/sorting.py::resolve_target_joints(name, joints, base_provider)`（纯决策逻辑） |
| 2 | **残影与实发都调它**（结构上不可能再分叉） | 实发：`api_move` / `api_goto` / `_run_file_job` / `execute_rule` 四个入口；残影：新只读接口 `/control/point-target` |
| 3 | **前端只负责画**，不再自己用点位自带 6 轴拼姿态 | `frontend/src/stores/exec.js` 的 `fetchPointTarget()` / `ghostFromPoint()`；悬停/点选/预演/逐步门控全走它 |
| 4 | 残影仍然**只预演、绝不下发** | `/control/point-target` 走只读路由 `router_ro`（**不挂** `require_control`），响应 `readonly=True`，内部只算不写 |
| 5 | 普通点位**逐字不变** | `resolve_target_joints` 对非 J6 正/反面**原样返回**点位自带 6 值，**且不读实时姿态**（`base_provider` 不被调用） |

### 9.3 为什么这样落地（"同源"的两种写法，选了更强的那种）

- 任务口径给了两条路：①"前端向后端要目标，只负责画"；②"两侧调用同一个后端函数"。
  **本方案两条都满足**：前端不再拼姿态（①），且残影接口与四处实发**共用同一个** `resolve_target_joints`（②）。
- 顺带把上一轮"**五处各写一遍同样的 glue**"（`if is_j6_face_point(...): compose_j6_only(...)`）
  **收敛成一处** —— 这比"改残影"更根治：只要有人改口径，不可能只改一半。
- `_move_flip_j6`（双面流程内翻转）**未改**：它保留"基姿态不可得 → 回退整姿态 + 日志如实标注"的
  **既有语义**（`tests/test_double_face.py::test_flip_falls_back_and_logs_when_base_unavailable` 钉死），
  与"到点"入口的"拿不到就拒绝"**故意不同**，不强行统一。

### 9.4 前端怎么"只画"

| 函数 | 作用 |
|---|---|
| `exec.fetchPointTarget(p)` | 调 `/control/point-target {point_id}`，拿 `{target, j6_only, error}`（**不抛**） |
| `exec.ghostFromPoint(p, "a"/"b")` | 用返回的 `target` 摆残影；**J6 正/反面但后端拒绝**（无实时基姿态）→ 收起残影 + 如实记原因；**后端不可用**（网络异常）→ 回退点位自带 6 值（**保持旧行为**） |
| `previewPointGhost / hoverPoint / pinPoint / pinPointB` | 全部改调 `ghostFromPoint`（不再 `setGhostPose(p.joints)`） |
| 悬停/点选竞态 | 模块级 `ghostSeq` / `ghostSeqB`（世代令牌）：旧请求后返回就丢弃；收起/离页也 +1 作废在飞的请求 |
| `execPoint` / `execProgram` 逐步门控 | 先 `await fetchPointTarget(p)`，再用**同一目标**做 `gateAt()` —— 门控与实发同源 |
