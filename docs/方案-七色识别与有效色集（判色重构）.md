# 方案：七色识别 + 「有效色由用户指令决定」（判色重构）

> 2026-10-10 · 状态：**已实现并验证**（结果见文末 §8）
>
> 触发口径（用户原话）：
> - 「把 7 种颜色都能识别；把检测代码重构、优化、修复、完善」
> - 「**只要用户说的颜色是有效颜色，用户没有提到的颜色的是无效颜色**」
> - 「加强检测逻辑全面修改；先思考、上网、做方案、优化方案、再实现」

---

## 0. 一句话

检测器**只负责如实报出"这到底是什么颜色"**（7 色 + 无彩色），
**"有效 / 无效"由用户指令决定** —— 说了的颜色才算数，没说的连同黑色一起**原路放回原位**。

---

## 1. 口径：先把名词钉死（避免"有效色"这个词被误解）

| 名词 | 定义 | 谁决定 |
|---|---|---|
| **调色板（可识别色）** | 红 / 橙 / 黄 / 绿 / 青 / 蓝 / 紫 —— 检测器能给出的 **7 个颜色名** | 代码（常量 `PALETTE_NAMES`） |
| **无彩色** | 黑（暗色）/ 未知 —— 报「黑」= **确信它不是 7 色之一**，不是"判出了有用颜色" | 检测器 |
| **有效色** | **用户这句话里提到的颜色**（说了红，红才有效） | 用户指令 |
| **无效色** | ① 调色板里出现过、但用户**没提到**的颜色；② 无彩色（黑/未知） | 用户指令 + 检测器 |

> ★ 关键改动：以前"有效色"是**写死**的红/绿/蓝、"无效色"固定是黑；
> 现在"有效/无效"这条线**由指令动态划**。检测器不再替用户决定谁有效。

---

## 2. 色相带（7 色**纯划分**，红带跨 0° 环绕）

| 颜色 | OpenCV H 范围 | 现场实测落点（真图，§7 数据） |
|---|---|---|
| 红 | `<12` 或 `≥160` | 2~4 ✓ |
| 橙 | `12 ~ 22` | 无样本（合成图 #FF7A18 → H≈13 ✓） |
| 黄 | `22 ~ 35` | 无样本（合成图 #FFD400 → H≈25 ✓） |
| 绿 | `35 ~ 88` | 69~70 ✓（★ 见下：由 75 退到 88） |
| 青 | `88 ~ 100` | 无样本（合成图 #00BFC8 → H≈91 ✓） |
| 蓝 | `100 ~ 135` | 104~106 ✓ |
| 紫 | `135 ~ 160` | 无样本（合成图 #8A3FC0 → H≈137 ✓） |

> ★ **三色零回归的关键**：蓝带下限取 **100**，护住现场实测蓝（H104~106）；
> 红带跨 0° 环绕，护住现场红（H2~4）。
> ★★ **绿带上限 75 → 88**（2026-10-10 现场"绿被判成青"后修正）：
> 现场绿件 H≈69~70，**离 75 只有 5 格** —— 光照/白平衡稍一漂就翻到"青"。
> 这是**把判据边界放在实测值正上方**的典型错误。现退到 88（绿留 ≥18 格余量），
> 青带收窄为 `[88,100)`，只留给"真青"（H≈91）。

## 3. 检测层重构（`camera/vision_color.py`）

| # | 改动 | 说明 |
|---|---|---|
| 1 | 新增 `PALETTE_NAMES`(7) / `HUE_BANDS` / `PALETTE_HEX` | 调色板一处定义，便于现场裁剪 |
| 2 | 新增 `_palette_vote()` | 七色分箱投票（**主判据**，与光照无关）。`_hue_vote` 保留为它的兼容包装 |
| 3 | 新增 `classify_palette()` | 七色 CIEDE2000 最近邻（**复核/提示**，不参与置信度） |
| 4 | `_color()` 改用七色投票 + 七色复核 | 一致→置信度略升；分歧→降一半；结果 hex 从 `PALETTE_HEX` 取 |
| 5 | **修「暗绿被判黑」**：改判条件 `暗` → `暗 **且** 不艳` | 见 §4 |
| 6 | 新增 `_looks_dark()`（按候选 ROI 中位给 V / S / Lab-chroma） | 替代 `_dark_self_frac` 作为改判依据 |

**保留不动**（防回归）：分割、矩形筛选（`fill_min` / `solidity_min` / `aspect_max`）、
`dark_object_mask`（无彩色兜底）、`classify_rgb` / `RGB_NAMES` / `ColorSampler`。

## 4. ★ 「黑」的判据修正（本次最核心的 bug 修复）

**旧（bug）**：`_dark_self_frac(dmask, mask, r) ≥ 0.5` —— 只看"暗"。
`dark_object_mask` 的 `thr = min(130, 背景中位 × 0.7)`，亮背景下顶到 130，
而绿件 V≈87~91 < 130 → 自身像素 90% 落进暗色掩膜 → **判黑**（现场"绿色检测不到"）。

**新**：黑必须是 **「暗」且「不艳」** 两条件同时成立（按候选 ROI 的中位统计）：

```
黑  ⟺  V_med ≤ dark_val_max(130)
        且 ( Lab_chroma_med ≤ dark_chroma_max(12)  或  S_med ≤ dark_s_max(80) )
```

**实测校验（真图，§7）**：

| 样本 | V_med | S_med | chroma | 新判据结果 |
|---|---|---|---|---|
| 绿件（暗帧） | 87 | 104 | 18.4 | V暗 ✓ 但 S/chroma 高 → **绿**（不再误判黑）✓ |
| 蓝件（暗帧） | 87 | 145 | 19.0 | 同上 → **蓝**（修掉旧 bug）✓ |
| 真黑/极暗件 | 59 | 62 | 5.0 | V暗 ✓ 且 chroma/S 低 → **黑** ✓ |
| 真黑/极暗件 2 | 83 | 9 | 1.0 | → **黑** ✓ |

> 色度/S 的判别余量：彩色件最低 chroma=18.0、S=96；暗色件最高 chroma=5.0、S=62。
> 阈值取在中缝（12 / 80），两侧各留 ≥6 的余量。

## 5. 有效色集（后端 `sorting.py`）

```
vote_color(frames, min_conf, accept_ratio, valid_colors=None)
    valid_colors 缺省 = COLORS(红,绿,蓝)   ← 向后兼容，行为不变
    判定：name ∈ valid_colors 且 conf ≥ min_conf 才算「有效帧」
```
- 调用方（AI 计划 / 分拣任务）把**用户提到的颜色**传进来 → 自动实现"没提到的颜色无效"。
- 未传时保持现状（红/绿/蓝有效、其余无效）→ **零回归**。

**三处调用方的口径**（`_capture(..., valid_colors=...)`）：

| 调用方 | valid_colors | 结果 |
|---|---|---|
| 三色分拣页 / 井字棋 | 缺省（红/绿/蓝） | **零回归**：只分三色 |
| AI 执行页（`ai.py`） | `S.RECOGNIZED_COLORS`（7 色） | 检测器**如实报真实颜色**；"放走/放回"交给**配额与摆法**决定 |

> ★ 为什么 AI 链路传"全部 7 色"而不是"用户提到的色"？
> 若把"没提到的色"在投票阶段就打成"未知"，界面会显示**「无法识别」** —— 但件其实认出来了，
> 只是没要它。那会误导现场以为识别坏了（本项目最忌讳的"假报警"）。
> 传 7 色 → 颜色如实报出，再由配额（`quotas.get(color)==0`）判"放回原位" →
> **结果一样（放回），但原因诚实**：是"没要这个色"，不是"没看出来"。

## 6. 不做什么（边界）

- ❌ 不改分割/矩形筛选阈值（`fill_min` 等，现场已标定）。
- ❌ 不改运动/速度/触发位/40103 等控制链路。
- ❌ 不引入 YOLO / torch / 新依赖（仍纯 OpenCV + numpy）。
- ❌ 不让检测器"猜"物体身份（不硬编码"这个位置是红"）—— 只按颜色如实报。
- ❌ 不动示教器程序 / RPL。
