# 方案 · 分拣页改版（左：仿真机器人 · 右：点位设置与分拣操作）

> 2026-10-08 · 用户口径：
> 左侧是仿真机器人；右侧是分拣操作面板（设置点位、保存点位）；
> **右侧要简单**：一个「一键就绪」按钮；A 区 9 格，**每格存 2 个点位（正上位 + 原料位）**；
> B 区同样 9 格 × 2 个点位（正上位 + 放料位）；**C 区摄像头位置可修改**。
> 合计仍是 **38 个点位**（A 18 + B 18 + C 1 + 开始/结束点 1）。

---

## 1. 现状与差距

| | 现状（今天刚做的第一版） | 目标 |
|---|---|---|
| 页面结构 | 纯数据页（一堆卡片纵向堆叠），**没有 3D 视口** | **左 3D 视口 + 右操作面板**（与点位执行/程序执行同一套 `MonitorLayout`） |
| 点位 | 只能跳去「点位执行」页示教；分拣页只做体检 | **就地示教/保存/复核**，A/B 每格两个点、C 与开始点可改 |
| 就绪 | 无入口，要回别的页点「一键就绪」 | 右栏顶部一个「一键就绪」 |
| 右栏 | 全塞满（体检+参数+状态+A/B 网格），信息量大 | **分两个小页签**：`执行` / `点位`，一屏一件事 |

## 2. 页面结构

```
MonitorLayout(view="sort")            ← 左：3D 视口（与其它页共用同一个 scene/canvas）
  ├─ .view  3D 仿真机器人 + 安全围栏片 + 语音字幕层（既有浮层照旧）
  └─ <slot> 右栏：分拣操作面板
              ├─ ① 就绪条：机器人已就绪? + [一键就绪] + 控制权限/轴锁徽标
              ├─ ② 页签： [执行]   [点位]
              ├─ ③ 执行页签：参数 + 空跑/开始/停止 + 进度 + 判色 + 三列占用
              └─ ④ 点位页签：示教工具 + A/B/C/开始结束 的点位格
```

- `MonitorLayout` 只需传 `view="sort"`：它内部会 `registerView("sort", el)`，
  3D 画布由 App.vue 的 `switchView` 搬进来 —— **与 point/program 完全同一套机制，无需改 3D 引擎**。
- 右栏宽度沿用既有 `--side-w`（可拖宽/折叠），窄屏自动堆叠。

## 3. 右侧「点位」页签（本次核心）

### 3.1 示教工具条（精简，一行）

| 元素 | 说明 |
|---|---|
| 轴选择 | J1…J6（分段按钮，单选） |
| 点动 | `−` / `+`（按住连续点动，松开停；死人开关 keepalive 沿用既有实现） |
| 步长 | 0.1° / 1° / 5° / 10°（**单击走一步**，与按住连续分开） |
| 速度 | **不单独设**：用右上角全局速度那一份（全项目唯一速度口径） |

> 为什么要放点动：否则"在分拣页保存点位"就得来回跳页。行程小、只占一行。

### 3.2 点位格（A 区 3×3 / B 区 3×3 / C / 开始结束）

每格显示 **2 个点位槽**（A 区 = 正上位 + 原料位；B 区 = 正上位 + 放料位），每个点位槽三个动作：

| 动作 | 语义 | 落点 |
|---|---|---|
| **存点** | 把机器人**当前位姿**写为该点位（已存在则覆盖） | `POST /api/sorting/teach {name}` |
| **到点** | 移到该点位（用于复核示教对不对） | `POST /api/sorting/goto {name}` |
| **清空** | 删除该点位 | `DELETE /api/sorting/point?name=` |

- 每个点位槽显示状态：**未示教 / 已示教**（灰点/绿点）+ 关节角摘要（鼠标悬停看全 6 轴）。
- 「存点」需**二次确认**（覆盖已有值时提示"将覆盖 xxx"），避免手滑把已示教的点冲掉。
- C 区（`C检测`）与 `开始/结束点` 用**同样的格子**（单格两行：一个点位一个槽），
  这样"可修改"与 A/B 一致，交互不用记两套。

### 3.3 分组与命名（沿用已实现的口径）

- 全部落在 `Point.group = "分拣"`，名字固定：`A1…A9` + `A1上…A9上`、`B1…B9` + `B1上…B9上`、
  `C检测`、`开始/结束点`。
- **名字即契约**：分拣引擎按名字取点；页面体检（已实现）会指出缺哪些 → 直接在这一页补。
- 页面格子里"正上位/原料位"的显示名与真实点位名的对应关系写死在页面（不靠猜）。

## 4. 右侧「执行」页签

保持已实现的执行能力，但**压缩成一屏**（体检结果只显示一句总结 + 缺项可展开）：

- 参数：速度（与右上角同源）、C 区停顿、抓帧数、吹气时长、本轮件数
- `空跑` 勾选 + **[开始]** + **[停止]**
- 进度条 / 第几件 / 阶段 / C 区判色（色块 + conf + 票数）/ B 区三列占用（`2/3 满`）
- 停止原因（红条）

## 5. 后端

复用已有 `Point` 表与 `/points` CRUD，**只加三个分拣专用薄接口**（都在 `api/sorting.py`）：

| 方法 | 路径 | 说明 |
|---|---|---|
| `POST` | `/api/sorting/teach` | body `{name}`（或 `{name, joints}`）：无 `joints` 时**取当前实时关节角**写入 → upsert（`group=分拣`）。**只接受 38 个白名单名字**，拒绝任意名字污染点位库 |
| `POST` | `/api/sorting/goto` | body `{name}`：移到该点位（走既有 `motion.command`：围栏互锁 + 轴锁 + 速度夹取 + 可被停止打断） |
| `DELETE` | `/api/sorting/point` | `?name=`：删除该点位（同样白名单限制） |

**为什么 `teach` 要用白名单**：这页只该管分拣的 38 个点。若允许写任意名字，
一次手滑就能在点位库里制造出没人认识的条目，而分拣引擎仍然"照名字找点"，
出问题时很难查。白名单把"能写什么"限死，配合既有体检形成闭环。

**就绪**：直接用既有 `POST /api/ready`（`rcReady.doReady()`），不新增。

## 6. 安全

- **示教写点位 = 配置写**：需控制令牌；不改运动链路。
- **到点 = 运动**：必须过 `guard_check`（围栏互锁）、轴锁口径、速度夹取（5~100%）、
  可被「停止执行」/急停打断 —— 与既有下发完全同路。
- **点动**：复用既有死人开关（1.5s 无 keepalive 自动停）+ 轴锁 + 围栏。
- 分拣运行期间**禁止手动点动/到点**（沿用 `_reject_if_run_active` 的互锁）：
  否则手动动作会与分拣流程抢同一个 40135 触发位。
- 「存点」在分拣运行中**禁用**（避免跑到一半把目标位改了）。

## 7. 验收

| # | 项 | 判据 |
|---|---|---|
| 1 | 页面结构 | 左侧 3D 视口可旋转/缩放，右边面板可拖宽/折叠；窄屏自动堆叠 |
| 2 | 一键就绪 | 右栏顶部按钮可用，状态与其它页一致（同一 store） |
| 3 | 点位格 | A/B 各 9 格 × 2 槽；未示教/已示教一眼可辨；悬停看关节角 |
| 4 | 存点 | 点「存点」后该点立刻变"已示教"，且**体检计数 +1**；重进页面仍在 |
| 5 | 到点 | 机器人移到该点（走护栏）；未示教的点按钮禁用 |
| 6 | C 区可改 | `C检测` 与 `开始/结束点` 与 A/B 同一套动作可用 |
| 7 | 白名单 | 尝试非 38 名单内的名字 → 400 拒绝 |
| 8 | 互锁 | 分拣运行中点动/到点/存点被拒且提示明确 |
| 9 | 不回归 | 既有 38 点位体检/空跑/执行/停止全绿；前端 `npm run verify` 全绿 |

## 8. 实施顺序

1. 后端：`teach` / `goto` / `point` 三个接口 + 白名单校验 + 单测
2. 前端：`SortingView.vue` 改为 `MonitorLayout(view="sort")` 双栏 + 右栏两页签
3. 前端：点位页签（示教工具条 + A/B/C/开始结束 点位格，复用 `exec.savePoint`/`/control/move`）
4. 校验：`npm run verify` + 单测；真机：点动示教 1 个点 → 到点复核 → 全量示教 → 空跑 → 单件 → 整轮
